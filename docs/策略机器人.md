# 策略机器人（0.13.0）

菜单 3 的复盘页里，工具栏右边那个【启动机器人 ▾】现在能**选一个策略让它自己跑**：
选策略 → 设手数 → 点开始，机器人就接管盘面，一根一根推进 K 线，该开仓就开仓，
自动挂止损止盈，收盘前平掉，跑到数据末尾自己停。

这份文档讲四件事：**它跑在什么假设下**、**三块代码各自负责什么**、**Caveman 的规则**、
**怎么加第二个策略**。

---

## 1. 先说清楚假设：零滑点、零手续费

界面上看到的所有盈亏，都是在这个前提下算出来的：

| 项 | 这里的做法 | 真实市场 |
|---|---|---|
| 市价单成交价 | 当根 K 线**收盘价** | 对手价，要跨买卖价差 |
| 限价/止损单成交价 | 挂单价；开盘就跳过时取**开盘价**（跳空） | 同 |
| 滑点 | **0** | 一个 tick 起 |
| 手续费 / 佣金 | **0** | 每手每边几毛到几美元 |
| 部分成交 | 不模拟，一次全成交 | 大单会分批 |

这不是"忘了加"，是需求里明确要求的假设：**用 prop firm 的模拟盘做考试号，
没有滑点、佣金可忽略**。所以这里的数字回答的是「这个策略在最有利的条件下能做成什么样」，
不是「实盘能赚多少」。

一个必须知道的量级：MNQ 一个 tick 是 0.5 美元，Caveman 每笔毛利润也就 0.5~1 美元
（详见 §4 的实测）。**价差一进来，利润表就变样**。所以别把这里的正数直接当收入。

## 2. 三块代码，各管一件事

```
internal/strategy/        策略：看已收盘的 K 线，说「该做多了，止损这里、目标那里」
        ↓ Signal
internal/replay/bot_strategy.go   执行器：真的下单、挂保护单、盯成交、日终平仓
        ↓ doMarketOrderLocked / doPlaceOrderLocked
internal/replay/instance.go       撮合：和真人点按钮完全同一套（跳空取开盘价、不用未来数据）
```

这条分界不是洁癖，是三个具体的好处：

1. **策略是纯函数**。测试里造几根 K 线就能验，不用起 Hub、不用连 WS（见 `caveman_test.go`）。
2. **成交口径只有一份**。策略拿不到 `Instance`，就不可能自己"造"一个成交价出来。
3. **加策略不用碰协议和前端**。注册表里多一条，启动面板里就多一项。

策略能看到什么、能说什么，全在 `internal/strategy/strategy.go`：

```go
type Context struct {
    Bars     []Bar     // 只到当前这根：后面的行情在这一层就不可见
    Cursor   int       // 当前下标
    Tick     float64   // 最小跳动
    Position Position  // 只读持仓
}

type Signal struct {
    Side   string  // buy | sell
    Stop   float64 // 绝对价格，不是距离
    Target float64 // 绝对价格
    Reason string  // 写进日志的一句话
}
```

**Stop / Target 用绝对价格而不是"距离"**：换算散在两边，迟早有一边把方向写反。
策略直接给「止损价 102.25」，执行器直接拿去挂单，中间不做任何算术。

## 3. Caveman 的规则

两根 K 线，一句人话：**一方全力推出去，被另一方一口气打回来，顺着打回来的方向做。**

```
信号棒   强趋势棒：实体占振幅 ≥ 50%，收盘贴在极值附近（阳线收在上 25%）
触发棒   紧接的一根反向棒，收盘**吞回信号棒的起点**
```

- 强阳棒 + 阴棒收在阳棒开盘价之下 → **做空**
- 强阴棒 + 阳棒收在阴棒开盘价之上 → **做多**

止损放在**信号棒极值之外**一个 tick（空单在信号棒最高价上方），
目标 = 入场价 ∓ R 的若干倍，R = 入场到止损的距离。

举个例子（`caveman_test.go` 里就是这个数）：

```
10:05  O=100  H=102  L=99.8  C=101.8   实体 1.8 / 振幅 2.2 = 82%，收在 91% 位置 → 强阳
10:10  O=101.8 H=101.9 L=99.0 C=99.2   阴棒，收盘 99.2 < 100（吞回阳棒起点）→ 触发

入场 99.2（触发棒收盘，市价）
止损 102.25（信号棒高点 102 + 1 tick）
R = 3.05
目标 1R = 96.15 → 向下对齐到 tick = 96.0
```

### 参数（启动面板里能改，只影响这一次启动）

| 参数 | 默认 | 含义 |
|---|---|---|
| `bodyMin` | 0.5 | 信号棒实体 ÷ 振幅的下限 |
| `closePosMin` | 0.75 | 信号棒收盘要贴到极值的百分之多少 |
| `targetR` | 1.0 | 目标 = R 的几倍。原文用 0.5R / 1R |
| `stopBufferTicks` | 1 | 止损放在极值外几个 tick |
| `minRTicks` | 4 | 风险不足这么多 tick 就不做 |
| `maxTradesPerDay` | 4 | 一个交易日最多开几单，0 = 不限 |
| `allowLong` / `allowShort` | 1 / 1 | 0 = 关掉那一侧 |

**为什么默认 1R 而不是原文的 0.5R**：0.5R 的保本胜率是 `1/(1+0.5) = 66.7%`，
而 820 天数据上实测打满率 66.0% —— 就差在那 0.7 个百分点上，成本一进来就是负的。
1R 的保本线 50%，实测 49.6%，更接近、但也还没站上去。**这个策略本身的期望接近 0**，
换目标不会把它变成赚钱的策略，只会换一种亏法。

### 两个刻意的"保守"

1. **价格对齐有方向**：止损往**更远**对齐，止盈往**更难**对齐（`AlignTickUp/Down`）。
   四舍五入平均下来会让目标略微变近、止损略微变近，回测就悄悄偏乐观了。
2. **同一根 K 线最多开一单**，而且只在空仓时出信号。策略不叠仓、不反手。

## 4. 一个交易日，机器人怎么走

以 MNQ 的周五为例（时间都是本地时区）：

```
06:00  新交易日第一根。机器人推进一步，策略看一眼 → 没有形态，什么都不做
  …    每 300ms 推进一根，策略每根判断一次
21:30  美股开盘。强阳棒 → 21:35 阴棒吞回 → 市价做空 1 手
       立刻挂两张保护单：buy stop 止损、buy limit 止盈（同一个 OCO 组）
21:45  一根长下影线打到止盈 → 止盈成交，止损被同组规则自动撤销
  …    继续推进，出现下一个形态再做，一天最多 4 单
04:50  进入收盘收尾时段：有仓位就市价平掉，之后不再开新仓
04:55  当夜最后一根
06:00  换交易日：计数清零，仓位和残留保护单强制清干净（绝不隔夜）
  …    数据跑完 → 平掉仓位、撤掉保护单、机器人自己停，操作权交回
```

每推进一根，执行器按固定顺序做五件事（`bot_strategy_tick`）：

```
1. advance       撮合上一根挂着的止损/止盈（价格怎么穿不用机器人管）
2. 换日检查       交易日变了 → 清仓 + 撤残留保护单
3. 同步保护单     一张成交了 → 撤掉另一张（OCO 的售后）
4. 收盘收尾       04:50 之后 → 清仓，不再开新仓
5. 空仓才问策略    有信号 → 市价开仓 + 挂止损 + 挂止盈
```

第 1 步必须在第 5 步之前：**先让上一根的挂单成交，再判断要不要开新仓**。
反过来的话，同一根里刚平掉的仓会被当成「还有仓位」，下一个信号要白等一根。

## 5. OCO：一个必须存在的规则

5 分钟 K 线只有最高价和最低价，**看不出这一根里先摸到止损还是先摸到止盈**。
一根长影线两头都扎的时候，止损和止盈会同时被判为触发。

不拦的后果很具体：止损先成交（仓位归零），止盈接着成交（仓位变成 −1），
**凭空多出一个没人管的反向仓**，然后它一直裸奔到日终。

实测（真实数据，2026-10-05 起 11 个交易日，MNQ 1 手）：

| | 修复前 | 修复后 |
|---|---|---|
| 开仓次数 | 46 | 46 |
| 成交笔数 | 96 | **92**（46 开 + 46 平） |
| 已实现盈亏 | −7.00 | **−113.00** |

修复前的 −7 是假的：反向仓在趋势里赚的钱，把真实亏损盖住了。看成交笔数就能发现
（96 ≠ 46×2），但只盯着盈亏数字是看不出来的。

实现上给订单加了 `Group`：同一组最多成交一张，其余在本根标成 `cancelled`。
机器人开仓时先挂止损、后挂止盈、打同一个组 —— **顺序决定同根双触发时判止损**，
这是保守的方向，也是唯一能写进文档的口径（`TestOCOGroupFillsOnlyTheFirstOrder`）。

用户手动下的单 `Group` 为空，互不影响。

## 6. 加第二个策略

三步，不用碰协议、前端、撮合：

**① 实现接口**（`internal/strategy/xxx.go`）

```go
func init() { Register(func() Strategy { return &myStrategy{} }) }

type myStrategy struct {
    v       Values
    lastIdx int
}

func (s *myStrategy) ID() string      { return "my-strategy" }
func (s *myStrategy) Name() string    { return "我的策略" }
func (s *myStrategy) Summary() string { return "一句话说明，会显示在启动面板里" }

func (s *myStrategy) Params() []Param {
    return []Param{{Key: "n", Label: "周期", Default: 20, Min: 2, Max: 200, Step: 1, Help: "..."}}
}

func (s *myStrategy) Configure(v Values) error { s.v = Merge(s.Params(), v); return nil }
func (s *myStrategy) Reset()                   { s.lastIdx = -1 }

func (s *myStrategy) OnBar(ctx *Context) []Signal {
    if ctx.Cursor == s.lastIdx { return nil } // 同一根可能被调用多次
    s.lastIdx = ctx.Cursor
    if !ctx.Flat() { return nil }             // 有仓位就别叠
    // …判断…
    return nil
}
```

**② 写测试**：造几根 K 线喂进去，断言信号的方向和止损价。照抄 `caveman_test.go` 的 `feed`。

**③ 跑 `go test ./...` + `npm run build`**（前端不用改，但 exe 里托管的 `web/dist` 要重新构建）。

启动面板会自动多出这一项 —— 它读的是后端注册表（`list_strategies`），不是前端写死的列表。

## 7. 已知限制

- **5 分钟粒度**：同根内先破上还是先破下判不了（已用 OCO 兜住"两张保护单"这一种后果，
  但"先止损后反向、还是先反向后止损"这类路径依赖仍然无法区分）。
- **零成本**：见 §1。想看真实一点的数字，得往撮合里加滑点和佣金，那是另一件事。
- **不模拟部分成交、不模拟流动性**：一根 K 线里想成交多少手都能成交。
- **没有资金管理**：手数是固定值，不按波动率调整，也不做最大回撤熔断。
- **策略状态不落盘**：机器人是进程内的运行状态，重启程序不会接着跑（持仓和成交在存档里）。
- **止损被手动撤掉**：执行器会发现「止损单不在了但仓位还在」，立刻市价平仓，不裸奔。
