# 复盘（菜单 3）设计

> 一份**在本地浏览器里逐根回放 K 线**的工具：选一个标的和一个时间点，从那一刻开始一根一根
> 往前走，在图上画趋势线/射线/矩形/箭头线/斐波那契回撤，按限价单和止损单做模拟交易。
>
> 前端在 `web/`（Vue 3 + TypeScript + Vite），后端在 `internal/replay`（Go，零第三方依赖）。
> 两者之间**只有 WebSocket**，一条 JSON 消息一个动作。

## 1. 它是什么、不做什么

| 做 | 不做 |
|---|---|
| 从 `data/` 里读 CSV，按「时间字符串」定位 K 线 | 改 CSV（复盘全程只读数据目录） |
| 一个服务端内存里的「实例」，可多人同时看 | 把实例写进数据库（只写一个本地 JSON 存档） |
| 实例、标注、挂单、成交写进本地存档，重启后还在 | 重启后接着「当时的操作者」——操作权要重新拿 |
| 一人操作、其余人观看的演示模式 | 多人同时改同一个实例 |
| 标注、挂单、成交都记在服务端并按顺序广播 | 前端偷偷改状态（除了缩放平移） |
| 离线可跑的机器人，驱动上述全部操作 | 机器人的策略合理性（它只负责"能操作"） |

**没有**初始资金、保证金、手续费、滑点、点差，也**没有**止损/止盈单类型 ——
要止损就自己挂一张 `stop` 单，规则和手动挂单完全一样。这是需求明确要求的简化，
换来的是「盈亏数字只由成交价决定」，容易核对。**市价单**只在「立刻成交」这一个动作上存在
（下单浮窗里的「市价买入/卖出」按钮），它按当前收盘价当场成交，不进入挂单队列。

## 2. 怎么跑起来

两种方式，二选一：

**A. 由 Go 服务托管页面（日常使用）**

```bash
cd web && npm install && npm run build      # 只需在改过前端代码后重跑
# 根目录双击 exe（或跑 build.cmd 后启动），菜单选 3
```

菜单 3 会在 `127.0.0.1:8790` 起一个服务，同一个端口既是页面也是 WebSocket，
并自动打开浏览器。页面地址、WS 地址都会打印在终端里。

**B. 开发模式（改前端代码即时生效）**

```bash
# 终端 1：Go 服务（菜单 3）
# 终端 2：
cd web && npm run dev     # http://127.0.0.1:5173
```

`vite.config.ts` 把 `/ws` 转发到 `127.0.0.1:8790`（`ws: true` 不能少，否则 Vite 当普通
HTTP 转发，浏览器收到的不是 101，握手直接失败）。Go 服务端口被占用时会自动换端口，
**换了要同步改 `vite.config.ts` 里的 target** —— 终端会明确告诉你换了。

配置项（`config.json`）：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `replayPort` | `8790` | 复盘服务端口。`0` = 让系统随便给一个 |
| `replayDistDir` | `"web/dist"` | 前端构建产物，相对 **exe 所在目录** |
| `replayStateDir` | `"state"` | 实例存档目录（索引 `replay-instances.json` + `instances/<id>/` 每个实例一个文件夹），相对 exe 目录 |
| `replayRecordingDir` | `"recordings"` | 录像目录（一份录像一个文件夹 + 一份索引），相对 exe 目录；用户产物，不入库 |

没构建前端时打开页面会看到一句明确的提示（不是白屏），并告诉你上面两条命令。

## 3. 一条消息的旅程

以「点一下『下一根』」为例，这条链路上每一步都能在代码里找到对应位置：

```
浏览器                    Go（internal/replay）                        其他浏览器
  │  {"type":"step"}            │                                            │
  ├───────────────────────────>│ Handle()                                    │
  │                            │  ├─ 操作权是不是你？（requireOperator）      │
  │                            │  ├─ Cursor++                                  │
  │                            │  ├─ 用新 K 线的 high/low 撮合挂单             │
  │                            │  ├─ 算浮盈、累计已实现盈亏                     │
  │                            │  └─ broadcastInstance("bar_advanced", 全量)  │
  │<───────────────────────────┴────────────────────────────────────────────>│
  │  把 bar 追加进 bars、更新游标/订单/成交/持仓，然后重画画布                 │
```

要点：

- **所有会改状态的请求都走同一条路**：校验 → 改 `Instance` → `appendEvent` → 广播。
  广播里带 `by`（谁做的）和 `seq`（该实例内的递增序号），所以「谁在什么时候做了什么」
  在后端是完整的。界面底部的「操作记录」就是这条流。
- **广播只发给这个实例的成员**。`broadcastInstanceLocked` 只遍历 `client.InstanceID == inst.ID`
  的连接，因此前端**收不到别的实例的数据**，不是靠前端过滤。
- **缩放和平移不发消息**。它们是纯像素变换，只影响本机画布；一旦发往后端，
  多用户就会互相抢视口。

## 4. 实例

实例是后端的一个对象（`internal/replay/instance.go`）。建实例时后端做这些事：

1. 按标的名找到目录（只认 `_symbols.json` 的登记，和菜单 2 一致）；
2. 选锚点：`time` 为空就**随机**挑一天、再挑那天的一根；给了时间就必须精确命中某根；
3. 锚点那天**整日**收进来，游标停在锚点上 —— 当天锚点之后那些根先「进内存但不下发」，
   点「下一根」才是真正的下一根（`12:00` 的下一根是 `12:05`，不是第二天 `00:00`）；
4. 往前一个日文件一个日文件地收，直到**已揭示**的根数够 400 根（`bars` 参数可调），这就是画布上的历史；
5. 往后预加载 5 天（`forwardDays`）—— 同样进内存但不下发，和「当天剩下的那部分」一起叫「未揭示」；
6. 算 EMA20；顺带把标的最小跳动（`tick`）挂到实例上，前端价格轴要用它。

| 字段 | 含义 |
|---|---|
| `bars` | 已揭示的 K 线（长度一定等于 `cursor + 1`） |
| `hiddenBars` | 已加载但还没揭示的根数 |
| `hasMore` | 数据目录里还有没有更晚的日文件 |
| `tick` | 这个标的最小跳动（来自 `_symbols.json`，见 10.1） |
| `tickValue` | 一个 tick 值多少美元（MNQ 0.5、MES 1.25、MGC 1、CL 10），结算盈亏用 |
| `annotations` / `orders` / `trades` | 标注、挂单、成交流水 |
| `position` | `{quantity, side, averagePrice}`，`quantity` 带符号（正多负空） |
| `realizedPnl` / `unrealizedPnl` | 已实现 / 浮动盈亏 |
| `operator` | 当前操作者的名字（空 = 无人） |
| `members` | 谁在看 |
| `events` | 最近 100 条操作记录（完整 500 条留在后端） |
| `notes` | 加载过程中的实情：哪份 CSV 有坏行、哪个日文件读不了 |

游标走到预加载末尾时，`ensureFuture` 会按日文件顺序往后读（空文件跳过，最多一次看 40 个），
读到数据目录尾就返回「数据已经到最后一根 K 线了」，界面会把这句话显示在右下角。

### 4.1 实例存档：重启后还在

实例、标注、挂单、成交本来只在内存里 —— 关一次程序就全丢（这是 v1 的行为）。现在改成
**定时落盘**，而且从 v2 起**按实例分文件夹**（v1 是所有实例塞在一个 JSON 里）：

```
<replayStateDir>/replay-instances.json        索引：版本、保存时间、下一个实例编号、实例 id 清单
<replayStateDir>/instances/ins-1/meta.json          游标、标的、tick/tickValue、持仓、累计盈亏、计数器、备注
<replayStateDir>/instances/ins-1/bars.json          已加载的 K 线（含未揭示的未来部分）
<replayStateDir>/instances/ins-1/annotations.json   标注
<replayStateDir>/instances/ins-1/orders.json        挂单
<replayStateDir>/instances/ins-1/trades.json        成交流水
<replayStateDir>/instances/ins-1/events.json        操作记录
```

| 落盘时机 | 为什么是这个时机 |
|---|---|
| 任何**会改实例的状态变化**（`markDirtyLocked(inst.ID)`）后 2 秒内 | 改状态的地方和广播是同一处（`broadcastInstanceLocked`），所以「广播过 = 该存了」，不会漏 |
| `srv.Close()`（Ctrl+C 回菜单）时**同步再刷一次** | 定时器可能刚好还没到点，不补这一下就会丢最后两秒的操作 |
| 建实例、删实例时立刻标脏（索引 + 实例两个标记） | 新建的实例还不能广播，但已经该被记住；删掉的要从索引里去掉并回收文件夹 |

几个刻意的取舍：

- **索引只记 id 和目录名**：K 线、成交这些大头都在实例自己的文件夹里。改一个标注只重写
  那个文件夹（`dirtyInst`），不用把别人的行情也抄一遍；文件也能直接打开看。
- **`meta.json` 最后写**：它是这份实例存档的提交点。中途断电时最多丢最后两秒的增量，
  不会出现「游标指向一根不存在的 K 线」（加载时按 `cursor` 截取 `bars`）。
- **只存「属于实例」的东西**：`operator`（谁在操作）**不存** —— 重启后那个人的浏览器可能早关了，
  存下来就会卡在「有人操作但人不在」。谁进来谁重新拿操作权。
- **日文件索引不存**：它取决于磁盘上现在有哪些 CSV，重启时按「最后一根 K 线的日期」往后
  重新索引一遍（`reindexLocked`），比存一份可能过期的索引更可靠。
- **实例编号接着走**：索引里带 `NextInstance`。不存它，重启后新实例会和旧的撞号（`ins-1` 撞
  `ins-1`），前端 join 到错的实例。
- **写文件用 tmp + rename**：写到一半断电，原来的文件还是完整的。
- **索引坏了不影响启动**：JSON 解析失败就当作「没有实例」，**坏文件原样留着**并在终端报一句，
  绝不自动删 —— 那可能是你唯一的一份。单个实例的标注/挂单/成交坏了只当空的，
  不会因为一个文件损坏就丢掉整段复盘（`meta.json` / `bars.json` 缺了才跳过这个实例）。
- **删掉的实例不会复活**：索引是「当前全部实例」的快照，不是追加日志；索引写成功后
  才会回收**被删实例**的文件夹（先写索引、后删目录，中途断电最多留一个空目录，不丢数据）。
- **旧存档自动迁移**：读到 v1 单文件时，先把原文件备份成 `replay-instances.json.v1.bak`，
  再摊进新布局并重写索引；恢复出来的游标、标注、挂单、成交一条不少。v1 里的盈亏是
  「点数 × 手数」口径，迁移时按 `tickValue / tick` 换成美元（老实例的累计盈亏和流水
  因此与新版一致，不会新旧混着两种单位）。
- **旧存档缺的 K 线会补回来**：0.5.0 建的实例，`bars` 里锚点日之后缺一整段（见 12 与
  `repairDayGapsLocked`）。恢复时发现「相邻两根跨日、而前一根在自己那天的日文件里还有后续行」
  就按日文件把这段日期范围重读一遍；游标和挂单的 `placedIndex` 一律按**时间**重新定位
  （补齐后下标全变了，只有时间还靠得住）。

对应的实现全在 `internal/replay/persist.go`。

## 5. 操作权：一人操作、其余观看

实例上记一个名字 `operator`：

- 建实例的人自动成为操作者；
- 后进来的人是**观众**：能看所有广播，但改状态的请求会被后端拒绝，提示
  「现在由 human 操作，你只能观看…」；
- 操作者点「交还操作权」后 `operator` 变空；此时任何人点「接管」，或者**直接做任意一个
  操作**（谁先动谁接管）都会拿到它；
- 操作者断开连接（关标签页、断网），操作权自动释放并广播 —— 否则实例会卡在「有人操作但
  那个人已经不在了」；
- 机器人启动时**接管**操作权（`operator = "bot"`），所以真人只能看 —— 这正是演示模式。
  机器人停止后操作权交回叫停的人。

「多用户测试时禁止同时操作」在后端是**硬约束**，不是界面把按钮置灰而已：
即使两个标签页同时按下「下一根」，第二个请求也会被拒绝。

## 6. 标注：只有时间和价格，没有像素

一个标注点长这样：

```json
{ "time": "2026-10-16 12:00", "price": 30125.5 }
```

`time` 是 CSV 里那一列的原始文本，必须是**已经揭示的某一根 K 线的时间**（锚点）。
`price` 是价格。**没有 x/y 像素**。理由：

- 换个窗口大小、缩放级别、换个显示器，像素坐标就全错了，而时间价格不会；
- 后端要做校验（锚点不能是未来的 K 线），它只认识时间和价格；
- 存下来就能直接对照 CSV 检查「这条线是不是画在那根的高点上」。

端点停在最后一根 K 线右侧时（画一条指向未来的趋势线、一个目标区间的矩形），
JSON 里多一个 `offset`：

```json
{ "time": "2026-10-16 12:00", "price": 30310.0, "offset": 40 }
```

含义是「从 12:00 那根 K 线往右数第 40 根」。**它不是时间**，也不是像素：

- 右侧那一段一根 K 线都还没有，没有任何真实时间可以引用。按 5 分钟硬往外推会撞上
  周末/休市（推出来的时间并不是真实 K 线的时间）；等新 K 线揭示出来，同一个未来时间
  又会落到另一个下标上，画好的线会自己左右跳；
- 「锚点下标 + 根数」只依赖已经存在的 K 线：缩放、平移、步进都不会让它漂。
  渲染时用的是和 K 线**完全相同**的一条公式
  `x = left + (锚点下标 + offset - scroll + 0.5) * barWidth`，所以延伸段和 K 线严格对齐；
- 锚点仍然必须是已揭示的 K 线（`time` 那一条红线没变），所以 `offset` 不泄露任何未来信息；
- `offset = 0` 时这个字段不会出现在 JSON 里 —— 旧存档、旧客户端看到的和以前一模一样；
- 偏移在前后端各夹一次（`maxForwardBars = 5000`）：前端夹是为了「预览 == 定稿」，
  后端夹是因为它不能信任消息内容。

**吸附（按住 Ctrl）**：按住 Ctrl 的那一刻，**十字光标自己先跳到 OHLC 上** —— 横线、竖线、
价格标签、吸附点上的小圈、左上角那句「Ctrl 吸附：开 100.00 · 周五 2026-10-16 09:35」一起动，
于是「这一下会落在哪儿」在**单击之前**就看得见（v1.6 之前不是这样：吸附只发生在画下去的
那一刻，按着 Ctrl 十字线纹丝不动，得先点一下才知道起点落在哪，点歪了只能 Esc 重来）。

吸附的取舍：把指针位置换算成「光标下那根 K 线 + 价格」，再在这根 K 线的 O/H/L/C 里挑最近的
一个。后端收到 `snap: true` 会**自己再吸一次** —— 两边用的是同一套取舍规则（O 优先，严格更近
才替换），所以预览和定稿必然一致；就算有人手工构造一条消息，也吸不出别的结果。延伸到右侧的
端点吸的是**锚点那根** K 线的 OHLC —— 那一段没有 K 线，没有别的报价可吸，前后端用的是同一根。

前端这套取舍只有一份实现：`web/src/components/chart/snap.ts` 的 `nearestOHLC` / `snapAtCursor`
（十字光标与价格提示调 `snapAtCursor`，定稿与拖动端点调 `nearestOHLC`）。**改它时必须同时
看一眼 Go 那边的 `nearestOHLC`** —— 两边不一致的症状是「单击之后图形跳一下」。

### 6.1 五种图形，全部用两个点描述

| 图形 | `kind` | 画出来是什么 |
|---|---|---|
| 趋势线 | `trend` | 两点之间的一段直线 |
| 射线 | `ray` | 从起点出发、穿过终点，一直延伸到价格区边界。**默认单击一下就画一条水平朝右的**（见 6.2） |
| 矩形 | `rect` | 两个对角点围成的区域（填充 + 边框） |
| 箭头线 | `arrow` | 趋势线 + 终点一个箭头 |
| 斐波那契回撤 | `fib` | 两点的价格区间摊开成 -1 / 0 / 1 / 2 四条**水平**线 |

两个端点的**锚点**都必须落在**已经揭示**的 K 线上（指向还不存在的 K 线既没意义，也会泄露
后面的行情）；但端点可以带 `offset` 往右越过最后一根 —— 五种图形都支持：趋势线/射线/箭头线
的终点、矩形的右边界、斐波那契四条水平线的右端都会跟着延伸过去。
「全部用两个点」是刻意的：协议、校验、拖动逻辑因此只有一套 —— 加第六种图形只要在
`annotation.go` 里加个常量、在 `chart/annotations.ts` 里加一段几何。

**斐波那契为什么只有四条水平线**：比例 0 = 起点价、1 = 终点价、-1 和 2 是往外各一个区间
（`price = start + ratio × (end - start)`）。它们**永远水平、互相平行**，用户只能改颜色，
不能单独拖某一条 —— 想改的是「这段区间的回撤位」，不是随手画四条线。

### 6.2 绘制：射线单击即完成，其余两次单击

绘图工具**不是按住拖动**。五种工具里，**射线单击一下就画完**，其余四种是两次单击。

**射线（单击即完成）**：

1. 点【射线】（光标变十字）；
2. 移动鼠标 —— **预览已经跟着鼠标走了**，落点和价位在按下之前就看得见；
3. 单击 = 定稿，一条**水平朝右**的射线，一直延伸到价格区右边缘；
4. 工具自动交回指针。

按住 **Shift** 则退回两次单击，用来画**斜**射线（默认形态本来就是水平，Shift 在这里是「退出它」）。

**其余四种（两次单击）**：

1. 在工具栏点一个工具（此时光标变十字）；
2. 第 1 次单击 = 定起点，立刻进入预览（预览用的是当前模板的样式）；
3. 移动鼠标找终点（按住 Shift → 趋势线/箭头线画成水平线）；
4. 第 2 次单击 = 定稿，把「两个端点 + 样式」发给后端；
5. 工具**自动交回指针模式**：想画下一个就重新点一次工具。

为什么不用拖动：拖动手势在触控板上很容易画歪，而且「一边拖一边看价格」时手一抖终点就跑了；
两次单击可以先把起点放稳，再慢慢找终点。两次点在同一根 K 线的同一个价位时视为「重新开始」，
不会产生一个看不见的零长度图形。

**为什么射线要单击**：复盘里画得最多的是「某个价位往右延伸的水平线」—— 支撑、阻力、
入场位，几乎每笔复盘都要画几条。原来要「选起点 → 按住 Shift → 选终点」三下才能得到
一个**本来就该是水平**的结果，Shift 在这里没有信息量，只是把两次单击变成了一次。
射线是「从起点穿过终点一直延伸」，方向完全由两个端点的相对位置决定，所以单击时
**终点可以由程序算出来**：价格取起点的价格（这就是水平），横坐标取「当前视口右边缘再往右一根」
（`indexAtX(plot.right) + 1`）。按当前视口算而不是写死一个根数，射线在任何缩放下都至少
越过整个可视区 —— 写死 50 根的话，放大到 `barWidth=40` 时只有 2000px，线会被裁在一个
莫名其妙的位置。真正画到哪儿仍然由 `clipRay` 按当前视图裁，缩放/平移后自动跟着变。

**为什么画完退回指针**：图形一旦定稿，接下来的单击就该回到平移 / 缩放的常规手势。
留在绘图工具上的话，下一次在空白处单击（比如想拖一下视图、或者只是想取消选中）
会接着画出一条看不见的零长度线 —— 指针模式下单击空白本来就是平移，两种工具的「空白处单击」
含义必须分开。「选工具 → 画两下」本来就是一个完整动作，回退的成本只是重新点一下工具。

### 6.3 模板：样式存在后端，图形存样式快照

每个工具下面有一组模板（颜色、线宽、实线/虚线；矩形多了填充色与填充不透明度；
斐波那契是四条水平各自一个颜色）。全部工具都有自己独立的一组，互不影响。

- 模板存在 `<stateDir>/replay-templates.json`，**全局**（不属于某个实例）：模板描述的是
  「我习惯用什么颜色的线」，换个标的复盘还是那几条；
- 第一次运行会种下 10 条出厂模板（每个工具两条，一实线一虚线），打开就能画；
- 改模板**不影响已经画好的图形** —— 图形里存的是画下去那一刻的样式**快照**
  （`Annotation.style`），不是 `templateId`。否则今天改一下颜色，昨天画在盘面上的
  十条线一起变色；
- 谁能改都行，不校验操作权：模板是「本机偏好」，不属于某张盘面。

### 6.4 编辑：点一下图形就改，点空白就退出

工具栏上**没有【指针】和【修改】两个按钮**了。工具只有「指针（默认）」和「五种绘图工具」，
编辑不是一种模式，而是指针模式下「选中了某一个图形」的状态：

| 操作 | 结果 |
|---|---|
| 单击图形 | 它成为**唯一**的编辑对象（出现两个端点手柄和虚线包围框），同一个手势按住还能直接拖 |
| 单击另一个图形 | 编辑对象换成新的那一个，上一个立刻失去手柄（不需要先取消再选） |
| 单击空白 / K 线 / 坐标轴 / 挂单线 | 退出编辑，回到纯指针（缩放、平移、改挂单价） |
| 拖**端点手柄** | 只移动这一个端点 |
| 拖**图形本体** | 整体平移（两个端点一起走） |
| `Del` / `Backspace` | 删除正在编辑的图形 |
| `Esc` | 也是退出编辑（不用把手从键盘上移开） |

移动和「只动一个端点」走的是**同一条消息**（`annotation_move` 带两个端点的新位置），
只动一个时另一个原样发回；后端校验完广播回来，界面上的图形永远来自广播。
样式不跟着移动变 —— 样式在画下去那一刻就定了。

**为什么按下就选中（而不是「先点一下选中、再拖」）**：编辑一个图形是一个连续动作。
选中放在 `pointerdown` 里，按住的同时就能拖端点，少一次点击；而且不会出现
「按下去是拖、松手补的那个 click 又把选中翻掉」的麻烦（旧版为此专门写了 `lastDragMoved`
去挡那个 click，现在整套补丁都删了）。

**「正在编辑哪一个」只有一份状态**：`store.selectedAnnotation`（派生出的 `editingId`
在拿起绘图工具时恒为 `null`）。界面上的手柄、虚线框、`Del`、底部提示语全部读它，
所以「切换编辑对象」只是把这个 id 换成另一个 —— 不是「退出一个模式再进入另一个模式」，
也就不会出现两个状态互相对齐的事故（典型的下场是手柄挂在一个刚被删掉的图形上，
下一次 `Del` 打到空气）。三条兜底保证它也留不下来：

1. 绘图工具在手时 `editingId` 派生为 `null`，同时 SVG 那一层 `pointer-events: none`
   —— 拿起笔就等于放下编辑；
2. 别人删掉了这个图形（`annotation_deleted` / `annotation_cleared`）、或者换了一块盘面
   （新的 `instance_state`），store 立刻清空选中；
3. `selectedId` 还会再确认这个图形**确实画得出来**（`figures` 里有它），
   锚点所在的 K 线暂时不在已揭示数据里时，手柄不会挂上去，`Del` 也不会删掉一个看不见的东西。

**绘图工具下为什么不接点击**：手里拿着笔时，鼠标落在哪儿都是「定起点」。如果图形还能被点中，
在线条密集的地方就再也下不了笔（点一下变成选中）。所以「想让图形可点」这件事的代价是
「先把笔放下」—— 而这个动作已经自动发生了：定稿后工具自动交回指针。

**按下在空白处为什么是「按下即退出」而不是「松手再退出」**：按下的那一刻用户已经决定了
要拖视图还是拖挂单；手柄留着会挡住这一下要拖的东西。顺带一个副作用是要说清的：按挂单线
（画在 Canvas 上的那张单）也会退出编辑 —— 它不是绘图图形，规则只有一条「不是图形就退出」。


**前端预览、后端定稿**（需求第 10 条）的做法：

1. 绘制/拖动时只更新本地的 `pending` / `moving`，**不发消息**；
2. 第 2 次单击（或松手）时把 `{kind, start, end, style, snap}` 发往后端；
3. 后端校验（时间必须已出现、价格必须有限、样式夹到合法范围）→ 编号（`a1`、`a2`…）→ 广播；
4. 界面上的正式图形**永远来自广播**。后端拒绝时预览一消失，界面上什么都不会留下。

## 7. 模拟交易：撮合规则与盈亏

挂单只有两个参数会影响成交：`kind`（`limit` / `stop`）和 `price`。
每次揭示新的一根 K 线，后端用这根 K 线的**最高价和最低价**去碰所有挂单：

| 单子 | 触发条件 | 成交价 |
|---|---|---|
| 限价买 `limit buy` | `low <= price` | `min(price, open)` |
| 限价卖 `limit sell` | `high >= price` | `max(price, open)` |
| 止损买 `stop buy` | `high >= price` | `max(price, open)` |
| 止损卖 `stop sell` | `low <= price` | `min(price, open)` |

- **成交价通常是挂单价，跳空时是开盘价**（`fillPriceFor`）。触发判定用的是整根 K 线的高低点，
  但开盘就已经越过挂单价时，那一笔真实成交发生在**开盘那一刻**：限价单会成交在更好的开盘价上
  （`min`/`max` 取优），止损单会成交在更差的开盘价上（取劣）。一律按挂单价成交，
  等于跳空时凭空占便宜 —— 止损买单最明显：跳空高开到 106，却还用 102.5 买到。
- **成交价会一路传到持仓成本、成交流水和盈亏**（`applyFill(o, price, t)`），不是只改个显示字段；
- **手数只能是整数**（`placeOrder` 校验）：期货没有「0.4 手」这种报单。前端下单浮窗、
  右键菜单、`placeOrder` 三处都按整数夹一次，后端再硬校验一遍；
- **盈亏按合约价值换算成美元**：价格差乘出来的是「点数」，再乘 `tickValue / tick`
  才是美元（MNQ 0.5/0.25 = 2 美元/点，MES 5，MGC 10，CL 1000）。一跳值多少写在
  `_symbols.json` 的 `tickValue` 里，没配置时退化成每点 1 美元 —— 这个乘数不另存，改了配置重开就生效；
- **本根挂的单从下一根开始参与**：`placedIndex >= cursor` 的单会跳过 —— 否则就是拿
  一根已经收完的 K 线的最高最低价倒推成交，等于开了后视镜；
- 一次触发按挂单数量**全部成交**，不做部分成交；
- 下单时**不校验「这个方向该用哪种单」**：挂反了（比如现价 100 挂 95 的止损买）在真实市场里
  是一张已经触发的市价单，撮合按开盘价成交，不会按更便宜的 95 白捡。界面上的右键菜单会自动选单型
  （见 10.3），下单浮窗仍允许手选；想**立刻**成交就用「市价」按钮（见下）。

**市价单（`order_market`）不参加上面这张撮合表。** 下单浮窗里的「市价买入 / 市价卖出」按钮
不需要价格：后端按**游标那根 K 线的收盘价**当场成交（`marketOrder`），订单直接是 `filled`，
成交、持仓、盈亏同步更新，不会留在挂单列表里等下一根。

为什么不做成「现价挂一张立即能成交的限价单」：复盘里没有盘口，能成交的价格就是当前收盘价；
如果让它排队，用户点完会看到「什么都没发生」，下次步进还可能按跳空后的价格成交 —— 那是限价单的语义。
市价单至少守住三条：

- 成交价 = 当前收盘价（和界面上「现价」显示的是同一个数），不计滑点；
- 手数仍是整数、仍要操作权，盈亏照样走 `applyFill`，口径与挂单成交完全一致；
- 它也记一条 `orders`（`kind = market`、`status = filled`），成交流水、历史列表和存档
  都不用另开结构。

**一根 K 里同时打掉两个方向的单怎么办？** 回放只有 O/H/L/C，没有盘中路径，所以同一根里
「先高后低」还是「先低后高」无从判断。现在的做法是按挂单顺序依次成交（都按各自的成交价），
因此一张止盈和一张止损挂在一起时，可能在同一根里都被打掉。要知道先后，得有更细的数据源。

盈亏用**平均成本法**（`applyFill`）：

- 同向加仓：`新均价 = (|旧仓|×旧均价 + 本次数量×成交价) / (|旧仓|+本次数量)`，本次实现盈亏 0；
- 反向减仓：先平掉能平的 `min(|旧仓|, 本次数量)`，
  实现盈亏 `(成交价 - 均价) × 平掉的数量 × 方向 × 每点价值`（多头方向 +1，空头 -1）；
- 平完还有剩余就是**反手**：新仓均价 = 本次成交价。

例：MNQ（2 美元/点）先在 18000 买入 1 手，再在 18110 卖出 3 手 → 平掉 1 手实现
`(18110-18000)×1×2 = +220 美元`，剩下 2 手空单均价 18110。此时收盘 18092，
浮动盈亏 `(18092-18110)×(-2)×2 = +72 美元`。

`quantity` 是带符号的：多头为正、空头为负、空仓为 0。界面上的「多/空/空仓」是它的展示。

## 8. 机器人（演示 / 策略）

工具栏上的【启动机器人 ▾】能起两种机器人，共用同一个 goroutine、同一把锁、同一条操作路径：

- **随机演示机器人**（不选策略）：每 `intervalMs`（默认 1200ms）随机做一件事，只用来压链路；
- **策略机器人**（选一个策略）：每 `intervalMs`（默认 300ms）推进一根 K 线，问策略该不该开仓。

### 8.1 随机演示机器人

它的动作表：

| 动作 | 权重 | 说明 |
|---|---|---|
| 步进 | 50% | 数据到底了就安静地跳过 |
| 加标注 | 18% | 随机挑一种图形、随机颜色/线宽/线型，随机决定是否吸附 |
| 移动标注 | 10% | 随便挑一个挪到另一根 K 线上 |
| 删除标注 | 8% | 同时存在的标注上限 40 个 |
| 挂单 | 12% | 买卖 × 限价/止损随机，价格在当前价附近 |
| 撤单 | 2% | 挂单上限 12 张 |

它**不走后门**：调用的是和真人完全相同的 `doStepLocked` / `doAddAnnotationLocked` /
`doPlaceOrderLocked`，广播里 `by = "bot"`。所以：

- 机器人能跑通 → 真人点按钮一定跑通；
- 机器人报错 → 真人会遇到同样的错（日志里能看到原因）。

它**不追求盈利或合理**（需求明确说了），存在的价值是把「K 线 + 标注 + 交易」三条链路
持续压测一遍，并且给一个人演示时提供「有人正在操作」的素材。

### 8.2 策略机器人（0.13.0）

选一个策略启动之后，机器人不再掷骰子，而是**每推进一根 K 线问策略一次**：

```
步进一根 → 撮合上一根的止损/止盈 → 同步保护单（OCO）→ 收尾时段清仓 → 空仓才问策略
```

有信号就市价开仓，并挂上两张保护单（止损 = stop 单、止盈 = limit 单，**同一个 OCO 组**），
收盘前平掉，数据跑完自己停并把操作权交回。策略本身在 `internal/strategy/`，
只出「方向 + 止损价 + 目标价」，下单和成交全靠复盘台那套撮合 —— 所以和真人点按钮同一条路。

**日终硬约束**：日历日最后一根 K 线（23:55）上无条件平仓 + 撤光该实例所有未成交挂单，
本根不再问策略。判据 `strategy.DayClose()` 只看 CSV 时间列的明文（北京时间），
不做时区换算。缺了 23:55 那根时靠「跨日历日」兜底强平，代价是吃一次跳空。
注意 CSV 的一天（00:00~23:55）和 CME 交易日（06:00~次日 05:00）差 6 小时，
所以一个交易日在文件上被切成两段，一天里最多两次收摊。

同组两张单**一根 K 线里最多成交一张**（OCO）。谁成交由 `instance.go` 的 `ocoWinner` 决定：
**止损优先于限价，同类先挂优先**，与挂单顺序无关。5 分钟 K 线只有最高/最低价，
两头都扎到时内部先破哪边数据里没有，取对持仓更不利的一侧（止损）是唯一诚实的口径；
判成止盈会让每一次「说不清」都替策略挑好结果，回测数字系统性偏乐观。

第一条实现是 **Caveman（野人）**：强趋势棒被紧接的反向棒吞回起点，顺着吞没方向做反转。

**零滑点、零手续费**下运行（需求指定的假设），界面上的盈亏是「最有利情况」，
不是实盘结果。完整说明见 **`docs/策略机器人.md`**。

### 8.3 为什么机器人是"演示模式"

机器人启动时**接管**操作权（`operator = "bot"`），所以真人只能看。
停止时**仓位保留、保护单撤掉**、操作权交回给叫停的人 —— 用户可能只是想暂停，
自己接着做。

| `pong` | 心跳应答 |

`action` 共 13 种：`bar_advanced`、`annotation_added/moved/deleted/cleared`（`annotation_cleared`
是「一次清空」：负载带 `count` 和删掉的 `annotationIds`，一条广播 = 一个原子状态）、
`order_placed/filled/moved/cancelled`（`order_filled` 是市价单成交，负载里带订单、成交、持仓和盈亏；
`order_moved` 带「改完的那一张」+ 全量列表）、
`control_changed`、`members_changed`、`bot_started/stopped`，
以及 `voice_added` / `voice_cleared`。

**语音那两条不进盘面状态**：语音是盘面数据（`instance.voice` / `voiceAll`），
但**不是**能靠 `applyInstanceEvent` 演出来的东西 —— 回放时语音只从记录里的语音步来，
所以 `applyInstanceEvent` 见到这两条会直接返回（见 11.7）。

v0.18.0 删掉的四条：`recording_started` / `recording_stopped` / `recording_audio` /
`recording_audio_cleared`。它们存在的理由是「录制是一个用户可见的状态」，而这个状态
已经被取消了：交易记录的开始与结束**只看仓位**，没有任何东西需要通知前端去切界面。
「这笔记完了」改由一次性的 `trade_recorded` 消息表达。

**为什么上行李段名写全**（`quantity` 而不是 `qty`）：这份协议要对着日志读、
要手写机器人、要在排查时一眼看懂，多打几个字母换可读性是划算的。

**画布为什么分两层**：K 线一次几百根、每帧重画，Canvas 快；标注要能被指针命中、
能拖动、能选中，SVG 元素天然有命中测试，不用自己写拾取算法。两层的坐标换算都来自
同一个 `ChartScale` 实例，所以图形和 K 线不会对不上。

坐标公式（`scale.ts`）：

```
x(index) = plot.left + (index - scroll + 0.5) * barWidth
y(price) = plot.top  + (priceMax - price) / (priceMax - priceMin) * plot.height
```

`index` 在这里是**连续下标**，可以大于最后一根（`last + offset`）：标注端点就是用它算 x 的，
所以延伸段和 K 线共用同一条公式，缩放/平移时一起动。指针位置反过来换算成端点时走
`indexAtX -> barRefAt`：落在数据范围内存「那根 K 线的时间」，越过末尾存「最后一根 + 根数」。

- 滚轮：以鼠标位置为锚点缩放 `barWidth`（保持指针下的 K 线不动）；
- 指针在**右侧价格轴**（`x >= plot.right`）时滚轮缩放价格轴，并把价格轴从「自动贴合」切成手动；
  在行情区滚轮仍然是缩放时间。**不再需要 Shift** —— 缩放价格是「拨价格轴」这个动作，
  指针站在轴上就该拨轴，而不是先按一个修饰键；
- 拖动：横竖一起平移，纵向拖动同样切手动价格轴；
- 双击：价格轴回到自动贴合；
- **加载新 K 线不移动视图**：「下一根」只把新 K 线按自己的下标追加到右边，`scroll` /
  `barWidth` / `priceMin` / `priceMax` 一个都不改 —— 所以已经画在屏上的 K 线和标注，像素位置
  逐点不变。新 K 线落在可见区外面就先看不见，想看就自己拖过去。视图只有两个入口会主动动：
  进/换实例时的 `resetView()`（初始取景，最后一根落在右侧 88% 处）和用户自己的拖动/缩放。
- 右下角那句操作提示写在**时间轴上方**（`bottom = 时间轴高度 + 4`）—— 贴在底部会和
  时间标签叠成一团重影。

指标分两类：

- **EMA20 在 Go 里算**，随 K 线一起下发 —— 它是盘面事实，指标口径只有一份，
  以后加终端视图也不会出现两套数字。
- **Doji X + Blue ZigZag（Pine v4 脚本的移植）在前端算**（`components/chart/indicators.ts`）：
  Lag / Doji Size 是用户在工具条上随手拧的**显示参数**，拧一下就变，走一趟协议会让
  「改个输入框」变成一次网络往返；它也不改盘面、不进存档，和缩放、平移属于同一类。
  算式逐句对齐 `pine/Doji X + Blue ZigZag.pine`（EMA 用 SMA 种子、`na` 要跳过、
  `mom` 的步长是 `round(lookback/2)`），参数与开关记在 localStorage。

原脚本用 `plot()` 画点，`na` 一断就是散点，看不出「哪一段在涨、哪一段在跌」；所以
`render.ts` 在点之间**多画一条折线**（同色、降透明度，clip 在行情区内）。这条线只是把
相邻两个转折点按时间顺序连起来，不改任何一点的价格与位置 —— 算式仍然只有
`indicators.ts` 一份。左右各多取一个屏外的点再裁掉，跨出屏幕的那一段才不会贴边断掉。

指标画在行情区里，**没有单独的副图区**（v1 那个 BarCount 副图已移除）。

### 10.1 价格轴的最小跳动（tick）

价格轴要显示「这个标的真实存在的报价」，所以刻度步长是 tick 的整数倍：
MNQ/MES 是 0.25 一跳，轴上就不会出现 `30125.3` 这种根本不存在的价格。

tick 的来源是一条链，越靠前越优先：

1. `data/_symbols.json` 里该标的的 `"tick"` 字段（可以手改，抓取程序重写 `_symbols.json`
   时会**保留**它，不会被覆盖掉）；
2. 内置的兜底表（`store.DefaultTick`）：`MNQ/MES` 0.25、`MGC/BTCUSDT` 0.1、`CL` 0.01；
3. 都没有 → `0.01`。

小数位数由 tick 推（`decimalsForTick`）：最少 2 位、最多 6 位。**下限是 2 位是有原因的** ——
加载时价格已经四舍五入到两位小数（`89.97000000000001` → `89.97`），只留一位会显示成
`90.0`，反而看不出真实报价。

四舍五入只做一次，就在**从 CSV 变成 `Bar` 的那个函数里**（`toBar` → `roundPrice`）；
标注端点、挂单价也一样走它。所以前端拿到的一定是两位小数，不会出现
`30125.499999999996` 这种数字在界面上抖。

**每跳价值（`tickValue`）**也写在 `_symbols.json` 的同一条记录里：MNQ 0.5、MES 1.25、
MGC 1.00、CL 10.00（美元）。它只影响盈亏结算：乘数 = `tickValue / tick`，
所以 MNQ 是 2 美元/点、MES 5、MGC 10、CL 1000。没登记时按标的名兜底
（`store.DefaultTickValue`），再认不出来就退化成「每点 1 美元」—— 不会算成 0。
抓取程序重写 `_symbols.json` 时同样**保留**这个字段。

### 10.2 两套配色（浅色 / 深色）

两个维度分开管：

- **页面**（顶栏、面板、输入框、按钮）：`style.css` 里的语义色变量，
  `:root[data-theme='light']` 一换，所有 `bg-panel` / `text-ink` / `border-line` 一起变。
  组件里不写 `slate-950` 这种具体色号 —— 否则加浅色模式时要在几百个类名后面各补一个
  `dark:` 变体，迟早漏一个。
- **画布**（K 线、网格、坐标轴）：Canvas 的像素不跟着 CSS 变量走，所以 `render.ts` 里
  有两套 `ChartTheme`，`themeOf(mode)` 返回其中一套，换主题时**重画一遍**。

两套 K 线配色的区别不是"换个色号"，而是**画法不同**：

| | 阳线 | 阴线 |
|---|---|---|
| 深色 | 绿实心 | 红实心 |
| 浅色 | **白填充 + 黑边框/影线**（空心） | **全黑**（实心） |

白底上纯红纯绿偏刺眼，而且红绿色弱的人看着几乎一样；空心/实心是打印时代就有的老办法，
白底黑字最清楚。（这也正是国内看盘软件的经典画法，只是深色时代大家习惯用红绿。）

主题存在 `localStorage` 的 `tv-replay-theme` 里，下次打开还是上次那套；
`index.html` 里有一小段内联脚本在样式生效**之前**就把 `data-theme` 挂上去，
避免"上次选浅色，进来先闪一下深色"。

### 10.3 画布上的「交易痕迹」与右键菜单（v1.2，v1.3 起单型按方向自动定）

这一版把「看图」和「看仓」并到同一张图上，顺手解决了几处"看得见但不好用"的地方。

**光标吸附到 tick**（`scale.ts` 的 `snapToTick`）。鼠标停在哪，十字光标的价格就吸到
**离它最近的合法跳价**，MES 只会出现 `6484.00 / .25 / .50 / .75`，不会出现 `6484.12`。
一条横线的位置和它右侧那个价格标签用的是**同一个值**，所以标签写的价格就是横线所在的价格。
没拿到 tick（还没进实例）时退化为两位小数 —— 和加载时四舍五入的口径一致。

**Ctrl 吸附 OHLC：按住的那一刻十字线就跳过去**（v1.6）。这是这一版的重点，也是和 tick 吸附
最容易混起来的地方 —— 两者都是「让光标不落在随便一个价上」，但**触发条件完全不同**：

| | 什么时候生效 | 吸到哪儿 | 干什么用 |
|---|---|---|---|
| tick 吸附 | 一直开着 | 最近的合法跳价（`.00/.25/.50/.75`） | 让读到的价是真实报价 |
| Ctrl 吸附 | **按住 Ctrl** | 光标下那根 K 线的 O / H / L / C | 让画出来的端点落在 K 线自己的价位上 |

按住 Ctrl 的当场，十字光标**自己就跳到那个 OHLC 上**：横线、竖线、价格标签、吸附点上的小圈、
OHLC 图例里被吸住的那一项（`开/高/低/收` 变色）、以及左上角那一句
「Ctrl 吸附：开 100.00 · 周五 2026-10-16 09:35」一起动。

```
                  ┌─ 吸附生效时：图例里被吸住的那项变色，左上角写出吸的是哪个价
                  │
 开 100.00 高 101.25 低 99.75 收 101.00      ┌──────────────────────────────────┐
 ────────────────────────────────────────────│ Ctrl 吸附：高 101.25 · 周五 …    │
                                            └──────────────────────────────────┘
                     ╭─╮ ← 吸附点上画个圈，横竖线都变琥珀色
 ────────────────────╰─╯────────────────────   ← 横线（就是被吸住的 OHLC）
```

为什么要「前移到光标」，而不是等画下去的时候才吸：**先看见落点，再单击**。以前按住 Ctrl
十字线纹丝不动，得先点一下才知道起点落在哪，点歪了只能 Esc 重来 —— 那个手感等于没有吸附。
现在按着 Ctrl 慢慢找位置就行，落点一直在眼前。

两个细节：

- **吸附在渲染那一帧现算**（`drawCrosshair` 调 `snapAtCursor`），不是算完存进 `hover` 里：
  否则滚一下滚轮、拖一下画布，十字线会停在上次算出的那个价位上，看着像吸附失灵。
  `hover` 里只传一个「此刻按没按 Ctrl」的布尔量；
- **鼠标不移动、只按一下 Ctrl 也要立刻吸**：这时不会触发 `pointermove`，所以 `keydown`/`keyup`
  里各补一次重画（`refreshHoverSnap`）。不补的话按了 Ctrl 什么都看不见，得动一下鼠标才出来。

拖动标注时**不**让十字线跟着吸：拖动中「落在哪儿」已经由图形自己的端点表达（端点被吸在
OHLC 上、整条线跟着走），不必再靠十字线提示；而且拖端点时端点可能停在最后一根的右侧
（`offset > 0`），那一段没有 K 线 —— 十字线一吸就会被夹回最后一根、离开端点，看着像坏了。

**右键小菜单**（`ChartPanel.vue`）。在任意价格处右键，弹出「现价 / 买入 / 卖出 / 复制价格」，
最下面还有一项**与价格无关**的「移除 N 个绘图」（v0.8.0）。
**买和卖的单型不让你选，由价格相对现价的方向算出来**（`chart/orders.ts` 的 `orderKindFor`）：

| 右键价格 | 买入 | 卖出 |
|---|---|---|
| 低于现价 | 限价买（等回落到这个价才买） | 止损卖（跌破这个价才卖） |
| 高于现价 | 止损买（涨到这个价才追多） | 限价卖（涨到这个价才卖） |
| 正好等于现价 | 限价买 | 限价卖 |

道理只有一句：**限价单是「等价格过来」，止损单是「价格跑了才追」**。同一个价，买和卖对方向的
要求正好相反，所以两个按钮的单型也正好相反。挂反的后果不是不成交，而是**一挂就成交成市价单**，
菜单里必须算死。菜单顶部会写一行「现价 6484.25 · 低于现价」，就是为了让这一下方向看得见。

```
现价 6484.25            低于现价
买入 1 手 6484.00 限价
卖出 1 手 6484.00 止损
复制价格 6484.00
──────
移除 3 个绘图
```

- 现价 = **游标所在（最后一根已揭示）K 线的收盘价**，不是鼠标下面那根历史 K 线的收盘价：
  单型是按「挂单价相对下单那一刻的市价」定的，而后端的基准永远是游标那根（`placeOrder` 里的
  `currentBar()`）。鼠标可以停在一百根之前的价位上，那不是现在的市价；
- 价格在**打开菜单那一刻**就算好并定死（吸附到 tick）。不能等点击时再按鼠标位置算一遍，
  手一抖价格就变了；
- 「N 手」的 N 就是下单浮窗里的「数量」（`store.orderQuantity`，**只能是正整数**）。
  两处共用一个数，菜单里写多少就是挂多少，省得自己跟自己打架；
- 复制走 `navigator.clipboard`，非安全上下文（`http://` + 非 localhost）退回
  `textarea + execCommand`；成功与否给一句 1.4 秒自消失的轻提示；
- 没有操作权时两个下单项是灰的（点击给提示），复制仍然可用；
- **「移除 N 个绘图」**（v0.8.0）：N 是当前实例的绘图总数（`instance.annotations.length`），
  按下去会一次清空**整块画布** —— 画布属于实例，不区分是谁画的，所以这一项也要操作权，
  没有操作权或者一个绘图都没有时是灰的。

  清空走一条专门的 `annotation_clear`，不是循环发 N 条 `annotation_delete`：那样别人的画布
  会一条条消失、操作记录里也会多出 N 行；一条消息 = 一次状态变化 = 一条 `annotation_cleared`
  广播，所有人同时变空画布。删完 `seqAnn` 不回退，新图形从下一个编号接着发 ——
  否则操作记录里两条「删标注 a3」会指向两个不同的图形。

  这个动作**没有撤销**，所以点击是**两下**：第一下只是把那一行变红、文案改成
  「确认移除 N 个绘图（不可撤销）」，第二下才真发消息。菜单一关就复位（`closeMenu`）。
  发出去之后本地**不做乐观清空**：等后端广播回来才算数，被拒时画布保持原样；同时把
  `pending`（画到一半的预览）、`moving`（正在拖的图形）、`selectedAnnotation` 一起丢掉，
  它们的引用马上就不存在了。

**未平仓的成本线**（`render.ts` 的 `drawPositionLine`）。`position.side !== 'flat'` 时，
在 `position.averagePrice` 处画一条贯穿价格区的横线，左边贴一个标签：

```
多 2 @ 6484.25 · 浮动 +125.00
```

标签写**浮动盈亏**而不是已实现盈亏：仓位没平时已实现盈亏一直是 0，写在成本线上等于什么都没说；
浮动盈亏才是「这条线现在值多少钱」（按游标那根的收盘价算，每点价值换算成美元）。

多头绿、空头红；标签贴左边是因为**右边要留给挂单标签**（挂单也是同一行的矩形块），
两者不会叠在一起。浅色主题下把绿/红各压暗一档（`#15803d` / `#b91c1c`），白底上才看得清。

**成交三角与开平连线**（`chart/trades.ts` + `drawTradeMarks`）。每笔成交留一个三角：
买 = 上三角、卖 = 下三角，尖顶住成交价。已经平掉的仓再连一条虚线，从**那一批开仓成交的三角**
连到**平仓成交的三角**。

配对用 **FIFO 批次**，不是平均成本法：同一方向的开仓各记一批（时间 + 真实成交价 + 数量），
反向成交从最早的批次开始消耗，消耗几批就画几条线。用均价配会同时错两处 ——
2 手分别在 100 和 102 开、再在 105 一起平掉时，线的起点跑到均价 101（不在任何一个三角上），
而且只会画 1 条，看不出是两笔独立的仓位被一起平掉的。

**配对和每批的盈亏都在后端算**（`instance.go: closedLots()`，协议字段 `closedLots`），
返回 `[]ClosedLot`，前端只排版、一处乘法都不做。每一批用**自己的开仓价**算：

```
(平仓价 - 该批开仓价) × 手数 × 方向 × 每点价值
```

⚠️ **不能**把 `applyFill` 那一笔的总盈亏按手数摊给各批（前端曾经就是这么做的，是错的）：
5 笔空单分批开在 7076.14 / 7081 / 7083.25 / 7081.5 / 7082.5（MES，每点 5 美元），
一起在 7079.25 平掉，后端按均价算出这一笔总共 `+40.70`；摊成 5 份后
**5 根线全部显示 `+8.14`** —— 既抹掉了各批开仓价的差别，又把开在平仓价之下、
明明亏 3.11 点的那一笔显示成盈利。按各自开仓价算才是真实的逐笔归因：
`-15.55 / +8.75 / +20.00 / +11.25 / +16.25`，加起来正好 `+40.70`。

**两套口径的分工**：仓位、账户已实现盈亏一律以 `applyFill` 的**平均成本法**为准
（`Position.averagePrice`、`Trade.realizedPnl`、`Instance.realizedPnl` 都不动）；
`closedLots` 只负责「这一批当初在哪个价位开的、这一批赚了多少」。
一笔平仓把**全部**持仓平掉时，两者之和完全相等；只平一部分时会不同 ——
那是平均成本与 FIFO 两种成本法的固有差异，不是算错。

**这两类痕迹画在 Canvas 上，不是标注**：Canvas 没有命中测试，也不进 `annotations`，
所以天然不能选中、拖动、删除（需求要的正是这个）。标注仍然走 SVG 那层。

**字号与时间轴**。正文 13px、整体小字上调一档（10→11、11→12、12→13），
字体栈 `Segoe UI → Inter → 系统 → 苹方 → 雅黑`；画布里的等宽字从 11px 抬到 12px，
价格轴宽度 78→86px、时间轴高度 22→24px 跟着放宽。
时间轴标签改成**完整日期时间** `周五 2026-10-16 09:35`（`formatAxisTime`），
不再"跨天才写日期"—— 复盘跨好几天时，只写 `09:35` 根本分不清是哪天。
标签变长一倍多，所以刻度最小间距从 96px 抬到 180px，贴边画不全的那两个标签直接不画。

### 10.4 市价按钮成对、挂单可拖可撤、平仓线可以「问一笔」（v1.4）

这一版把三件「每次都要回底部面板做」的事搬到了图上，外加一个用来看单笔交易的悬浮卡；
滚轮的分工也在这一版按指针位置改了，那一处写在上一节的缩放列表里。

**市价单拆成两个按钮。** 以前是「市价{n}手」一个按钮 + 上面的买入/卖出下拉；复盘时最常做的
是**反手**（刚市价买完，下一根就要市价卖），共用一个方向意味着每次都得先改下拉 ——
改错方向就是一笔反向仓。现在「市价买入 N 手」「市价卖出 N 手」各写死方向，一步到位。
限价/止损仍然用下拉（那两个要填价格，本来就得在这个框里操作）。

**拖挂单线改价。** 挂单是 Canvas 画的（`drawOrders`），没有 DOM 可以命中，所以拾取自己做：
指针与某条挂单线的 y 距离 ≤ `ORDER_HIT_PX = 6` 就算按到了（取**最近**的一条，不是数组里最后一条）。
按下后进入 `drag.mode = 'order'`：

- 拖动过程中只改**本机**的 `orderDrag`（画布按这个价格画、标签临时带上价格）；
  每动 1px 就发一条 WS 的话，多人演示时别人看到的线会一路抖；
- 松手才发 `order_modify`，价格吸附到 tick（和十字光标、右键菜单同一把尺子）；
- 价格没变就不发 —— 点一下不该在操作记录里留一条「6484.00 → 6484.00」。

后端 `Instance.moveOrder` **只改价格**：单型、数量、编号、下单时间全都不动。拖过现价就自动
换单型会让订单在用户手里悄悄变性质（「跌破 95 才卖」的止损单往上拖过现价，会变成
「涨到 105 才卖」的限价单），而他以为自己只是挪了条线。想换单型就撤了重挂。
已成交/已撤销的单也不能改（改了不会再参与撮合，只会让历史对不上）。

**每张挂单一个「×」。** 是 **HTML 按钮**叠在画布上，不是画出来的：hover 反馈、`title`、
禁用态都是浏览器白送的。位置仍然由 `ChartScale.yOf` 算，和那条线严格对齐；横向让在挂单标签
右边 —— 画布绘制标签时用 `ORDER_RESERVE_RIGHT = 24` 让出了这块地方，两边共用一个常数。
`pointerdown.stop` 必须有，否则按下会冒到画布，顺手把视图也拖一下。

**平仓线的悬浮卡**（`TradeTipCard.vue`）。鼠标停在「开仓 → 平仓」的虚线上时弹出，
内容是需求里的六项：方向、手数（标题里）、开仓价、平仓价、持仓时长、已实现盈亏。

```
多 2 手  平仓
开仓价      30846.25
平仓价      30748.00
持仓时长    2小时15分钟
已实现盈亏   −196.50
停 3 秒不动可固定到画布
```

几个关键决定：

- **命中用「点到线段的距离 ≤ 6px」**（`distanceToSegment`，投影参数夹到 `[0,1]`，
  所以线段两端之外不会延伸出一条看不见的命中带）。6px 是折中：3px 以下要瞄准才碰得到，
  10px 以上“从旁边经过”就会弹卡挡 K 线，几条线挨着时还分不清指的是哪条。
- **跟随卡 `pointer-events: none`**：卡片一旦能接指针，鼠标「停在卡片上」就不再落在虚线上，
  「移出就销毁」永远触发不了。销毁点有三处：指针离开这条线、离开画布、按下鼠标（要开始拖了）。
- **3 秒不动 → 固定**。计时从**最后一次移动**算起，每动一次就重置（`armPinTimer`）。
  固定的那一刻，卡片的位置取它**当前渲染的位置**，而不是鼠标位置 —— 否则会从右下角瞬移到左上角。
- **钉住之后可以拖、可以关**：拖动改的是卡片的 `left/top`（夹在画布内），
  `pointerdown.stop` 拦住画布的平移；右上角「×」关闭。`Esc` 也会收掉它。
- 同一时间只允许一张卡：钉住之后不再出跟随卡（否则屏幕上两张卡说同一件事）。

### 10.5 下单浮窗：把「下单」从底部搬出来（v0.8.0）

底部那条 Tab 条把画布让出来了，但「下单」这一列很尴尬：**它是要反复点的那块**。
收起来就得展开再找输入框，不收就常驻吃掉 200px 高度。所以这一版把这一列**单独提出来**，
做成浮在页面上的窗（`TradeFloat.vue`），持仓、挂单、成交流水仍然留在底部 Tab。

**位置只有一份**（`pos`，视口像素的左上角），展开态和折叠态共用它：

```
展开                                    折叠
┌──────────────┐                        ╭────╮
│ 下单  现价 …  │ ← 标题栏是把手          │下单│ ← 44px 图标，整枚都是把手
│ 买入▾ 限价▾  │                         ╰────╯
│ 价格   数量  │                         （左上角还是原来那个点）
│ 挂单         │
│ 市价买/卖    │
└──────────────┘
```

- 折叠只是把盒子缩小，**锚点不动** —— 于是「拖到角落 → 折叠 → 展开」不会跑到别处去；
  反过来拖动小图标，展开时面板就从那个角落长出来。两套位置各存一份的写法会出现
  「折叠在右下、展开又跳回左上」，所以不这么做；
- **拖动只发生在标题栏 / 小图标上**（内容是输入框，按住就拖会毁掉填价格的体验）。
  `pointerdown` 里 `preventDefault()` + `stopPropagation()`：不拦的话一按就开始框选文字、
  输入框还会抢焦点。位移（`|dx|+|dy|`）≤ 5px 当**单击**，折叠态下「按下 → 松手」就是展开，
  不用再放一个按钮；
- 拖动基准是「按下那一刻的指针 + 当时的位置」（`dragFrom`），每帧都用同一个基准重算绝对位置，
  所以不会漂；宽度在拖动期间是定死的（`expanded ? 276 : 44`），`offsetWidth` 不会来回变；
- **永远夹在视口里**（`clampPos`）：拖动、展开、窗口 `resize` 各夹一次。半截露在屏幕外的
  浮窗是找不回来的 —— 尤其缩成只剩一个图标的时候。高度用实测的 `offsetHeight`，
  首帧量不到才退回估算值；
- **位置记在 `localStorage`**（`tv-trade-float-pos`），刷新页面还在原处；只记位置，不记
  折叠状态 —— 每次打开都是展开的，省得「那个框怎么不见了」；
- 首次出现的默认位置是**左上**（`x=16, y=112`），不让它默认压住右边：价格轴、挂单线标签、
  平仓信息卡都长在那儿；
- 价格/方向/单型和以前那一列完全一样：换实例回到现价、行情往前走而用户没手改过就跟着现价。
  「数量」仍用 `store.orderQuantity` —— 右键菜单也在用它，只能有一个数。
- 组件挂在 `ReplayView.vue` 里，`position: fixed` + `z-[45]`：压住画布里的右键菜单（`z-40`）
  和平仓信息卡（`z-30`），但**让错误提示（`z-50`）盖得住它** —— 报错比浮窗重要。
  它不参与外面的 flex 布局；没有进入实例时整个不渲染（没东西可下单）。

## 11. 交易记录与回放（v0.11.0 起，v0.18.0 改成自动）

### 11.1 录的是事件流，不是视频

需求原话就是「录制内容非视频」。所以录下来的是**起始盘面 + 之后每一条操作广播**：
一次复盘里真正有价值的不是像素，而是「第几步、谁、做了什么」。视频既占地方又搜不动，
而事件流可以逐帧跳、可以单步、还能直接拿去做回归测试。

**v0.18.0 起它叫「交易记录」，而且没有开关。** 录的仍然是同一份事件流，变的是
「什么时候开、什么时候关」：以前要用户点一下【● 录制】，现在只看仓位 ——
空仓变成有仓的那一刻自动开始，回到空仓的那一刻自动收尾（见 11.2）。

录制的挂点只有一处 —— `hub.broadcastInstanceLocked` 的末尾：

```go
// 广播已经发出去之后：收尾判定要看「这一步做完之后」的仓位
h.trackTradeLocked(inst, action, payload, by)
```

为什么不散在各个 `do*Locked` 里：那样每加一个动作就要记得补一行，**迟早会漏**，
而漏掉的动作在回放里表现成「画面少了一步」，很难发现。挂在唯一出口上，
新增动作天然被录。

这条决定的三个直接后果：

- **机器人操作天然被录**，因为机器人走的也是 `h.doStepLocked` → `broadcastInstanceLocked`。
  需求第 6 条「验证前端用户操作与后端机器人操作完全等价」因此不是额外功能，是位置选对了的结果（见 11.8）。
- **录下来的 payload 就是广播出去的那份原文**（存成 `json.RawMessage`）。回放时喂给同一个
  reducer，画面必然一致 —— 不是两处实现「写得像」，是同一条数据。
- **文件小**：一份 12 步的记录 `recording.json` 是几 KB，同长度视频是几十 MB。

`recordableAction` 只放行**改盘面**的九种动作：`bar_advanced`、标注四类、订单四类。
操作权变化、成员进出、机器人启停、语音广播都不走这条「一条广播 → 一步」的路 ——
它们不是「画面上发生了什么」，录进去只会让第 3 步里莫名多出一条「谁拿到了操作权」。
（语音另有一步，但那是记录器自己开的，见 11.3。）

### 11.2 什么时候开始、什么时候结束、第 1 步是什么

> **v0.18.0 改了口径。** v0.11–v0.17 里「开始/结束」是两个用户动作（`record_start` /
> `record_stop`）。忘开就没有记录、忘关就会把一大段无关操作录进来 —— 这两个问题在
> 自动触发之后都不存在了。现在**结束条件只看仓位**，`record_start` / `record_stop`
> 只回一句「已经改为自动」。

开始的条件（三条缺一不可，见 `trade.captureTradeBaseLocked`）：

| 条件 | 为什么 |
|---|---|
| 这个实例还没有在进行中的记录 | 一笔交易只有一条记录 |
| 当前是**空仓** | 有仓的时候不可能「开始一笔新交易」 |
| 这一条广播**改动了仓位**（`order_filled`，或 `bar_advanced` 的 `Fills` 非空） | 只有这两种动作能把空仓变成有仓 |

结束的条件只有一条：**这一条广播之后仓位归零**。不看到底是谁平的、是不是同一根 K 线，
也不看操作者是否还连着 —— 仓位没了，这笔交易就结束了。

**第 1 步 = 开仓成交之前那一屏。** 开仓本身是一条广播（成交），如果等成交之后才开始记，
`Base` 里就已经带着仓位，回放的第一帧就是「已经进场了」，入场那一下永远看不到。所以
hub 在**可能开仓的操作之前**先抓一份盘面快照：

```go
// doStepLocked：只有真的挂着单才抓（没有挂单就不可能有成交，省下一次几百根 K 线的拷贝）
if openOrderCount(inst) > 0 { h.captureTradeBaseLocked(inst) }
// doMarketOrderLocked：市价单一定会成交，而这一笔很可能就是开仓
h.captureTradeBaseLocked(inst)
```

快照挂在 `inst.pendingBase` 上，由**紧随其后的那条广播**消费掉。它是「每次可能开仓的
操作都重抓一遍」的：这次没成交、下一次才成交，第 1 步必须停在真正入场前的那一屏，
否则回放会从几根之前开始演，步数和盘面对不上（操作失败时 `do*` 会把它清掉）。

于是步序表长这样（一笔市价开、市价平的交易）：

| 步 | Kind | 是什么 |
|---|---|---|
| 1 | `base` | 开仓**之前**那一屏（空仓，但已经有你画的图形、挂的单） |
| 2 | `order_filled` | 开仓成交 —— 回放从这里才看到仓位 |
| 3… | 各动作 | 换根 / 画图 / 下单 / 语音，一条广播一步 |
| N | `order_filled` | 平仓成交（**先记进来，再收尾**，所以最后一笔不会掉在记录外面） |

**同一根 K 线内开平（日内往返）也会留下一条完整记录**：3 步，`BarsHeld = 0`，
`MFE = MAE = 0`（一根 K 线只有 OHLC，看不出高低点谁先来）。

> **v0.15.0 的旧口径**仍然有效：v0.11–v0.14 的「一步」是**一根 K 线**，一根 K 线上画的三个
> 图形、挂的两张单、讲的一段话全塞在同一步里，回放时一次性摆出来。现在**一条放行的广播 = 一步**。

**第 1 步**把已揭示的 K 线（到游标为止）、标注、挂单、成交、`closedLots`、持仓、
已实现/浮动盈亏深拷进 `RecordingBase`（`trade.tradeBase`）。

之后**每一条放行的广播开一步**（`tradeRecorder.observe` → `push`），所以：

| 用户做了什么 | 广播 | 录成 |
|---|---|---|
| 点【下一根】 | `bar_advanced`（撮合结果在同一条的 `fills` 里） | 1 步 |
| 画完一个图形（定稿那一下） | `annotation_added` | 1 步 |
| 拖动图形 / 拖端点（松手才提交） | `annotation_moved` | 1 步 |
| 挂单 / 改价 / 撤单 / 市价成交 | 各自一条 | 各 1 步 |
| 说一段话 | 无（语音不走广播那一条路） | 1 步（不改盘面） |
| 机器人做一次同样的事 | 同一条 `do*` → 同一条广播 | 1 步 |

**为什么 1:1 是安全的**：每个手势本来就只产生一条广播（画图在定稿时才发、拖挂单松手才提交、
点【下一根】时撮合结果就带在同一条 payload 的 `Fills` 里），所以不存在「动作做了一半被切成
两步」的中间态；而每条 payload 都带全量 `orders/trades/position`，任意一步都是自洽快照，
不会出现「K 线已经出来、成交还没更新」的半帧。

每一步的结构：

```go
RecordingStep{
    Step   int         // 1 起的步号（连续）
    At     int64       // 真实时刻（Unix 毫秒）——同一秒里连画两个图形很常见
    Kind   string      // base / 动作名 / recording_audio（语音步）
    By     string      // human / bot / system
    Time   string      // 这一步发生时**当前那根 K 线**的明文时间（盘面锚点）
    Cursor int         // 这一步之后的游标（跳步自检）
    Audio  *AudioClip  // 仅语音步
    Events []RecordingEvent // 通常 1 条；起点和语音步是空数组
}
```

几条硬约定：

- **步号 = `len(rec.Steps)`，由服务端数**。前端只显示，不自己数 —— 两边各数一份就会出现
  「界面写 12 步、文件里只有 11 段」。v0.18.0 起 `event.recStep` 也删了：交易记录自动进行，
  界面上没有「现在第几步」要显示（见 [11.5](#115-交易记录-tab)）。
- **`Bars`（推进了几根 K 线）和 `StepCount`（几步）是两个数**。一根 K 线可能十几步，
  列表里两个都显示（`12 步 / 3 根`）。
- **清空语音会摘掉那几步并重排步号**（`tradeRecorder.renumber`）：记录还没定稿、
  外部没引用过步号，重排是安全的；不重排的话回放会走过一串「什么都不发生」的空步。
- **协议里的数组字段必须是数组，不能是 `null`。** Go 的 nil slice 会序列化成 `null`，
  而起点和语音步天然没有事件。前端步进条直接读 `s.events.length`，`null` 会让「打开回放」
  当场抛 TypeError —— 实测症状是**顶栏已经进了回放态、整个播放器却渲染不出来**，看着像卡死。
  所以 `Steps[].Events` 和 `Audios` 在创建时就显式给空切片，`recording_test.go` 里有一条
  断言钉住 JSON 里出现 `"events":[]`。
- **格式升版、不迁移**：`Recording.Format` 从 1 升到 2，`scan` 跳过旧格式并打一句日志，
  `Load` 遇到旧格式明确报错（需求原话：旧录像不必保留）。硬读旧文件会让步进条显示成
  「一步蹦出一整根 K 线变化」的怪物，比报错更难排查。v0.18.0 **只加字段不加版本**：
  `stats` / `instanceId` 都可缺省，缺统计的老文件在读取时按事件流反推（`deriveStats`，
  和实时路径共用同一个 tracker，所以两种来源口径天然一致）。

于是回放的定义只有一句：**深拷 `base`，然后按步依次把每条事件喂给 `applyInstanceEvent`。**
一步一个操作之后，「单步」就等于「回到用户的下一次动手」。

### 11.3 语音步：自己占一步，按 K 线时间挂载，每根最多 9 条

交互是「**按一下空格开始、再按一下结束**」（v0.11.1 从「按住」改过来的：讲一根 K 线常常
要说十几秒，一直按着空格手是酸的，也没法用空格做别的）。

> **v0.16.0 起这一节讲的是「交易记录里的那一份」**：语音讲解已经提升为一级功能
> （空仓也能录），入口、权限、存储、兼容都在 [11.9](#119-语音讲解从录制里解耦v0160)。
> 本节剩下的内容仍然成立 —— 持仓期间录的语音照样按 K 线时间挂载、自己占一步、每根最多 9 条。

**开始**分两步（v0.12.0）：`keydown` 只记「空格已按下」（`armed`），**`keyup` 之后再等
`START_DELAY_MS = 90ms` 才 `getUserMedia`**。原来按下就开麦，麦克风比手指快，机械键盘
抬起时那声「咔」稳稳地顶在每段录音的开头。`keydown` 里绝不碰麦克风 —— 这是这段交互的
唯一硬约束，谁把它挪回去，录出来的开头就又脏了。

**结束**仍然是 `keydown`（正在录时按下即停）：抬手前那一下咔哒声本来也会被录进去，
早一帧停少半帧噪音。`window.blur` 时兜底停一次，并把「等 90ms 开麦」那一步一起撤掉
（切窗口会丢 keyup，麦克风指示灯一直亮着很吓人；在后台偷偷开麦更糟）。

麦克风设备在录制浮层的下拉里显式列出（`enumerateDevices` 的 `audioinput`，选择记在
`localStorage` 的 `tv-replay-mic`）。不申请权限就列不出设备名，所以**只有真的进入录制状态
才申请权限** —— 一打开页面就弹授权框是很烦的。

**波形**分两种，都是「响度包络」而不是逐点示波器（96 个桶足够看出哪里在说话、哪里是静音，
一行 200px 宽的地方画 16000 个采样只会得到一片黑）：

| 什么时候 | 数据从哪来 | 画在哪 |
|---|---|---|
| 正在录 | `AnalyserNode.getFloatTimeDomainData`，每帧取窗内峰值，攒 150 个电平从右往左滚 | 浮层里的 `<canvas>`（`ClipRecorder.readWave()`） |
| 录完之后 / 回放时 | `GET /api/recordings/<id>/audio/<file>` 取回来 `decodeAudioData`，分桶取峰值 | `<AudioWave>` 组件（SVG 路径），按 URL 缓存在 `audio/waveform.ts` |

为什么不把录完的波形跟着消息一起传上来：回放端本来就只有 URL（音频不进 JSON），
两条路各写一份迟早会不一致；服务端算又得给 Go 加一条解码链，与「零第三方依赖」冲突。
「取回来解码一次」是唯一两边都能用的算法。

**清空本根**（`record_audio_delete`）：删掉**当前这根 K 线**上的全部录音，连磁盘上的
`audio-N.wav` 一起删，并且**把那几步一起摘掉、步号重排**（`recorder.clearAudioOfBar` +
`renumber`）。范围按 K 线而不是按步：一根 K 线上可能已经分几步录了好几段，说错了
要重来不该只清最后一段。两段式确认（第一下变红写「确认清空」，第二下才真删），
和删录像、删绘图的理由一样。

**试听**用 `<audio>` 打 `/api/recordings/<id>/audio/<file>` —— 录制中也能听，因为音频已经
落地了（见 11.4）。播不了只可能是两件事：浏览器拦了自动播放（`NotAllowedError`，真实点击
通常不会），或者文件刚被清掉（`onerror`）。两种都给一句明确的提示，不静默失败。

**录制浮窗是 `fixed` 的浮窗**（v0.12.0，之前是贴画布左上角的 `absolute` + 「折成一行」）。
和下单浮窗共用同一套交互与同一套夹边逻辑：拖标题栏换位置、位移 > 5px 才算拖动、
折叠成 44px 的圆形小图标（整枚都是把手，没拖动 = 单击展开）、位置存 `localStorage`
（`tv-record-hud-pos`）、每次移动/展开/窗口缩放都夹回视口。

两个硬要求：

1. **z 必须比下单浮窗高**：下单浮窗是 `z-[45]`，录制浮窗 `z-[60]`（实测 `z-50` 还压不住，
   `elementFromPoint` 拿到的仍是浮窗）。不然点不到录制浮窗里的按钮。
2. **默认位置要错开**：下单浮窗在 (16,112)、宽 276，录制浮窗默认 (300,112)、宽 268 ——
   首次出现就并排，不用先拖一次。不用「录制时自动隐藏下单浮窗」是因为录模拟交易恰恰要用它。

画布容器之外的 `fixed` 不会被 `absolute` 的父级裁掉，所以浮窗可以拖到任何角落（包括顶栏上）。

采到的音频要变成 WAV 才能落盘（`audio/mic.ts` 的 `ClipRecorder`）：

```
MediaRecorder(webm/opus) → AudioContext.decodeAudioData → 线性插值重采样到 16kHz
  → Int16 单声道 PCM → 手写 44 字节 RIFF 头 → base64 → WS 上行
```

为什么不用 webm 原样存：16kHz / 16bit / 单声道是 32KB/s，一句 20 秒的讲解才 640KB，
而且 `.wav` 双击就能放；opus 还得让用户装个播放器。

**存储键是那根 K 线的明文时间**（`step.Time`），不是下标 —— 和 CSV 的 `time` 列、
标注的锚点、挂单的时间是同一套字符串。下标在「录像换了实例重放」或「补齐 K 线」之后
就不可靠了，时间字符串不会。

两道硬上限，都在 `addAudio` 里校验（前端也会置灰，但后端不能信前端）：

| 上限 | 值 | 为什么是这个数 |
|---|---|---|
| **每根 K 线**条数 | `maxAudiosPerBar = 9` | 「防止用户在**同一根 K 线**上反复重录」——所以是按 K 线数，不是按步数、也不是按整条录像。换到下一根额度重新从 0 开始，**整条录像的录音总数不限**。计数器是 `clipsOfBar(time)` 现数的，不是累加变量，清空之后额度自然回来。<br>v0.15.0 之前叫 `maxAudiosPerStep` 且按步数：那时一步恰好等于一根 K 线，两个口径相同；一操作一步之后必须按 K 线时间数，否则「画了三个图形再录音」会因为多走了几步而莫名其妙少几条额度 |
| 单条字节 | `maxAudioBytes = 2 << 20`（约 64 秒） | 录音走 WS 上行，`ws.go` 的 `maxFramePayload` 是 **4MB**，base64 膨胀三分之一 → 2MB 变 2.67MB 还有余量。再大就会在**发送端**被帧上限掐断，症状是「录音一停连接就断」，极难排查 |

还有一道格式校验：文件头必须是 `RIFF` + `WAVE`。这段音频之后会用 `audio/wav` 发给浏览器，
收一个任意二进制进来，等于开了一个内容不明的本地文件服务。`durationMs` 没给就按
`(字节数-44)/32` 反算。

### 11.4 落盘：`recordings/`

```
recordings/                          ← replayRecordingDir（-- 相对 exe 所在目录）
  recordings.json                    索引：版本、保存时间、记录摘要清单
  rec-20261016-094512/               一笔交易一个文件夹
    recording.json                   format(=2) + base + steps + stats
    audio-1.wav                      语音（16kHz 单声道 PCM）
    audio-2.wav
```

**这个目录和实例存档（`<stateDir>/instances/<id>/`）之间没有任何引用。** 删实例不删记录、
删记录不动实例，两边各自完整 —— 见 [11.12](#1112-记录独立于实例边界行为全写在这里)。

几个刻意的取舍：

- **语音在录的当下就写**，`recording.json` 才是提交点。开仓开始记录时就 `MarkLive` 建好目录
  并登记，之后每说一条立刻写 `audio-N.wav` —— 语音浮窗的试听走的是
  `GET /api/recordings/<id>/audio/<file>`，而 HTTP 只认磁盘。所以 `AudioFile` 的两道门是
  「id 在索引里**或**正在记录中」；收尾时 `Save` 只补写 `recording.json` + 更新索引，
  顺手删掉没人引用的 `audio-*.wav`（清空本根删过、或者上次留下的残留）。
  保存失败会把整个目录 `Drop` 掉：没有 `recording.json` 的文件夹在列表里看不见，
  留着只是谁也认不出来的垃圾。
- **写盘在锁外**。收尾只把「待保存」塞进 `hub.pendingSaves`，`Handle` / `Unregister` /
  `Close` 的 defer **解锁之后**才真写。写盘是 IO，拿着 `h.mu` 做会把所有人的步进和广播一起卡住。
- **四种收尾**：平仓（仓位归零，正常路径）、删实例（`deleteLocked`）、进程退出（`Close` 遍历
  所有实例）、以及崩溃后重启（那一条留在磁盘上的检查点，见 [11.13](#1113-检查点持仓中的记录每-2-秒写一次)）。
  前三种都走 `finishTradeLocked`，`Stats.Closed` 按当时仓位如实写。
- **索引不是唯一真相**。`OpenRecordingStore` 会 `scan()` 扫一遍目录，把带 `recording.json`
  的文件夹收回索引 —— 索引坏了、被删了，记录文件本身还在就能捞回来。
- **音频走 HTTP，不走 WS**：播放时 `GET /api/recordings/<id>/audio/<file>`，
  带 `Cache-Control: private, max-age=3600`。路径要过两道门：id 必须在索引里，
  文件名必须匹配 `audio-N.wav` **且** `filepath.Base(name) == name`（挡 `../` 穿越）。
- **列表走内存索引、回放才读整份文件**。`recording.json` 里带着几百根 K 线，
  列表页没必要每次都读一遍。

### 11.5 交易记录 Tab

底部第三个 Tab 从【回放】改名【交易记录】（v0.18.0）：它本来就不是「录像」，
内容是一笔交易从开仓到平仓之间的全部操作，而且是自动产生的 —— 列表里没有「开始/停止」，
只有一个【刷新】。

列表每行**先给结论、再给过程**：

| 位置 | 内容 |
|---|---|
| 第一行 | 名称（`标的 · 多2 手 · +2.00 · 入场时间 → 出场时间`）、`N 步 / M 根`、语音数、`持仓中` 标记 |
| 第二行 | 方向手数、**盈亏**（赚红亏绿，国内习惯）、`MFE / MAE`、进出场价、`持仓 N 根 · M 次成交` |
| 第三行 | 标的、起止区间、操作数、文件大小、创建时间、创建者 |

删除是**两段式**（第一下变红写明「不可撤销」，第二下才真删）—— 和「移除 N 个绘图」
同一个理由。

点开一条就进播放器：

| 控制 | 行为 |
|---|---|
| ▶ / ⏸ | 连续播放。**时长按步骤类型给**（`STEP_MS`：换 K 线 900ms、画图 550ms、下单 650ms、起点 1200ms），1x / 2x / 4x 按整除缩短。一步一根 K 线的时候每步信息量差不多，现在一步一个操作，「换根」要看清 K 线形状、「画图」只要看清线出现 —— 用同一个时长要么看不清、要么像卡住 |
| ◀ / ▶\| | 单步后退 / 前进（播放中按会先暂停） |
| ⟲ 重播 | 回到第 1 步再从头播 |
| 步进条 | 每步一个方块（一步 = 一次操作），点一下就跳到那一步。**按类型上色**（下一根=蓝 / 画图=绿 / 下单成交=紫 / 语音=琥珀 / 入场前=灰），**换 K 线处留一道空隙**，否则几百格同样的小方块看不出结构。有语音的那一步还带一个琥珀色小点 |
| 本步语音 | 步进条**下面**一行：当前这一步的语音 chip（▶ + 波形 + 时长），**点一下播**，再点停。语音自己占一步，所以这里通常只有 1 条。橙点只说"有语音"，要听哪条得在这里点 |
| 自动放语音 | 播到语音那一步时先把它放完再继续步进（**按步对齐**：不按 K 线时间过滤，否则一根 K 线上「画图 → 语音 → 画图」三步会把同一段语音重复放三遍） |
| 空格逐条 | 连续播放中按空格 = **切到逐条**（先把自动步进停掉，不然讲解会被下一步盖掉），再按就是下一条；当前步没有语音时返回 false，空格交给别的处理（播放/暂停） |

播放期间画布是**只读**的（见 11.6），顶栏显示「回放中 · 记录名 · 第 N/M 步」和一个【退出回放】。

### 11.6 回放是只读的

回放没有真实实例 —— 画面是从 `rec.base` 推出来的，本地算的。所以任何上行操作在回放期间
既没有意义，也会串到「当前 join 的那个实例」上去。四道闸：

- `canOperate` 加上 `&& !playbackActive`：所有上行按钮的禁用都挂在它上面（改一处即全局生效）；
- 下单浮窗整个不渲染（`v-if="!store.playbackActive"`）—— 回放里挂单毫无意义；
- 工具栏的「接管」「启动机器人」一并禁用；
- `ChartPanel` 的 `Delete` / `Backspace` 删标注也要过 `store.canOperate`。

另外两个坑：

- `resync()`（断线重连）在回放时**不 join `rec:xxx`** —— 回放没有真实例，硬 join 会收到
  一条错误并把画面清空。
- 退出回放时 `playback.close(restore = true)` 会重新 join 真实实例；但**切换实例**前要
  `close(false)`，否则会先 join 旧实例、再 join 新的，中间闪一下错的盘面。

### 11.7 一份 reducer，两个消费者

`stores/instance-reducer.ts` 导出一个纯函数：

```ts
applyInstanceEvent(inst: InstanceDetail, action: string, payload: unknown): void
```

它就地改盘面：`bar_advanced` 追加 K 线并更新游标/持仓/盈亏，标注增删改、订单挂/撤/成交
各一段。两个消费者：

| 场景 | 谁调 | 数据从哪来 |
|---|---|---|
| 实时 | `replay.ts` 的 `applyEvent` | WS 推来的 `EventMsg` |
| 回放 | `playback.ts` 的 `buildState(rec, upto)` | 深拷 `rec.base`，再依次喂 `steps` 里的事件 |

这是「回放画面和当时完全一致」的**结构性保证**，不是靠两处实现写得像。共用之后，
加第六种绘图工具只需要改一处，回放自动跟上。

两个实现细节值得记下来：

- **深拷不能用 `structuredClone`**：Pinia 的 state 是 Proxy，`structuredClone` 会抛
  `DataCloneError`。用 `JSON.parse(JSON.stringify(...))`。
- 语音那两条 action（`voice_added` / `voice_cleared`）在 reducer 里**直接 return**：
  语音不是「一条广播改一块盘面」，回放时它只从记录里的语音步来（见 11.9）。
- v0.18.0 删掉的 `recording_started/stopped/audio/audio_cleared` 本来也是直接 return 的
  （它们改的是浮层，不是盘面）；浮层都没了，这几条自然也不存在了。

### 11.8 机器人等价性怎么验的

需求第 6 条要「验证前端用户操作与后端机器人操作完全等价」。`recording_test.go` 的
`TestTradeRecordingIsAutomatic` 就是这条的答案（机器人那半边由 `botTickProbeLocked` 驱动，
它走的是和真人一模一样的 `do*Locked`）：

1. 空仓时先画一条射线、步进一次（证明这些**不会**产生记录）；
2. 市价买入 2 手 → 记录自动开始，第 1 步是**开仓之前**那一屏；
3. 持仓中画一条、说一段、再换一根（这一根是唯一能算 MFE/MAE 的整根 K 线）；
4. 市价平掉 → 记录自动收尾，收到 `trade_recorded`；

然后断言：步序表（`base / order_filled / annotation_added(bot) / bar_advanced(bot) /
annotation_added / recording_audio / bar_advanced / order_filled`）、
统计（方向手数、进出场价、盈亏、MFE/MAE、持仓根数、`closed`）、`recording.json` 和
`audio-1.wav` 真的在目录里、列表和详情能读回来、HTTP 取音频 200 + `audio/wav`、
`../` 穿越被挡、删除后目录消失且**实例毫发无损**。

最后一步最关键：**把记录从头重放成一个新实例，和当时那个真实实例逐项比对**
（游标、K 线、标注、挂单、成交、持仓、已实现/浮动盈亏）。这一条过了，
「录下来的东西足以复现当时画面」才算成立。

### 11.9 语音讲解：从录制里解耦（v0.16.0）

v0.11 – v0.15 里录音是录制的**子能力**：`handleRecordAudio` 第一句就是「现在没有在录制」，
麦克风、波形、试听、清空全塞在只在 `isRecording` 时存在的浮窗里。于是一个只想
「在这根 K 线上讲两句」的人被迫先开一段录像，录完还多出一条不值钱的录像。

v0.16.0 把语音提升为**和「绘制图形」同级的一级功能**。四件事各归各位：

| | 归属 | 说明 |
|---|---|---|
| 能力 | **实例**（`voice.go` 的 `voiceStore`） | 和标注、挂单同级：随时能录，不依赖录制 |
| 入口 | 工具条的【🎙 录音】 | 和五种绘图工具排在同一行；再点一下收起（= 放下麦克风） |
| 状态 | `VoiceState`（快照 / `bar_advanced` / 语音广播） | 服务端数的「本根 x/9、共 N 条」，界面只显示 |
| 下游 | 录制 | 录制期间录的那几条**额外抄一份**进录像，回放到那一步语音响 |

**功能入口**。工具条上【🎙 录音】与【趋势线】【射线】【矩形】…并排，点开是一个可拖、
可折叠的浮窗（`VoiceFloat.vue`）：麦克风选择、实时波形、`空格` 开始/结束、本根清单
（波形 + 时长 + ▶）、一键清空本根，外加一份「其他 K 线还有 N 条」的折叠清单。
（v0.17.0 起，同一份语音在**时间横轴下方**还有一条按 K 线排开的录音条，见 [11.10](#1110-时间横轴下方的录音条v0170)；
浮窗负责「录和本根」，录音条负责「按时间轴听全部」。）
空格只在浮窗打开时被捕获 —— 收起浮窗就等于放下麦克风，空格回到原来的含义。

**状态与权限**。和绘图同一条口径：**要操作权、不能在回放里**（`store.canVoice`，
服务端 `requireOperatorLocked` 再挡一次）。唯一的差别是**入口对所有人开放**：
观众也要能听讲解，所以【🎙 录音】按钮不看操作权，只有「往上加一段」这个动作看 ——
浮窗里会写明「现在是观看状态，只能听、不能录」。操作权被交还、机器人接管、换实例时，
正在进行的录音会被取消（麦克风必须松开，录了也发不出去）。

**存储与调用关系**。语音是**实例存档**的一部分：

```
state/instances/<实例 id>/voice.json         元数据：[]AudioClip（id / time / 时长 / 文件 / 谁录的）
state/instances/<实例 id>/voice/voice-N.wav  音频（16kHz / 16bit / 单声道，32KB/s）
```

取用走 `GET /api/instances/<实例 id>/voice/<voice-N.wav>`（和录像的
`/api/recordings/<id>/audio/<file>` 并列，不复用）。调用链是：

```
VoiceFloat → voice_add(AudioData=base64 WAV)
  → handleVoiceAdd → requireOperatorLocked
    → addVoiceLocked
        ├─ inst.voiceNotes().add(...)        盘面那一份（唯一真相，写 voice/）
        └─ inst.rec.addAudio(...)            仅在录制中：录像那一份（写 recordings/<id>/audio-N.wav）+ 开一步
  → broadcastInstanceLocked(voice_added)     带 VoiceState + VoiceAll + RecordingState
```

**为什么音频存两份**：录像要能单独拷走、单独删除，实例也是。一份共用路径会让
「删了实例，旧录像里的语音还能不能放」变成一个要猜的问题；同一条 30 秒的讲解约 1MB，
两份换两边都能独立存活，值。

**兼容处理**。老的 `record_audio` / `record_audio_delete` 一条都没删，但它们变成
**薄别名**：语义仍然是「必须在录制中」，实现改走同一条 `addVoiceLocked` /
`clearVoiceOfBarLocked`，广播仍用旧动作名 `recording_audio`（负载额外带上 `voice` /
`voiceAll`）。所以：

- 老前端、外部脚本：报文、错误文案、步号、`state.barAudios` 全都不变；
- 录像格式还是 `format = 2`，录音步仍然是一个 `recording_audio` 步（`Events` 为空、
  `Audio` 挂在步上），**旧录像照旧能放**，播放器一行没改；
- 「每根 9 条」这条约束挪到了 `voice.go`（`maxClipsPerBar`），录制器的
  `maxAudiosPerBar` 变成它的别名 —— 一个数，两处引用，不会再出现
  「录制中 9 条、不录制 12 条」这种两套口径；
- 清空是同一个动作的两个落点：盘面清单和录像里那几步一起摘（步号重排），
  不会出现「界面上空了、回放到这根还在说话」。

一条**语义上的取舍**要写明：录制**之前**录的语音不会进这条录像（它已经属于盘面了）。
录像仍然是「从点录制那一刻起的自包含快照」，不会因为盘面上有更早的语音而变得不可复现。

### 11.10 时间横轴下方的录音条（v0.17.0）

11.9 之后语音是**盘面数据**了，但界面上的两个入口都只能回答「当前这根」：
浮窗列本根、工具条显示 `3/9`，而「这块盘面上一共讲过哪些根、各在哪」没有视图。
复盘只能往前走、不能倒回，早先几根的语音一划出视野就再也找不到 —— 11.9 给的补丁是
浮窗里那份「其他 K 线还有 N 条」的清单，但它只说时间，人还得自己在图上找 09:45 在哪。

v0.17.0 把这份清单摆回它本来该在的地方：**时间横轴正下方**，一条 40px 高的录音条。

**布局**。整条只有三块，横向边界和行情区**逐像素对齐**：

```
┌──────────────────────────────────────────────────────────┬─────────┐
│  ────●────────●──●──────────  轨道（左 10px → 价格轴左沿）│ 🎙 3 条 │
│                                                          │ ▶ 连播  │
└──────────────────────────────────────────────────────────┴─────────┘
   ↑ 与 plot.left 对齐                          ↑ 与 PRICE_AXIS_WIDTH(86px) 同宽
```

- **轨道**：`left: plot.left`、`right: PRICE_AXIS_WIDTH` —— 和画布上行情区的左右边完全相同；
- **右端一列**：和价格轴同宽（86px），视觉上接着价格轴往下，放「🎙 n 条」（点一下开语音浮窗）
  和【▶ 连播】；
- **高 40px**：一个 20px 高的标记居中骑在一条极淡的基线上，上下各留 10px；
- 高度是**固定**的（没有「有语音才出现」）：一会儿出现一会儿消失会让画布跟着跳，
  录音时看得见的那一下最刺眼。回放时也在，只是清单换成录像里那份。

**为什么能和 K 线严格对齐**。标记的 x 用的是画布**同一支笔**：

```
画布  xOf(i) = plot.left + (i - scroll + 0.5) * barWidth
录音条 x(i)  =               (i - scroll + 0.5) * barWidth     // 轨道自己已经让出了 plot.left
```

`barWidth / scroll / plot.left` 由 `chart/viewport.ts` 的 `chartViewport` 提供，
ChartPanel 在**每次请求重绘时**（`requestDraw`，尺寸变化后再补一次）写一遍。
于是缩放、平移、换实例、改窗口大小，录音条都跟着走 —— 不需要任何「同步」消息，
因为两边读的是同一个值。**这一版踩过的坑**：一开始把 `plot.left` 加了两遍
（轨道已经让位，又加了一次），标记整体右偏 10px，肉眼几乎看不出来，
是用一段核对脚本（录音条标记中心 vs `xOf`）量出来的，误差现在是 0.01px 级。

**一根 K 线一个标记**（不是一条语音一个）。同一根上最多 9 条，逐条画会重叠成一坨；
合成一个标记、右上角标条数，点一下**按顺序连播这一根的全部** —— 那正是「听听这根讲了什么」。
标记宽度跟着 `barWidth` 走（一根柱子的 9 成，9–20px），所以缩小时会连成一条
「语音密集区」，放大时各自独立。标记里画的是**真实解码出来的波形包络**
（复用 `AudioWave`），不是装饰。

**三条交互**，都只有一个结果：

| 动作 | 结果 |
|---|---|
| 点标记 | 播这根 K 线上的全部（同一组的正在响就停）；播放中标记变琥珀色，底部一条进度 |
| 点【▶ 连播】 | 按时间顺序把整块盘面（回放时是整条录像）的语音过一遍，按钮变【■ 停止】 |
| 点两端的 `‹n` / `n›` | 视野外还有 n 根讲过话，点一下把视图移过去（`chartNav.centerOn`，只滚视图、不出声） |

「只滚视图、不出声」是刻意的：箭头是找位置的，不是播放键；一按就开口会让人以为点错了。
反过来，**标记不会改变光标、也不会跳步**：它只出声。回放里点标记同样只出声 ——
步进是回放自己的事，被音频拖着走会打乱时间感。

**一个声音**。语音现在有三处能点（浮窗本根清单、浮窗的「其他 K 线」、录音条），
各建一个 `HTMLAudioElement` 就会出现两个问题：点录音条时浮窗里那条还在响；
「哪条在响」有三份互不相认的说法。所以试听收进 `audio/player.ts` 的单例：
一份队列、一份 `currentFile` / `progress` / `error`，浮窗和录音条读同一份状态，
高亮自然同步。队列只做顺序播放，不做循环、不做并发 —— 讲解叠在一起听不清。
播放失败（文件被清掉、浏览器拦自动播放）的说明也写在播放器里，两边分别贴到自己的提示区。

**空态与找不到的情况**，一句话说清各自的下一步（都在轨道左端）：

| 情况 | 文案 |
|---|---|
| 一条语音都没有 | 还没有语音讲解 · 点工具条【🎙 录音】，或按 空格 讲两句 |
| 有，但都在视野外 | 语音都不在视野内 · 点轨道两端的 ‹n / n› 移过去 |
| 有，但 K 线已经不在了（换过数据集） | 这些语音挂在已经不在的 K 线上（数据目录换过？） |
| 回放里一条都没有 | 这条录像里没有语音 |

**没做**：图上（K 线区域）不画「这里有语音」的小喇叭 —— 录音条已经承担了
「按时间轴找语音」的职责，再在蜡烛上叠一层只会和标注抢位置。

### 11.11 统计口径：盈亏、MFE / MAE（v0.18.0）

一条记录里存的是「每一步做了什么」，而人想看的是一行结论。所以收尾时（以及每 2 秒的
检查点）后端把这一笔的统计算进 `RecordingSummary.stats`（见 `trade.go` 的 `statsTracker`）：

| 字段 | 含义 |
|---|---|
| `side` / `quantity` | 开仓方向与**开仓那一下**的手数（加减仓看 `maxQuantity`） |
| `entryTime` / `entryPrice` | 这一笔**第一次成交**的时间与价格 |
| `exitTime` / `exitPrice` | 最后一次成交的时间与价格（部分平仓时一路更新） |
| `realizedPnl` | 全部成交的已实现盈亏之和（美元，口径和账户里那个 `realizedPnl` 一致，都是平均成本法） |
| `mfe` / `mae` | 最大有利 / 不利波动（美元，`mfe >= 0 >= mae`） |
| `barsHeld` | 持仓期间**完整**走过的 K 线根数 |
| `fills` | 成交笔数（开仓 + 加减仓 + 平仓） |
| `steps` | 这段记录里的操作步数（含第 1 步） |
| `closed` | 是否**正常平完**；false = 记录结束时仓位还在（实例被删 / 程序退出 / 崩溃草稿） |

两条容易做错的地方，都写在这里当约束：

1. **MFE / MAE 只统计「有持仓且这一根没有成交」的整根 K 线。**
   一根 K 线只有 OHLC，成交发生在开盘、盘中还是收盘根本看不出来。把开仓那根、平仓那根的
   高低点也算进来，等于凭空替交易者挑了一个最有利/最不利的时刻 —— 那种数字看着更"完整"，
   但经不起追问。所以同一根 K 线内往返时两项都是 0，`BarsHeld` 也是 0。
2. **多头空头用带符号的持仓手数统一，不写分支。**
   `up = (High - 均价) × 持仓手数 × 每点价值`，`dn = (Low - 均价) × 持仓手数 × 每点价值`，
   多头的 `High` 侧是浮盈、空头正好反过来 —— 乘一下符号就对了。写两个分支的话，
   总有一边会把符号写反，而错了的数字看起来照样"合理"（`recording_test.go` 里
   专门有一条**只有空头**的用例钉这个）。

**每点价值**（`price per 1.0 → 美元`）由 `_symbols.json` 的 `tickValue / tick` 算出来，
不另存一个乘数：MNQ `0.50/0.25 = 2`、MES `1.25/0.25 = 5`、MGC `1.00/0.1 = 10`。
没配置（或者配置不成对）时退化成 1 美元/点 —— 至少数字之间还能互相比较。

**为什么在录的时候算，而不是收尾时重放事件流**：广播出去的那一刻 payload 还是**类型化的
结构体**（`BarAdvancedPayload` / `OrderFilledPayload`），成交价、持仓均价、最高最低价都是现成的；
等落盘之后再去 JSON 里翻，等于把已经知道的事实重新猜一遍。老文件（v0.18.0 之前落的）没有
`stats`，读取时用同一个 tracker 按事件流反推（`deriveStats`），所以两种来源口径一致。

### 11.12 记录独立于实例：边界行为全写在这里

交易记录**不是**实例存档的一部分，它是从实例的操作流里**摘出来**的另一份数据：

```
<stateDir>/instances/<id>/{meta.json, events.json, annotations.json, voice/…}   实例存档
<recordingsDir>/<recID>/{recording.json, audio-N.wav}                          交易记录
```

两边不互相引用（记录里只有一个 `instanceId` 用于追溯，删掉实例之后它指向一个不存在的 id，
打开 / 回放 / 删除都不依赖它）。所以：**删实例不删记录、删记录不动实例**。

边界情况都有明确行为，不是「尽力而为」：

| 情况 | 行为 |
|---|---|
| 实例被删除 | 当前这笔**立即收尾并保存**，`Stats.Closed` 按当时仓位如实记（通常 false）；记录文件留在记录目录里，列表上显示「持仓中」 |
| 程序退出（Ctrl+C） | 同上：`Close` 遍历所有实例收尾，不留半截记录 |
| 进程崩溃 | 每 2 秒的检查点保住到最后一刻（见 11.13）；重启后它作为一条「持仓中」的记录留在列表里，不会被当成坏文件 |
| 仓位跨实例 | **不存在**：每个实例有自己的账本（`Position` / `Trades`），同一个标的在两个实例上是两笔独立的交易、两条独立的记录 |
| 重启后仍有持仓 | **不续录**：那笔交易的开头已经在崩溃前那次检查点里了；下一次「空仓 → 有仓」才开新的一条 |
| 反手（多 2 → 卖 4 = 空 2） | 仓位没有经过 0，所以**同一条记录继续记**（它是一笔连续的交易），`maxQuantity` 记下最大值 |
| 操作者离开 / 换人 | 记录**继续**（v0.18.0 删掉了「人走了就收尾」：一笔交易属于这块盘面上的仓位，不属于某个人） |
| 实例被删除后的通知 | `notifyTradeRecorded` 发现实例已不在 `h.instances` 里，退化成**广播给所有人**（前端只刷新一次列表，没有副作用）—— 否则这条记录保存得安安静静，用户还以为丢了 |

### 11.13 检查点：持仓中的记录每 2 秒写一次

自动记录带来一个副作用：一笔交易可能持续几十分钟甚至过夜。只在收尾时落盘的话，
一次崩溃就把整段操作丢光了。

所以 `stateLoop` 每 2 秒看一眼「这一笔有没有新内容」（`tradeRecorder.dirty`），脏了就把
当前这份写成草稿（`SaveDraft`）：记录里长什么样就是什么样，`Stats.Closed` 还是 false，
列表上显示「持仓中」。它和正式记录**同一个 id、同一行**（`Save` 按 id 覆盖，
`SaveDraft` 也按 id 覆盖），所以列表里不会出现「一行草稿 + 一行成品」。

序列化必须在**锁内**做完：副本里的 `Steps` / `Base` 切片和正在推进的那一份是同一份内存，
锁外再 `json.Marshal` 就会撞上并发写。写盘（IO）仍然在锁外 —— 和「写盘在锁外」那条纪律一致。
写失败就把脏标记放回去，否则这次的改动要等下一次操作才有机会落盘，而用户可能正好在这之后
关掉程序。

## 12. 数据加载的取舍

- **不一次读全**：一个标的 800 多个日文件、90 多万根，全读进内存要几十 MB，
  而一次复盘只看锚点附近几百根。所以是「历史 400 根 + 未来 5 天」，用完了再续读。
- **锚点日整日加载**：只收到锚点为止的话，`Bars[cursor+1]` 就是第二天日文件的第一行，
  点「下一根」会从 `12:00` 直接跳到第二天 `00:00`（0.5.1 修的正是这个 bug）。
- **判断「历史够不够」用已揭示根数**，不用已加载根数：锚点靠凌晨时当天那两百多根还没揭示，
  按已加载根数算会提前停止往前补，画布上的历史就不够 400 根了。
- **随机锚点避开首尾各一天**：首日没有历史，尾日没有未来，落在那里会显得工具坏了。
- **去重按时间**：日文件手工合并过可能出现重复，`dedupeBars` 保留后一份（与落盘「后写覆盖」一致），
  保证时间在实例里唯一 —— 协议就用它当标识。
- **坏行不致命**：哪份文件有坏行只记进 `notes`，其余行照常加载。

## 13. 已知限制

| 限制 | 说明 |
|---|---|
| 存档按实例整份重写 | 每 2 秒只重写**变了的那个实例**的文件夹（几个文件、几百 KB）。实例很多、K 线很长时会变慢；真到那一步再换成增量日志 |
| 重启后操作权是空的 | 存档不记「谁在操作」（那个人可能已经不在了）——谁进来谁重新拿 |
| 标注横坐标量化到 K 线 | 端点只能落在 K 线中心，或「最后一根 + N 根」（右侧延伸段）：不能落在两根之间，延伸段也没有时间标签（换来了「严格时间价格」与简单校验） |
| 斐波那契只有四个固定比例 | -1 / 0 / 1 / 2，只能改颜色；想加 0.618 这类比例要改 `fibRatios`（前后端各一份） |
| 模板是全局的，不跟实例走 | 换标的还是那几条常用线；如果将来要「按标的记模板」，得给模板加个作用域字段 |
| 只在 `127.0.0.1` 监听 | 页面能看到本地数据目录的绝对路径，不对外网开 |
| 录像不能跨实例重放 | 录像里的 `base` 是起点那一屏的快照，回放不 join 任何实例，也不读 CSV。所以改过 `data/` 里的 CSV 之后，老录像画的还是当时那一屏 |
| **每根 K 线**最多 9 段语音、单段约 64 秒 | 9 条是「防止在同一根上反复重录」；整块盘面 / 整条录像的总数不限，点【下一根】额度就重置。额度归 `voice.go`（`maxClipsPerBar`），录制器只是沿用这个数。单段上限是 WS 上行帧（4MB）与 base64 膨胀一起决定的，见 11.3 / 11.9 |
| 语音只能在**当前那根** K 线上录 | 挂载点是服务端游标那根（前端不传时间，避免两种「当前」）。要听早先几根的，走横轴下方的录音条（点标记即可，见 11.10），或浮窗里那份「其他 K 线还有 N 条」 |
| 录音条上**一根 K 线只有一个标记** | 同一根上的 9 条合成一个标记（右上角标条数），点一下按顺序连播这一根的全部；想单条点播去语音浮窗。逐条摆在时间轴上会在同一根的位置堆成一坨 |
| 录音条的标记**只出声，不动视图/光标** | 它不跳步、不移动游标：回放里被音频拖着走会打乱时间感。要「回到那一刻」用两端的 `‹n` / `n›` 或者浮窗里的清单 |
| 语音存两份（实例 + 录像） | 一段 30 秒的讲解约 1MB，录制中讲的话会同时写进 `instances/<id>/voice/` 和 `recordings/<id>/`。换来的是两边能各自删、各自留（见 11.9） |
| 波形是包络，不是示波器 | 96 个桶的响度峰值：看得出「哪里在说话、有没有录到」，看不出音色。要真波形得存原始采样并逐点画，在 200px 的列表行里没有意义 |
| 录像没有视频 | 录的是事件流（起始盘面 + 每一条操作广播），不是画面像素。好处是能单步、能搜索、能拿去做回归测试，代价是**画布之外的界面状态**（缩放/平移、选中的 Tab）不在录像里 |
| 录制期间只录「改盘面」的动作 | 操作权变化、成员进出、机器人启停不入录像（它们不是画面上发生了什么），回放到那一步会看不到「谁刚拿了操作权」 |
| 录音文件不重新编码 | 存的就是 16kHz/16bit/单声道 PCM WAV；再想压缩（比如转 opus）就得引第三方依赖，与「零依赖」冲突 |
| 语音**不跟着录像走**（录制之前录的那些） | 录像仍然是「点录制那一刻起的自包含快照」：盘面上早就有的语音不会进这条录像。想让讲解进录像，就在录制中讲 |
| 没有资金/保证金 | 盈亏只按成交价算，不判断买不买得起 |
| 前端没有自动化测试 | 项目约定不用无头浏览器；后端有完整单测 + 真实 WS 端到端 + 冒烟脚本 |

**手动验多人演示**（2 分钟）：

1. 菜单 3，页面打开后在右上角「标的与实例」里建一个实例；
2. 再开一个标签页访问同一地址，在那个下拉面板里点「进入」—— 这个标签页是观众，
   工具按钮变灰、「操作权」显示 human；
3. 回到第一个标签页点「下一根」、画个矩形、挂张单 —— 第二个标签页会同步出现，
   底部「操作记录」Tab 会写着 `human 步进/加标注/挂单`；
4. 第二个标签页点「接管」（需要先交还）或用第一个标签页点「启动机器人」，
   看观众端如何自动跟随；
5. 关掉菜单 3 的窗口（Ctrl+C 回菜单）再重新进 3 —— 实例、标注、挂单都还在列表里。
6. 在「标的与实例」里**删掉当前实例、紧接着新建一个** —— 界面只安静地退回新实例，
   **不弹**「这个实例已经被删除了」，录制浮窗里也不会挂着这句话。

**手动验录制与回放**（3 分钟，需要麦克风）：

1. 进一个实例，点工具栏的【● 录制】——按钮文案变成【录制中…】，出现录制浮窗
   （第 1 步 / 本根录音 0/9 / 当前 K 线时间），此时浏览器会**请求一次麦克风权限**；
   按住浮窗**标题栏**能把它拖走，点 **—** 能折成 44px 的小图标（再点一下展开），
   刷新页面后它还在你拖到的位置；
2. 点【下一根→】两次、画一条射线、挂一张单 —— 浮层上的步数**按操作一步步涨**
   （两次步进 + 一个图形 + 一张单 = 5 步含起点），而不是按 K 线涨；
3. 在浮层里选一个麦克风，**按一下空格（抬起手指）再说一句话、再按一下结束** —— 浮层的
   「本根」+1、**步数也 +1**（录音自己占一步），录的过程中能看到**实时波形**在滚；
   点那一条右边的 ▶ 能试听，点「清空本根」连点两下能删掉（波形和计数一起归零，
   步数也跟着退回去）。
   用机械键盘时把音量开大听开头那一小段：**没有按键的咔哒声**（开麦比抬手晚 90ms）；
4. 点【下一根】再录一条：「本根」从 1 重新数、「共 N 条」继续累加
   （上限是每根 K 线 9 条，不是整条录像 9 条，也不是每步 9 条）；
5. 再点一次【录制中…】结束录制，右下角弹一句「已保存到 …」；
6. 打开 `recordings/` 目录，应该看到 `recordings.json`、一个新文件夹里的 `recording.json`
   和几条 `audio-N.wav`（被清空的那几条不会留下）；
7. 底部【回放】Tab 里能看到这条录像（徽章写「N 步 / M 根」），点开：用 1x / 2x / 4x
   连续播一遍、单步走两下、暂停、重播；**单步时画面一次只变一个东西**（不是一根 K 线的
   全部变化一口气出来），步进条上蓝色=下一根、绿色=画图、紫色=下单、琥珀=录音；
   拖到有琥珀小点的那一步，**下面一行会列出那一段录音（带波形）**，点一下直接出声；
   勾上「自动放语音」也行；
8. 回放期间确认下单浮窗不见了、工具栏的「接管 / 启动机器人」是灰的、按 `Del` 删不掉标注；
9. 点【退出回放】——应该回到原来的实例，盘面还在原处。
