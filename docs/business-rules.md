# 业务规则（当前实现）

本文件记录**代码里已经生效**的交易与数据规则，每条都指向唯一实现。
标「未定义」的是产品需要但代码里不存在的部分 —— 不要把它们当成既有规则使用。

改规则前先读对应实现的文件头注释（那里写着「为什么」）；改完必须补测试。

## 1. 术语

| 术语 | 含义 | 位置 |
|---|---|---|
| 标的（symbol） | 如 `CME_MINI:MNQ1!`，一个标的一个数据文件夹 | `store` |
| 日文件 | 一个标的、一个本地日期一个 CSV，文件名即日期 | `store` |
| 实例（Instance） | 一块盘面：标的 + 锚点 + 已揭示的 K 线 + 订单/成交/标注/语音 | `replay/instance.go` |
| 锚点（Anchor） | 实例开始那一刻的 K 线时间 | 同上 |
| 交易记录（Recording） | 从空仓→有仓到回到空仓这一段的事件流，独立于实例存档 | `replay/trade.go` |
| 操作（Event） | 任何会改变盘面的动作，经广播下发并落进记录 | `replay/hub.go` |

## 2. 行情与时间口径

| 规则 | 内容 | 实现 |
|---|---|---|
| 周期 | 只收 `intervalSeconds = 300`（5 分钟）；其他周期的序列整段跳过 | `ingest` |
| 周期判定 | 不看任何字段，用相邻时间戳的**众数差**反推；按「会话 + 序列」分别投票 | `ingest/decode.go` |
| 时间列 | CSV 的 `time` 是 K 线**开盘时间**，本地时区明文 `yyyy-MM-dd HH:MM`，非 Unix 秒 | `store` |
| 日期归属 | 按本机时区划「哪一天」；换机器/换时区，同一根 K 线的归属日会变 | `store/timebar.go` |
| 交易日 | 从 **06:00** 起算（美国盘换算到本地）；04:50~05:55 是结算收尾时段 | `replay/session.go`、`bot_strategy.go` |
| 下一天开盘的判据 | **停盘缺口**（与上一根间隔 > 65 分钟），不是「0 点」 | `replay/session.go` |
| 日历日最后一根 | 23:55（本地），此后到 05:55 无 K 线（CME 结算） | `store.ExpectedBars` |
| 每日期望根数 | 周一 216/204、周二~周五 276、周六 72/60、周日 0（夏令时/冬令时各一值） | `store/scan.go: expectRule` |

## 3. 订单模型

- 单型只有三种：`limit` / `stop` / `market`；方向 `buy` / `sell`。
  **没有**独立的「止损单类型」「止盈单类型」—— 要止损就挂一张 `stop`。
- 状态：`open` → `filled` / `cancelled`；市价单生成即为 `filled`。
- 手数必须是正整数，上限 10000（`normalizeQuantity`）。
- 挂单可以改价（`moveOrder`），但**不改单型、不改数量、不改编号**；
  只有 `open` 状态可改。
- 挂单可带 `Group`（OCO 组号）；用户手动下单不带组，机器人止盈止损才带。
- 单型由**下单那一刻**的价格相对现价的方向决定（前端 `chart/orders.ts: orderKindFor`），
  拖动改价不会翻转单型。

## 4. 撮合规则

实现：`internal/replay/instance.go` 的 `advance` / `orderTriggered` / `fillPriceFor` / `ocoWinner`。

| 规则 | 内容 |
|---|---|
| 撮合时机 | 每揭示一根新 K 线，用这根的最高/最低价撮合 |
| 挂单生效 | **本根挂的单从下一根开始参与**（`PlacedIndex >= Cursor` 跳过），不用已收完的 K 线倒推 |
| 限价买 | `low <= 挂单价` 触发 |
| 限价卖 | `high >= 挂单价` 触发 |
| 止损买 | `high >= 挂单价` 触发 |
| 止损卖 | `low <= 挂单价` 触发 |
| 成交价 | `min/max(挂单价, 开盘价)`：限价买/止损卖取 min，限价卖/止损买取 max（跳空时成交在开盘价，不白捡便宜） |
| 部分成交 | 不模拟，一次全成交或全不成交 |
| 市价单 | 立即按**当根收盘价**成交，价格四舍五入到 2 位小数（`roundPrice`） |
| 成本 | **无手续费、无佣金、无点差、无滑点、无隔夜费** |

## 5. 持仓与盈亏

实现：`instance.go: applyFill`（唯一权威）、`position`、`unrealizedPnl`、`pointValue`。

- 持仓是**净头寸**：`Quantity` 正=多、负=空、0=空仓；`AveragePrice` 为平均成本。
- 同向成交 → 加权平均摊平成本。
- 反向成交 → 先平能平的部分，已实现盈亏：
  `(成交价 - 均价) × 平掉手数 × 方向 × 每点价值`。
- 反手（平完还有剩余）→ 新仓均价 = 本次成交价。
- 未实现盈亏 = `(当前根收盘价 - 均价) × 持仓量 × 每点价值`。
- **每点价值** = `tickValue / tick`（来自 `data/_symbols.json`）；
  取不到时退化为 `1`，即「价格每走 1.0 一手算 1 美元」。
- 逐批平仓（`closedLots`）是**只读派生视图**，供画布上的平仓虚线使用，
  不参与记账、不落存档。

## 6. OCO（同组保护单）

- 同一 `Group` 在一根 K 线内**最多成交一张**，另一张记为 `cancelled`（不静默丢弃）。
- 两张都触发时 **止损优先**，与挂单顺序无关。
- 同为一种类型时，先挂的优先。
- 理由：5 分钟 K 线看不出最高/最低谁先出现，取对持仓不利的一侧，避免回测系统性偏乐观。

## 7. 一键退仓（flatAll）

一条消息完成：先按现价市价平掉整个仓位 → 再撤销全部 `open` 挂单 → 广播一条 `flat_all`。
市价平仓失败时挂单还没动过，盘面保持原样。既无仓位也无挂单时返回错误。

## 8. 交易记录

实现：`replay/trade.go`、`recording.go`；录制挂在**唯一的广播出口**上。

- **自动开始**：仓位从 0 变成非 0 的那一刻开始录；**自动结束**：仓位回到 0。
- 第 1 步是「开仓成交之前」的盘面快照，所以回放能看到入场那一下。
- 同一根 K 线内开平也留一条完整记录。
- 记录与实例存档**互不引用**：删实例不删记录，删记录不影响实例。
- 崩溃保护：每 2 秒 checkpoint；重启后未平仓的记录以「持仓中」保留（`Closed=false`），不续录。
- 统计（`TradeStats`）：开/平时间与价格、手数、最大手数、已实现盈亏、MFE/MAE、
  持仓根数、成交笔数、操作步数、是否平完。
- **MFE/MAE 只统计「持仓期间且该根没有成交」的整根 K 线**；
  同一根内开平记为 0。
- 记录页时间轴一律按 `createdAt`（记录生成时间）分组：复盘可以今天补做去年的行情。
- 回放延伸：只能在记录**末尾**加载后续真实 K 线，作为一步 `bar_extended` 写进记录；
  中间插入会让后续步的时间与游标错位。

## 9. 策略机器人

实现：`internal/strategy`（纯函数出信号）+ `replay/bot_strategy.go`（执行器）+ 撮合复用 `advance`。

- 策略只输出「方向 + 止损价 + 目标价」（绝对价格），不接触 `Instance`，不能自造成交价。
- 开仓时挂两张同组保护单（止损 + 止盈），受 OCO 约束。
- 日终硬约束（**仅机器人**）：23:55 那根无条件平仓 + 撤光挂单，本根不再开新仓；
  04:50 起进入结算收尾，只平不开；换交易日时清仓兜底。
- 目前注册的策略只有 `caveman` 一个；另有「随机演示机器人」（不填 strategy）。
- 机器人状态只在内存，不落存档；重启不会自己接着跑。

## 10. 数据质量判定（分析页）

实现：`internal/store/scan.go`，前端只排版不重算。

- **异常日**：当天根数不在 `expectRule` 给出的期望值里，或文件有坏行/重复/读不了。
- **数量不一致日**：同一天有数据的各标的根数不完全相同。
- 增量扫描的记忆键是「文件路径 + 大小 + 修改时刻」；缓存失效靠磁盘指纹，不靠时间。
- 页面每 2 秒轮询，实时链路只有一条：`store 写盘 → 指纹变 → 重扫 → 页面换数字`。

## 11. 未定义（产品需要，代码里没有）

以下内容**不要**当作既有规则使用，也不要在实现时自行补全：

1. 账户：余额、权益、可用保证金、出入金。
2. 交易成本：手续费、佣金、点差、滑点、隔夜利息。
3. PF 考核：账户规模、利润目标、最大回撤（静态/跟踪）、日亏限制、最少交易日、
   通过/失败判定与暂停规则。
4. 多实例/多标的合并到一个账户的记账口径。
5. 合约乘数以外的保证金计算（当前只有 `tickValue / tick` 的点值换算）。

## 12. 改规则的检查清单

- 撮合 / 盈亏 / 手数 → 改 `instance.go`，跑 `go test ./internal/replay`。
- 时段 / 日终 → 改 `session.go` 或 `bot_strategy.go`，跑 `dayclose_test.go`、`bot_strategy_test.go`。
- 记录 / 统计 → 改 `trade.go`，跑 `persist_test.go`、`recording_test.go`。
- 期望根数 → 只改 `store.ExpectedBars`，同步 `webreport/testdata/format.test.cjs` 的期望值。
- 协议字段 → 同时改 `replay/protocol.go` 与 `web/src/types/protocol.ts`。
- 任何规则变更都要在本文件同步一条，并说明影响到的历史数据/记录是否需要重算。
