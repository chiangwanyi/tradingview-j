# 产品定位与 MVP 范围

> 本文件是 PF 考核训练平台前端重构的**第一阶段**产出：只做产品分析与设计，不含任何代码改动。
> 全文使用三种标记：
> - `[事实]` 能从当前仓库代码 / 文档核实的；
> - `[建议]` 为本产品目标提出的设计主张，可以推翻；
> - `[待确认]` 必须由你决定，**本文件不替你补**。

---

## 1. 一句话定位

`[建议]` 把现在的「K 线回放工具」变成**一个能回答"我这次考核还剩多少空间"的训练台**：
概览页管考核，工作台管练，记录页管复盘。

注意这里的主语：**考核状态是主角，行情是手段**。回放、标注、模拟下单这些能力不新增，
只是被重新组织到"为考核服务"的位置上。

## 2. 现状基线（只列与本次设计相关的）

| # | 事实 | 来源 |
|---|---|---|
| F1 | 程序是**单 exe + 本地两个 HTTP 服务**：`8765` 数据质量分析页（只读、跟着抓取自启自停）、`8790` 复盘页（有状态，托管 `web/dist`） | `config.json`、`internal/webreport`、`internal/replay` |
| F2 | 复盘前端只有 **3 条路由**：`/`（画布）、`/records`（月历）、`/records/day/:date`（当天详情） | `web/src/router/index.ts` |
| F3 | 前端是 Vue 3.5 + Pinia + TS + Vite + Tailwind 4，**只有浅色一套配色**，语义色 `up=绿 / down=红`（美股习惯，与国内相反） | `web/src/style.css`、README |
| F4 | 一个**实例（Instance）** = 单标的 + 锚点 + 已揭示 K 线 + 订单/成交/标注/语音，**盈亏只挂在实例上**（`RealizedPnl` / `UnrealizedPnl`） | `replay/instance.go`、`protocol.go:489` |
| F5 | **没有账户模型**：无余额、无权益、无初始资金。`InstanceSummary` 只有 `realizedPnl` 和 `trades` 两个钱相关字段 | `protocol.go:467`、`docs/business-rules.md` §11 |
| F6 | **没有任何 PF 规则代码**：利润目标、最大回撤、日亏限制、最少交易日、通过/失败判定全部不存在 | `docs/architecture-audit.md` §5 |
| F7 | 撮合**零成本**：无手续费、无佣金、无点差、无滑点 | `docs/business-rules.md` §4 |
| F8 | 行情只有 **5 分钟**，且只能靠人工在 TradingView 上拖出来（被动旁路） | README、`config.json: intervalSeconds=300` |
| F9 | 交易记录**按 `createdAt`（记录生成时间）归日**，行情时间只作为每笔的附加信息 | `docs/business-rules.md` §8 |
| F10 | 交易日按 **06:00** 起算，日终 23:55，日历日与交易日不一致 | `replay/session.go`、`business-rules.md` §2 |
| F11 | 多人：一人操作、其余观看；状态下发只有一条路（后端定稿、前端预览） | `replay/hub.go`、ADR-007 |
| F12 | 记录页已有**八张 KPI + 六张 ECharts 图**（日历 / 当天 / 统计三个 Tab） | `RecordsKpi.vue`、`RecordsCharts.vue` |
| F13 | 现有页面**没有全局导航**，靠顶栏按钮互相跳（`/` ↔ `/records`） | `ReplayView.vue:160`、`RecordsTopBar.vue` |

**F4/F5 是本阶段最重要的两条**：账户不是"再加一个字段"，是一个新的聚合根。
界面可以按"已有账户"来设计，但必须知道**这个账户在后端还不存在**。

## 3. 目标用户与他们的真实问题

`[建议]` 只有一个用户画像：**自己在做 PF 考核（或准备做）的个人交易者**，
用 5 分钟 MNQ/MES 一类期货练手，需要在一个屏幕里回答五个问题：

1. 我这次考核还活着吗？（状态）
2. 离目标还有多远？（利润）
3. 我今天还能亏多少、总共还能回撤多少？（风险）
4. 今天做得怎么样？（当日）
5. 我这套做法长期能过吗？（复盘）

对照现有产品：第 4、5 题**已有相当能力**（记录页），第 1、2、3 题**完全没有**。
所以本项目的价值集中在**补 1/2/3**，而不是重做 4/5。

## 4. 核心价值主张

`[建议]` 三句话，用于判断任何设计该不该进 MVP：

1. **风险先于收益**：屏幕第一眼看到的是"还剩多少空间"，不是"赚了多少"。
2. **每一笔都算数**：在工作台下的每一单都实时进入某一次考核的账，不需要用户手动"开始/结束"。
3. **一次只面对一个考核**：多账户时切换要一键，但不能在一屏里摊开所有账户的数字
   （摊开等于让人无法判断哪个更急）。

## 5. 设计原则

| # | 原则 | 具体含义（可验收） |
|---|---|---|
| P1 | **两种模式物理隔离** | 自由研究 / 考核训练是两个互不相通的账本；界面上永远有标识说明"现在这一单算不算考核" |
| P2 | **一屏一个结论** | 概览页第一屏必须有一句自然语言的判断句，而不是一排 KPI 数字墙 |
| P3 | **风险不只靠颜色** | 任何"接近/越过限制"的状态必须同时有文字、图标或数值表达（色觉障碍 + 灰度打印） |
| P4 | **口径只有一份** | 金额、百分比、剩余空间的算法只在后端算；前端只排版（沿用 ADR-005/ADR-007） |
| P5 | **规则是数据，不是代码** | `[建议]` PF 参数按账户存储、可在设置里改；换一家 PF 公司不改代码 |
| P6 | **不给未来买单** | 不做多币种、不做团队、不做对接真实券商、不做移动端 |
| P7 | **演示必须可辨认** | 所有非真实数据带 `[演示数据]` 标识，且有一条常驻说明 |

## 6. MVP 范围

### 6.1 必做（本阶段设计对象）

| 场景 | 内容 | 为什么是 MVP |
|---|---|---|
| A 查看考核进度 | 概览页：账户身份、状态、目标进度、两处风险空间 | 产品的存在理由，没有它就是个回放工具 |
| B 开始/继续训练 | 工作台顶部的账户风险条 + 从概览一键进入 | 训练入口必须在一屏内可达，否则用户会绕回旧路径 |
| C 观察交易风险 | 权益 / 余额 / 已实现 / 未实现 / 当日盈亏 / 两处剩余空间的语义分层 | PF 训练失败几乎都死在"不知道还剩多少" |
| D 回顾历史表现 | 记录页按账户筛选（页面本身已有） | 已有能力，只需加一个维度，成本极低 |
| E 查看考核结果 | **状态卡 + 结论抽屉**，不做独立结果页 | 通过/失败是状态，不是目的地；独立页在 MVP 里是浪费 |

### 6.2 明确不做（P2 以后）

- 考核账户之间横向对比、排行榜；
- 一致性规则（consistency rule）等高级 PF 条款；
- 出金 / 扩规模 / 账户购买流程；
- 真实 PF 公司对接、自动同步官方后台；
- 实时行情（本系统只有 5 分钟回放，没有 tick 级实时）；
- 移动端 / 触屏布局；
- 多标的合并成一个考核账户（`[待确认]` Q11，见 `business-rules-open-questions.md`）。

### 6.3 页面数量结论

`[建议]` **3 个页面 + 1 个抽屉**，不设"规则与设置"独立页：

| 目的地 | 类型 | 说明 |
|---|---|---|
| 考核概览 `/` | 页面（默认首页） | 替代现在的画布首页 |
| 交易工作台 `/train` | 页面 | 现有 `ReplayView` 的重新包装 |
| 交易记录 `/records` | 页面（含统计 Tab） | 已有，增加账户维度；统计复盘作为它的 Tab 而不是新页 |
| 账户规则 / 设置 | 抽屉 | 只读规则 + 少量账户管理，撑不起一个页面 |

理由：你列的 5 个候选页面里，"统计复盘"与"交易记录"看的是同一批数据（记录页已有八 KPI + 六图），
拆成两个页面只会让人在两处找同一个数；"规则与设置"在一次会话里通常只看一次，
做成页面等于给它和概览同等的导航权重。**减少页面数量本身就是产品决策，不是偷懒。**

如果后续统计确实长到需要自己的工作量（比如多账户对比、标签钻取），再拆页，迁移成本只是加一条路由。

## 7. 与现有实现的取舍（必须知道的代价）

| 取舍 | 说明 |
|---|---|
| 首页从画布换成概览 | 现在的肌肉记忆（打开就想看盘）会被打断；缓解办法是概览页右上角常驻「继续训练」，一键进上次的实例 |
| 画布页不再兼首页 | 多人协作时"观众"进来先看到的是账户状态，不是别人正在画的盘面 —— `[待确认]` 是否需要"跟随操作者"入口 |
| 账户要新做后端 | 本阶段后端冻结，所以 Mock Demo 只能是静态布局；真实联调要等后端出账户域（见 `business-rules-open-questions.md` Q14） |
| 5 分钟粒度 | 考核的"当日盈亏"只能按 5 分钟收盘价评估；盘中瞬时突破回撤线**在本系统里无法复现**，判定口径必须由你定（Q5） |
| 红绿语义 | 沿用项目现有的 `up=绿 / down=红`（F3），不改成国内习惯 —— 改一处会连带 `chart/render.ts` 和全部组件，且与 README 的书面约定冲突 |

## 8. 一句话总结

`[建议]` 新版不是"给回放工具加一个仪表盘"，而是**把考核账户变成产品的中心，回放降级成它的执行器**。
判断一条需求该不该做，只问一句：它有没有帮用户更快知道"我还剩多少空间"。
