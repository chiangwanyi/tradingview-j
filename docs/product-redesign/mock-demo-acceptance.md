# 静态 Mock Demo 验收标准

> 用途：下一阶段的 UI 实现完成后，**逐条对勾**即可判断"能不能给你看"。
> 每条都是可观察的事实，不写"体验良好"这类无法判定的标准。
> 本阶段只定义标准，不实现页面。

---

## 0. Demo 的定义（先划线）

| 是 | 不是 |
|---|---|
| 静态布局：页面、区块、层级、字号、间距、颜色 | 可运行的应用 |
| 演示数据写死在页面里，带 `[演示数据]` 标记 | 真实计算盈亏、权益、回撤 |
| 页面之间可跳转（可为假链接） | 真正推进 K 线、撮合成交 |
| 概览 / 工作台 / 记录 三个页面 + 规则抽屉 | 登录、多用户、权限 |
| 可切换"演示账户 A/B/C"与"自由研究" | 接入 WebSocket、读写本地文件 |

`[建议]` 技术形态：**纯静态 HTML + 内联样式或现有 Tailwind 构建产物**，
不引入新依赖、不建 Vue 页面（本阶段允许零代码，Demo 阶段也只允许"看得见、点得动"的静态页）。
若需要复用现有 token，只能**复制** `style.css` 里的 CSS 变量，不要改动源文件。

## 1. 一票否决项（任一不满足即不通过）

| # | 检查 | 判定方式 |
|---|---|---|
| V1 | **没有任何真实数据的假象**：所有非真实数字都带 `[演示数据]` 标记，且顶栏有一条常驻演示横幅 | 截图 + 全文搜索 `[演示数据]` |
| V2 | **余额、权益、当日盈亏、回撤四个概念在界面上不互相冒充**：标签文字各不相同，且有位置说明区别 | 人工读 | 
| V3 | **风险信息不只靠颜色**：接近/触线状态同时有文字（"还剩 $X"/"已触线"）或符号 | 灰度截图仍能判断 |
| V4 | **自由研究与考核模式可一眼区分**：任一页面都能看到当前模式徽章 | 三个页面各自截图 |
| V5 | **不存在未确认规则的具体计算公式**：界面上出现的每个计算值都能追溯到 `[演示数据]` 或"演示口径"说明 | 逐字段核对 |
| V6 | **没有把概览页做成 KPI 卡片墙**：第一屏必须有一句自然语言结论句 | 人工读 |
| V7 | **没有修改现有仓库文件**：`git status` 只显示新增的 `docs/product-redesign/` 与 Demo 目录 | `git status` |
| V8 | **没有新增依赖、没有改技术栈**：`web/package.json`、`go.mod` 无变化 | `git diff` |

## 2. 覆盖面（核心流程是否走通）

| # | 检查 | 通过标准 |
|---|---|---|
| C1 | 三个页面齐全 | 概览、工作台、记录（含统计 Tab）各有一张可看的页面 |
| C2 | 规则抽屉可打开 | 从概览与工作台都能打开，内容含 Q3/Q4/Q5 对应参数 |
| C3 | 概览 → 工作台 | 「继续训练」按钮存在且指向工作台 |
| C4 | 概览 → 记录 | 点"最近 5 笔"任一行或权益曲线某点，能跳到记录页 |
| C5 | 工作台 → 记录 | 顶栏导航可达 |
| C6 | 记录 → 单笔 | 从逐笔明细能跳回工作台（回放态） |
| C7 | 账户切换 | 至少两个演示账户可切换，切换后概览卡片内容随之变化 |
| C8 | 场景 A~E 都能在 Demo 里被"看到" | A 概览、B 工作台、C 风险条、D 记录、E 通过/失败状态卡各至少出现一次 |
| C9 | 状态覆盖 | 至少展示：进行中、接近上限、已通过、已失败 四种；空状态至少展示"无账户" |

`[建议]` C9 用"演示账户 A/B/C"三个数据组自然覆盖，不必为每个状态做单独页面。

## 3. 账户与考核状态是否清晰

| # | 检查 | 通过标准 |
|---|---|---|
| A1 | 账户身份可读 | 名称、规模、考核类型、状态、已训练天数五项都在身份卡里 |
| A2 | 状态不靠颜色也能读 | 徽章内必须有文字（进行中/接近上限/当日失效/已通过/已失败） |
| A3 | 目标进度可算 | 同时给出：权益、目标值、百分比、还差多少四个数，且百分比与"还差"能对上（±$1 舍入） |
| A4 | 权益与余额并存时能区分 | 同屏出现时，一个是主数字、一个是小字并带标签 |
| A5 | 已结束账户表现正确 | 通过/失败状态下，训练按钮不再显示"继续训练" |

## 4. 风险信息是否容易理解

| # | 检查 | 通过标准 |
|---|---|---|
| R1 | 两处剩余空间都有一句话结论 | 各自出现"还能亏 $X"/"还能回撤 $X"，不是只给两个负数让人自己减 |
| R2 | 横条有参照 | 每个剩余空间都配一条填充比例条，且标注上限值 |
| R3 | 接近上限有双通道提示 | ≥80% 时：颜色变化 + 文字/符号 |
| R4 | 回撤基准可见 | 追踪式回撤旁必须出现"峰值权益 $X"，否则"回撤"不可解释 |
| R5 | 触线状态明确 | 触线后对应卡片写明"已触线"与后果（演示口径），按钮禁用并给原因 |
| R6 | 工作台风险条与概览一致 | 同一账户同一时刻，两页的权益/今日盈亏/两处剩余数字相同（静态写死也要一致） |

## 5. 布局与视觉

| # | 检查 | 通过标准 |
|---|---|---|
| L1 | 1440×900 下无横向滚动、无重叠、无被裁切 | 截图 |
| L2 | 1280×720 下仍可用（允许纵向滚动） | 截图 |
| L3 | 层级清楚 | 每页只有一个"最大字号"层级；仪表数字 > 区块标题 > 正文 > 辅助 |
| L4 | 颜色克制 | 只使用现有 9 个语义令牌 + `up/down` 两色；不出现第二种绿色或主题色 |
| L5 | 数字格式统一 | 金额统一 `+$1,240.00` / `-$430.50`，百分比 `62.0%`，等宽数字 |
| L6 | 画布页没被"加装饰" | 工作台除 36px 风险条外，画布区域占比不明显小于现状 |
| L7 | 不是 KPI 墙 | 概览页的"卡片"数量 ≤ 6，且至少一个是**非卡片**的（进度条/结论句/曲线） |

## 6. 演示数据标识

| # | 检查 | 通过标准 |
|---|---|---|
| D1 | 顶栏常驻横幅 | `演示数据 · 非真实考核结果`，任一页面可见 |
| D2 | 每处参数区块有标记 | 概览主卡、规则抽屉、统计页各有一处 `[演示数据]` |
| D3 | 规则抽屉有免责说明 | 明确写"不代表任何真实 PF 公司规则，本地模拟" |
| D4 | 演示参数集中可查 | 与 `business-rules-open-questions.md` §6 的表一致（50K/150K/25K 三组） |
| D5 | 没有假装算出来的数 | 不出现无来源的"上月收益""胜率 68.3%"这类未在演示表里定义的统计 |

## 7. 模式隔离是否清楚

| # | 检查 | 通过标准 |
|---|---|---|
| M1 | 模式徽章常驻 | 概览/工作台/记录三页都能看到当前模式 |
| M2 | 自由研究记录不可计入 | 记录列表里自由研究的行带灰标签 `自由研究 · 不计入`，且**没有**"计入考核"的开关 |
| M3 | 切换账户有确认语义 | 有持仓时切账户的提示文案存在（静态文案即可） |
| M4 | 不存在混合账户的视图 | 任何页面都不会把两个账户的盈亏加在一起显示 |

## 8. Demo 阶段明确不做（做了反而不通过）

- 实时计算：任何"改一个数、另一个数跟着变"的联动金额（可以有点击态，但不能有算出新值）；
- 真实 WS 连接、真实读写 `state/` / `recordings/`；
- 登录、角色、权限；
- 深色模式（`[事实]` 项目只有浅色一套）；
- 图表交互（缩放、十字光标、标注）—— 工作台可以用现有截图占位；
- 统计页六张图的真实 ECharts 渲染：可以用静态占位框 + 图例标题，**不要**为了好看编造数据曲线
  （唯一例外：权益曲线用演示数据表里的点数手画，且标注 `[演示数据]`）。

## 9. 交付物清单

| # | 交付 | 形式 |
|---|---|---|
| 1 | 概览页 | 静态 HTML，展示账户 A（进行中，接近上限） |
| 2 | 概览页状态变体 | 账户 B（已通过）、账户 C（已失败）、无账户空态，共 3 个变体（可用同一文件切换参数） |
| 3 | 工作台页 | 静态 HTML，含 36px 风险条 + 画布占位 + 底部 Tab |
| 4 | 记录页 | 静态 HTML，月历 + 当天 + 统计三个 Tab 的**静态**状态（Tab 可切换即可） |
| 5 | 规则抽屉 | 静态 HTML 覆盖层 |
| 6 | 一页对照说明 | `mock-demo-notes.md`：哪些是演示、哪些待确认、与本文档的偏差清单 |

`[建议]` 第 6 项必须有：Demo 一定会与规格有偏差，**偏差必须写出来**，否则下一阶段会把偏差当需求。

## 10. 验收动作（10 分钟走完）

1. `git status` —— 只有新增文件（V7/V8）；
2. 打开概览页，5 秒内说出"目标完成多少、今天还能亏多少、回撤还剩多少"（P2）；
3. 灰度截图概览页，仍能读出所有风险状态（V3）；
4. 切到账户 B / C，状态徽章与按钮文案随之改变，且没有"继续训练"（A5）；
5. 切到"自由研究"，模式徽章变化，记录页出现 `不计入` 标签（M1/M2）；
6. 打开工作台，风险条四个数与概览一一对应（R6）；
7. 打开规则抽屉，读到 Q3/Q4/Q5 的三个参数与免责说明（D3）；
8. 全文搜索"演示"，确认标记密度足够（D1/D2）；
9. 读 `mock-demo-notes.md`，确认所有偏差都已列出。
