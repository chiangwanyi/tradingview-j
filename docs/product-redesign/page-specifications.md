# 页面规格

> 五个交付物里最长的一份。每页按「目标 → 布局 → 信息层级 → 交互 → 状态」的顺序写，
> 目的只有一个：**下一个 UI Agent 不需要猜**。
> 标记沿用：`[事实]` / `[建议]` / `[待确认]`。所有金额单位美元，示例数字一律 `[演示数据]`。

---

## 0. 全局外壳

| 项 | 规格 | 理由 |
|---|---|---|
| 顶栏 | 48px，`bg-panel`，下边框 `border-line`，左右 padding 12px | 与现有 `ReplayView` 顶栏高度一致，切页不跳动 |
| 一级导航 | 三段等宽文字按钮：概览 / 训练 / 记录；当前项文字 `text-ink` + 2px 下划线，其余 `text-dim` | 三项，不需要图标；文字比图标更能表达"记录"这种含糊概念 |
| 账户切换器 | 顶栏右侧，显示 `账户名 · 规模` 与状态点；点开为下拉：自由研究 / 各账户 / 管理账户 | 模式和账户合一，见 `user-flows.md` §8 |
| 模式徽章 | 切换器左侧，胶囊：`考核 A`（`bg-accent-soft`）/ `自由研究`（`bg-elev` + `text-faint`） | P1：任何时候都能看出这一单算不算考核 |
| 连接状态 | 1.5px 圆点 + 文字（已连接/连接中/已断开），沿用现有实现 | `[事实]` `ReplayView.vue:34` |
| 演示横幅 | 当数据非真实时，顶栏下方一条 24px 的 `bg-amber` 提示：`演示数据 · 非真实考核结果` | P7；只在演示数据存在时出现，真实数据下**不留空条** |
| 配色 | 只用现有令牌：`surface/panel/elev/line/ink/dim/faint/accent/up/down` 及其 `-soft` 变体 | `[事实]` `style.css` 只有浅色一套 |
| 字号基线 | 正文 13px，次要 12px，页面标题 15px，仪表数字 28–40px（`tnum`） | 现有页面已是 12/13/15 三档，加一档"仪表数字"即可 |
| 数字格式 | 金额 `+$1,240.00` / `-$430.50`（千分位、两位小数、正数带 `+`）；百分比 `62.0%`；金额单位后缀 `tnum` 等宽 | 与 `lib/records.ts: moneyText / pctText` 一致，前端不另写格式化 |

## 1. 考核概览 `/`（最重要的页面）

### 1.1 页面目标

一屏之内回答："我现在急不急、该不该练、练得怎么样"。
**成功标准**：用户不做任何点击，就能说出"我距离目标还差多少、今天还能亏多少、回撤还能吃多少"。

### 1.2 布局（1440×900 基准，两列 62 / 38）

```
┌─ 顶栏 48 ──────────────────────────────────────────────────────────────┐
├─ 演示横幅 24（仅演示数据时）───────────────────────────────────────────┤
│                                                                        │
│ ┌── 左列 62% ──────────────────────┐  ┌── 右列 38% ─────────────────┐ │
│ │ ① 账户身份卡                      │  │ ④ 今日风险卡                │ │
│ │  账户A · 50K · 追踪回撤    [进行中]│  │  今日亏损 ██████░░░░ 43%    │ │
│ │  第 7 个交易日 · 开始 10-21       │  │  已亏 -$430 / 上限 -$1,000  │ │
│ │                                  │  │  还能亏 $570                │ │
│ │ ② 结论句（一句话，16px）           │  │                            │ │
│ │  "目标完成 62%，今天还能亏 $570，   │  │ ⑤ 总回撤卡                  │ │
│ │   回撤还剩 $2,400"                │  │  当前回撤 ██░░░░░░░░ 20%    │ │
│ │                                  │  │  -$400 / 上限 -$2,000       │ │
│ │ ③ 目标进度条                      │  │  还能回撤 $1,600            │ │
│ │  权益 $51,860          目标 $53,000│  │  峰值权益 $51,900           │ │
│ │  ████████████████░░░░░░  62%      │  │                            │ │
│ │  还差 $1,140 · 还需 3 个交易日(?)  │  │ ⑥ 规则摘要（只读 → 抽屉）   │ │
│ │                                  │  │  目标 6% · 日亏 2% · 回撤4% │ │
│ │ ⑦ 权益迷你曲线（最近 20 交易日）    │  └────────────────────────────┘ │
│ │  含目标线（绿虚线）与失败线（红虚线）│                                │
│ └──────────────────────────────────┘                                │
│ ┌── 底部通栏 200px ───────────────────────────────────────────────────┐│
│ │ ⑧ 最近 5 笔（表格，行可点→回放）  │ ⑨ 今日小结 │ [继续训练]（主按钮）││
│ └────────────────────────────────────────────────────────────────────┘│
└────────────────────────────────────────────────────────────────────────┘
```

`[建议]` 左右两列**不等宽**：左边讲"离成功多远"（过程），右边讲"离失败多近"（约束）。
把两处风险做成等宽并排的卡片墙，就会变成企业后台的 KPI 面板 —— 这正是你明确不要的效果。

### 1.3 信息层级（逐字段判定）

| 区块 | 信息 | 层级 | 表达方式 | 为什么 |
|---|---|---|---|---|
| ① | 账户名 / 编号 | 中 | 15px 加粗 | 多账户时这是"这是谁"的唯一锚点 |
| ① | 考核类型（如 50K 追踪回撤） | 低 | 12px `text-dim`，跟在规模后面 | 规则差异会影响读法，但不需要大字 |
| ① | 账户规模（50K） | 中 | 与账户名同行 | 规模决定"$1,000 日亏"是不是严苛 |
| ① | 当前状态 | **高** | 状态徽章：进行中（中性）/ 当日失效（琥珀）/ 已通过（绿）/ 已失败（红），**徽章内带文字** | 状态是最先要读的，但不能只靠颜色（P3） |
| ① | 开始时间 / 已训练交易日 | 低 | 12px 一行 | 天数只有在"最少交易日"规则存在时才有用（`[待确认]` Q7） |
| ② | 结论句 | **最高** | 16px，一句话，数字加粗 | P2：一屏一个结论；比任何卡片都先被读到 |
| ③ | 起始余额 | 低 | 放在"目标"的展开说明里 | 只在算百分比时用到，值不变 |
| ③ | 当前余额（已平仓） | 低 | 与权益同区块，12px，标"余额" | 与权益并列但**降一档**，避免两个数打架 |
| ③ | 当前权益 | **高** | 与进度条同一行，右对齐对齐目标值 | "我现在有多少"是决策基础 |
| ③ | 目标盈利金额 | 中 | 进度条右端标签 | 提供"距离"的参照 |
| ③ | 当前累计盈利 | 中 | 进度条填充里或左侧数字 | 与权益区分：这是"赚了多少"不是"有多少钱" |
| ③ | 目标完成百分比 | **高** | 28–32px `tnum`，进度条右侧 | 一个数说清进度 |
| ③ | 距离目标还差 | **高** | 进度条下方，`+$1,140` 形式 | 用户真正关心的是这个，不是百分比 |
| ④ | 每日亏损限制 | 中 | 横条左端点标签 `-$1,000` | 上限是常量的参照系 |
| ④ | 当日盈亏 | **高** | 大数字（盈利绿 / 亏损红）+ 横条填充 | 今天的手感 |
| ④ | 当日剩余亏损空间 | **高** | 横条右侧 `还能亏 $570`，用量 > 80% 时变琥珀并加"⚠"符号+文字 | PF 最常死在这一条 |
| ⑤ | 总回撤限制 | 中 | 横条左端点 | 同上 |
| ⑤ | 当前回撤 | **高** | 大数字 + 横条 | 决定"还能连亏几天" |
| ⑤ | 剩余回撤空间 | **高** | `还能回撤 $1,600` | 唯一直接决定"会不会出局"的数 |
| ⑤ | 峰值权益 | 低 | 12px 灰字，横条下方 | 追踪式回撤必须显示基准，否则"回撤"这个词不可解释（`[待确认]` Q5） |
| ⑥ | 规则摘要 | 低 | 3–4 个 `标签 值` 对 + 「查看规则」 | 是读法说明，不是操作对象 |
| ⑦ | 权益迷你曲线 | 中 | 120px 高 sparkline，含目标线与失败线两条虚线 | 让"趋势"可见：进度条只说此刻，曲线说是在爬还是在磨 |
| ⑧ | 最近 5 笔 | 中 | 表格：时间 / 方向 / 手数 / 盈亏 / 标签 | 概览页只放"最近发生了什么"，完整分析去记录页 |
| ⑨ | 今日小结 | 低 | 3 个数：笔数 / 胜率 / 净盈亏 | 与记录页同口径，不新算 |

**明确不放在概览页**：六张统计图、逐笔明细、标签分布、来源筛选、成交明细、挂单列表。
`[建议]` 概览页的图**最多一张**（权益曲线），因为它回答"趋势"；其余图都在回答"为什么"，属于记录页。

### 1.4 语义区分（这一节比排版重要）

| 指标 | 定义 | 与谁容易混 | 界面上的处理 |
|---|---|---|---|
| 起始余额 | 账户开考时的资金 | — | 只在百分比说明里出现 |
| 余额 balance | 已平仓部分的现金 | 权益 | 小字、标签"余额"，永不做大字 |
| 权益 equity | 余额 + 未实现盈亏 | 余额 | 大字，标"权益"；浮盈时两者不同，要能解释 |
| 累计盈利 | 权益 − 起始余额（`[待确认]` 是否含浮盈） | 已实现盈亏 | 只用于进度条分子，不单独做大字 |
| 已实现盈亏 | 平仓累计 | 当日盈亏 | 第二层，悬停展开 |
| 未实现盈亏 | 当前持仓浮动 | 已实现 | 第二层，**持仓为空时显示 `$0.00`，显示空态而不是 0 的更少见的写法** |
| 当日盈亏 | 当日已平 + 当日浮动（`[待确认]` Q4 口径） | 累计盈利 | 大数字，紧跟"当日"二字，绝不简写成"盈亏" |
| 当前回撤 | 峰值权益 − 当前权益（追踪时）或 起始 − 当前（静态时） | 当日盈亏 | 横条 + 基准值一起展示 |
| 剩余空间 | 限制 − 已用量，**只取亏损侧，最小为 0** | — | 一句话"还能亏 / 还能回撤"；到 0 时文案变"已用完" |

`[建议]` 所有"剩余"都写成**自然语言 + 金额**（"还能亏 $570"），不要写成 `-$430 / -$1,000` 让人自己减。
减法是设计该替用户做的事。

### 1.5 关键交互

| 触发 | 结果 |
|---|---|
| 点账户 chips（顶部，若有多个账户） | 主卡整体换账户，URL 变为 `/?account=<id>` |
| 点「继续训练」 | 跳 `/train`，沿用该账户上次的实例；没有实例则弹起点选择 |
| 点权益曲线某点 | 悬停显示该日：权益 / 当日盈亏 / 回撤；点击跳记录页对应那天 |
| 点最近 5 笔的某行 | 跳到工作台并回放该笔（复用现有 `pendingPlaybackId` 机制） |
| 点「规则」 | 右侧抽屉，只读参数 + 标注哪些是 `[演示数据]` |
| 点状态徽章 | 抽屉：状态说明（何时、因何、差多少） |
| 悬停任意金额 | 一行口径提示（"含未实现盈亏，按最后一根收盘价"） |

### 1.6 状态矩阵

| 状态 | 界面表现 |
|---|---|
| **无账户** | 主区居中一张卡：两行说明 + 两个按钮「新建考核账户（演示）」「先自由研究」；不显示任何 0 值仪表 |
| **账户存在但未开始**（0 交易日） | 身份卡 + 全部仪表置灰并标"待开始"；主按钮「开始第 1 个交易日」；结论句 = "还没开始，先练一个交易日" |
| **进行中，风险充裕** | 正常态；两处横条用 `up`/`accent` 低饱和填充 |
| **进行中，接近上限**（用量 ≥ 80%） | 对应卡片加左边框 3px 琥珀 + 徽章「接近上限」+ 文字"还剩 $X"；结论句把该风险提到句首 |
| **当日失效** | 当日卡整块变灰 + 「今日已触线」；训练按钮变「查看结论」；账户状态徽章「当日失效」 |
| **已通过** | 账户卡置顶绿条「已通过 · 达标 $3,000 / 用了 12 个交易日」；进度条满格；训练按钮「查看结论」；仪表只读 |
| **已失败** | 红条「已失败 · 触发日亏限制 · 10-28 14:35」；两处横条按触发点定格；提供「查看结论」与「归档」（`[待确认]` Q9） |
| **数据缺失**（某日 K 线未抓全 / 权益无法计算） | 对应卡片显示 `—` + 一行"数据不完整，无法计算"；**不显示 0**，不猜 |
| **多个账户** | 顶部 chips 横向排列（≤6 个），超出折叠进「更多」；可选的排序：按创建时间（默认）/ 按风险紧迫度（`[建议]` 提供切换） |

## 2. 交易工作台 `/train`

### 2.1 页面目标

在**不打断看盘手感**的前提下，让用户随时知道"这一单在考核里意味着什么"。
现有画布（同步缩放/标注/下单/语音/机器人）全部保留，`[事实]` 见 `ReplayView.vue` 结构。

### 2.2 布局（在现有基础上只加两条）

```
┌─ 顶栏 48 ──────────────────────────────────────────────────────────────┐
├─ 账户风险条 36px（新增）───────────────────────────────────────────────┤
│ 账户A [进行中]  权益 $51,860  今日 -$430  日亏剩余 $570▮▮▮▮░░  │回撤剩余 $1,600│ 规则│
├─ 工具栏（现有 ChartToolbar）───────────────────────────────────────────┤
│                                                                        │
│                       画布（现有 ChartPanel，占满）                     │
│                                                    ┌ 下单浮窗（现有，可拖）│
│                                                                        │
├─ 语音条 40px（现有 VoiceTape）─────────────────────────────────────────┤
├─ 底部 Tab 204px（现有 TradeDock：模拟交易 / 操作记录）──────────────────┤
└────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 规格 | 理由 |
|---|---|---|
| 账户风险条 | 36px，`bg-panel`，四项等距：权益 / 今日盈亏 / 日亏剩余 / 回撤剩余，每项"标签 12px + 值 14px tnum" | 不动现有画布"只剩画布"的原则（`ReplayView.vue` 头注释）；36px 是可接受的代价 |
| 模式徽章 | 风险条最左，胶囊 | 离开概览后仍要能回答"这单算不算考核" |
| 剩余空间视觉 | 每个"剩余"后面跟一条 48×4px 的微型条（用量比例） | 数字需要参照，4px 条不抢空间 |
| 「规则」 | 风险条最右，小按钮 → 只读抽屉 | 训练中最常问"我还能亏多少"，规则是答案来源 |
| 主按钮 | 无 | 工作台本身是"已经在做"，加按钮是噪音 |

`[建议]` **不**在工作台里放权益曲线或交易统计。工作台的唯一任务是看盘和下单；
一旦塞进统计，画布高度会继续被挤压，而这块屏幕的价值全在画布。

### 2.3 信息层级

1. **最高**：K 线本身（现有）。
2. **次高**：账户风险条的四个数字，尤其"日亏剩余"与"回撤剩余"（越线就意味着整场考核结束）。
3. **再次**：当前持仓/挂单（现有画布与底部 Tab）。
4. **最低**：账户名、模式徽章、规则入口。

### 2.4 关键交互

| 触发 | 结果 | 备注 |
|---|---|---|
| 揭示下一根（→ 键 / 按钮） | 现有行为；平仓后风险条数字更新 | 数字必须由后端广播驱动，前端不自行累加（P4） |
| 平仓成交 | 风险条闪一次高亮（1.5s），`当日盈亏` 与两处"剩余"变化 | 闪动是提示"数字变了"，不是庆祝 |
| 当日已用风险 ≥ 80% | 风险条左侧出现琥珀竖条 + 文案"今日已用 82%" | 文字 + 颜色双通道（P3） |
| 当日触及限制 | 风险条变红条 + "今日已触线 · 本日交易结束"；下单按钮禁用并给原因 `[待确认]` Q4 | 是否硬停由规则决定 |
| 切换账户（顶栏） | 有持仓时确认，无持仓直接切；切走不结束实例 | 见 `user-flows.md` §8 |
| 进入回放态（从记录页来） | 风险条置灰为"历史回放 · 不影响考核" | 回放是在看过去，不能改账户 |

### 2.5 异常与空状态

| 情况 | 表现 |
|---|---|
| 未选账户，直接进 `/train` | 顶部一张选择面板（复用现有 `InstancesMenu`）：继续上次 / 最新 / 随机开盘 / 指定时间 |
| 无任何 K 线数据 | 提示"数据目录里还没有行情，先回菜单 1 抓取" + 说明页链接 |
| 断线 | 顶栏状态变红，风险条数值保留最后一次快照并标"数据可能过期" |
| 考核已结束（通过/失败） | 画布可看，下单按钮禁用 + 一行"该账户已结束（已通过），仅供复盘" |
| 多人在同一实例 | 观众看到风险条但下单按钮禁用（现有 `isOperator` 机制） |

## 3. 交易记录 `/records`

### 3.1 页面目标

回答"我这套做法长期怎样"。**页面本身不改版式**（`[事实]` 已有月历 / 当天 / 统计三层，八 KPI + 六图），
只加两样：账户维度、计入标记。

### 3.2 布局（改动点用 ★ 标）

```
┌─ 顶栏 48（新增全局导航）───────────────────────────────────────────────┐
│ 记录页第二行（现有 RecordsTopBar）                                     │
│  ★ [账户 ▾ 全部账户 / 账户A / 自由研究 / 未归类]  [来源 ▾]  [月份 ◀ ▶] │
├───────────────────────────────────────────────────────────────────────┤
│  Tab：日历 │ 统计                                                     │
│  ┌ 月历（现有）──────────────┐ ┌ 本月概览（现有）────────────────────┐ │
│  │ 有记录日按盈亏染色 ▲▼      │ │ 笔数 / 盈亏 / 胜率 / 盈亏比        │ │
│  │ ★格子角标：账户色点        │ │ ★「本月的考核归属」：账户A 12 笔 …  │ │
│  └───────────────────────────┘ └────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────────┘
```

| 改动 | 规格 | 理由 |
|---|---|---|
| ★ 账户筛选 | 下拉，选项 = 全部 / 各考核账户 / 自由研究 / 未归类 | 与现有"来源筛选"同排，复用同一套筛选状态传递方式 |
| ★ 计入标记 | 列表行的来源列旁加小标签 `计入考核` / `自由研究` | 让"这条算不算"无需推导 |
| ★ 日历角标 | 格子上一个 4px 圆点，颜色对应账户 | 多账户时一眼看出"这天练的是哪个"（`[待确认]` Q10 是否需要） |
| 不做 | 不改八 KPI 的数字口径、不改六张图 | 这些已有且经过使用验证 |

### 3.3 从记录进入单笔详情

沿用现状（`[事实]`）：
- 点日历某天 → `/records/day/:date`（八 KPI + 六图 + 逐笔明细）；
- 点明细某一行 → 回工作台回放该笔（`pendingPlaybackId`）。

`[建议]` 概览页/工作台里需要看单笔时，用**行内展开或抽屉**展示"这一笔的 4 个数"（方向、手数、开平价、盈亏），
不要新建"交易详情页"：单笔的信息量撑不起一个页面，而页面会诱使我们去填满它。

## 4. 统计复盘（`/records` 的「统计」Tab）

> `[建议]` **不做独立页面**。理由见 `product-overview.md` §6.3：它和交易记录读同一批数据，
> 现有实现已经在同一个页面的第二个 Tab 里。若你坚持独立页（例如未来要做多账户对比），
> 本节内容可以直接搬成一个路由，不需要重新设计。

### 4.1 页面目标

回答"我的问题在哪"：是胜率低、盈亏比差、还是某类单子（某标签/某时段/某方向）在持续亏。

### 4.2 结构（自上而下）

```
筛选条（账户 / 来源 / 标签多选 / 时间范围）
① 汇总条：累计盈亏 · 权益曲线（★含目标线与失败线）· 最大回撤（面积阴影）
② 三栏对比：多空对比 · 按标签对比 · 按星期/时段对比
③ 分布：每笔盈亏分布（柱）· 持仓时长与盈亏（散点）
④ 逐笔表（可排序，行可点回放）
```

| 区块 | 数据来源 | 说明 |
|---|---|---|
| ① 累计曲线 | 现有 `aggregate()` 已算 | ★ 新增两条参考线：目标线（账户目标金额，从起始累计）与失败线（起始 − 回撤上限） |
| ① 回撤 | 现有"最大回撤" | 用面积阴影标出回撤区间；悬停显示起止日期与幅度 |
| ②③④ | 现有六图 | 不改 |

`[建议]` **统计页不显示考核状态徽章**，只显示"这些数据来自哪个账户"。考核状态属于概览，
在两个页面同时展示会让人以为是两个不同的状态。

### 4.3 空状态

| 情况 | 表现 |
|---|---|
| 无任何记录 | 一句"还没有交易记录，去训练里做一笔" + 按钮 |
| 筛选后为空 | "当前筛选下没有记录" + 「清除筛选」 |
| 账户刚创建 | 同"无任何记录"，但文案指明账户名 |

## 6. 页面与导航的关系（一张判断表）

| 功能 | 放哪 | 为什么不是别的地方 |
|---|---|---|
| 考核进度主卡 | 概览 | 它是首页的存在理由 |
| 两处风险空间 | 概览（大）+ 工作台（小） | 概览做决策、工作台做执行，两处都需要但要不同的力度 |
| 六张统计图 | 记录页统计 Tab | 回答"为什么"，不是"现在怎样" |
| 单笔详情 | 当天页 / 行内抽屉 | 信息量小，独立页会空 |
| 规则参数 | 抽屉 | 一次会话看一次 |
| 新建/归档账户 | 抽屉 | 同上；也避免误触 |
| 数据质量日历（现有 8765 分析页） | **不进新版前端** | 它服务于"抓取是否完整"，是运维视图，不是交易视图；`[事实]` 它是独立服务与独立页面 |
