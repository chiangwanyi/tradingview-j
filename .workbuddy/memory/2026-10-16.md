# 2026-10-16

## 新工程：tradingview-j —— TradingView 图表 WebSocket 抓取

用户目标：从已登录 Chrome 的 TradingView 图表页 F12 里那条
`wss://prodata.tradingview.com/socket.io/websocket?...&auth=sessionid`
抓出通信数据，最终形态是**持续实时入库**。

### 技术选型

- 选定 **CDP 接入已登录 Chrome**（复用会话、可主动发帧要长历史）。
  备选：Chrome 扩展猴补 WebSocket、mitmproxy 中间人。
- **关键事实（实测 + 官方文档确认）**：Chrome >= 136 起，给**默认**用户数据目录加
  `--remote-debugging-port` 会被静默忽略，端口根本不开。所以"关闭 Chrome 加参数重启"这条路无效。
  替代方案是 Chrome >= 144 的官方开关 `chrome://inspect/#remote-debugging`
  → 勾选 "Allow remote debugging for this browser instance"，可在**运行中的实例**上生效，
  无需重启/重新登录；但每次外部连接会弹一次授权框，且每个新浏览器会话都要重新勾。
  Chrome 版本 155，User Data 在 `%LOCALAPPDATA%\Google\Chrome\User Data`。
- 用户机器上没有 `web-access` 技能的 CDP Proxy 在跑，也没开任何调试端口。

### 实现

零依赖（Node 22.22 自带 `WebSocket` 与 `node:sqlite`）。文件：

- `src/cdp.mjs` —— 端口发现（读 DevToolsActivePort + 兜底扫 9222/9229/9333）、targets、CdpSession
- `src/frames.mjs` —— 协议层：`splitFrame` / `buildFrame` / `extractBars` / `toBar`
- `src/capture.mjs` —— 订阅 `Network.webSocket*` 落盘 NDJSON；`--hook-ws` 可注入发送器
- `src/ingest.mjs` —— 解码入库
- `src/store.mjs` —— SQLite，`(symbol, series, t)` 幂等 upsert + 周期众数反推
- `bin/tv.mjs` —— CLI：doctor/targets/capture/ingest/stats/export/send/eval
- `test/selftest.mjs` —— 15 项离线自测，全部通过

### 踩到的真实坑（重要，协议改版时别丢）

1. **心跳会直接贴在 JSON 负载后面**（心跳无 `~m~` 头）。最初"按 `~m~` 头切分取间隙"的实现会把
   `{"m":"heartbeat","p":[]}~h~7` 当成一段 → JSON 解析失败。必须用**正向扫描 tokenizer**。
2. 声明长度按字符算这件事**不保证**。长度对不上时退化为"切到下一个帧头之前"。
3. 抽 K 线**不硬编码方法名**，改成按形状找 `{ s: [ { i, v: [数值...] } ] }`，
   `du` / `timescale_update` / 未来新方法都能吃到。

### 状态

- 全链路打通并验证：`capture` → `ingest` → `stats` / `export` 跑通，库里 301 根 5m K 线
  （CME_MINI:MNQ1!，2026-10-14 23:45 → 2026-10-16 01:45）。自测 19 项全过。

## 实抓后的修正（同日晚）

用户勾选开关后（Chrome 只写 `DevToolsActivePort`，**HTTP 的 `/json/version`、`/json/list` 一律 404**），
接入层必须改成浏览器级 WS + `Target.attachToTarget` 子会话；老版 HTTP 发现接口已不可用。

三个原"待确认"项的答案：

1. **prodata 不压缩、不二进制封装**：585 帧全 opcode=1 文本，910 段 JSON 全部可解析，0 个 opaque。
2. **抓包里没有 `symbol_resolved`**，品种只能从图表页 URL 的 `?symbol=` 取。
3. **初始加载 300 根**（5m 图约 25 小时），要更长历史必须主动 `request_more_data`。

### 两个血的教训（都已写进 README）

1. **`lbs.bar_close_time` 不是每根 K 线的收盘时间**。它在整段抓包里只有一个取值
   （1792115700 = 图表右侧可视边界，TradingView 默认右侧留白），拿它减 `t` 会得到
   94200s / 93900s / 15m 这种随时间线性漂移的垃圾周期。我做离线自测时"凭空推断"它是 per-bar 的，
   还写了个通过的用例 —— 被真实数据打翻。**周期只能靠相邻时间戳众数差反推**（正确得到 5m）。
   教训：对协议字段语义的假设不要写进自测当事实，那会制造虚假的绿色。
2. **`clearInterval` 作用域写错 → 进程永不退出**。写成 `.finally(() => clearInterval(tick))`，
   `tick` 在 executor 外不可见，抛 ReferenceError 跳过 `browser.close()`，WebSocket 一直开着。
   现象是输出全空 + SIGTERM（未排空的 stdout 全丢），排查成本高。现已：计时器与 clearInterval
   同作用域 + 清理放 `try/finally` + CLI 出口加"stdout 排空后再退出"保险。

### 其他实测事实

- `Network.enable` **之前**已建立的 WebSocket，Chrome **不补发** `webSocketCreated`
  → 帧能收到但 `url` 为空。要拿连接 URL 必须 `--reload`。
- 帧的 `p[0]` 是 chart session id（`cs_gaSTXIAFy41H`）。
- 方法频次：`qsd`(665，报价非 K 线) / `du`(162) / `quote_*` / `create_study` / `study_*` /
  `timescale_update`(2) / `set_auth_token`(1)。
- `st1`/`st2` 是指标序列，用 `st` 键而非 `s`，不会被误抽成价格 K 线（已加回归用例）。
- 三条 WS：`prodata`（图表）、`pushstream/private_feed`、`pushstream/public`（通知）。
- 该图表周期 = **5 分钟**，t 为 Unix 秒，`v = [t,o,h,l,c,v]`。

## 需求转向：不是实时，而是"用回放把整条时间轴填满"

用户明确：**不用实时更新**，他要的是手动/自动切到各个日期，把指定标的的 5 分钟 K 线
尽可能完整地存到本地，用于学习研究。

### 核心发现：数据是按需拉的，靠"拨动可视范围"触发

图表只有在**可视范围走出已缓存的那一窗**时，才发 `request_more_data`，服务器回一段
`timescale_update`（实测每次 ~90~300 根）。实测拖 3 次 → `sds_1` 从 302 根涨到 578 根，
最早从 `10-14 23:45` 推到 `10-13 08:40`。

**所以不需要手动回放** —— 程序反复把图表往回拖就行。落地成 `tv backfill`。

  结算间歇 + 周末休市会被全报成缺失），改成**从数据自身学习"每个星期几的时段模式"**，
  再逐日比对。附带两节：⚠ 参照样本不足告警、以及**断档列表**（不做任何交易时段假设，

  `ingest` 加台账 `data/ingest-state.json` 做增量续入。

### 一次成功的回填（实测）

`backfill --max-steps 14` → 新增 1527 根，时间轴从 `10-13 00:10` 推到 **`10-05 11:00`**，
每步约 +122 根（约 10 小时）。结束后自动反向拖回视图。
覆盖度报告此时正确指出：周末 2 天空白、每日 21:00–22:00 结算间歇、
以及一个 8 小时的真空洞（`10-14 08:30 → 16:30`）。

### 新踩的坑

1. **series id 会随重连换号**：`sds_1` → `sds_2`。它是每条 WebSocket 连接自己发的临时订阅号，
   不是数据属性。结果同一根 K 线在库里留两行（内容一致）。对策：主键保留 series 保真，
   `coverage` 按 symbol 聚合，`export` 默认按 `symbol+interval+t` 收敛。
2. **"拖动没反应"要区分两种原因**。有一轮 backfill 报 0 新增，只发出 2 帧 ——
   说明拖拽压根没送达图表（后台标签页渲染被节流）。对策：每次拖动前 `Page.bringToFront`，
   并统计图表发出的 `request_more_data` 次数 —— "没发请求"和"已到边界"是两件完全不同的事。
3. **`makeWriter.close()` 内部已经关过 db**，外层再 `db.close()` 抛 `ERR_INVALID_STATE`。
4. 覆盖度报告在样本少时会偏乐观（每个星期几只见过 1 天时，模式≈照抄那一天）。
   已在报告里加 ⚠ 明说，不制造假绿灯。

### 关键设计决定

- **前端零构建**：Vue 3 in-DOM template（模板写在 index.html）+ Tailwind 4 browser build，
  两个库放 `web/vendor/`。无 npm、无打包、不联网可用。
- **自动回拉默认关闭**，这是避风控第一道闸。驱动器每次循环**重读 `this.settings`**，
  所以运行中能热改（`HOT_FIELDS` 里就地 `Object.assign`，不换对象引用）。
- **SSE** 推日志/状态/步进，`EventSource` 自动重连。
- **`check()` 必须是 async 且真的 await**：同步版会把 async 断言回调的 Promise 丢掉 → 假绿。
- **e2e 用独立无头 Chrome + 临时 profile + `TV_CDP_PORT`**，不碰用户正登录的浏览器；
  图表页用一个本机 URL `/fake/tradingview.com/chart/...` 冒充（`pickTarget` 按子串匹配），
  完全不依赖外网和登录态。

### 新踩的坑（都已写进 README）

1. **迁移时用旧快照回写索引，把刚登记的映射抹掉了。** `migrateLegacy` 在循环前 `loadIndex`
   拿快照，循环里 `fileForSymbol` 各自读-改-写 `index.json`，最后又用旧快照 `saveIndex` 盖回去
   → 迁移完索引空 `{"symbols":{}}` 而库文件都在。**读-改-写的接口不能在循环外缓存快照。**
2. **日历把「整日无数据」短路掉了**，正好抹掉了最该看见的洞（`if (!bits) return 全0`）。
   改成所有日子统一走 `expectedBuckets.has(sec)` 四态判定。
3. **覆盖度「根数」没去重**：series 换号让 2274 根报成 2576 根，断档还会看到一串 0 间隔。
   现在 `analyze()` 开头 `[...new Set(...)]`，`summarize()` 用 `COUNT(DISTINCT t)`，
   物理行数单独作 `rows` 暴露 —— 两者不等本身就是"发生过重连"的信号。
4. **`new URL().pathname` 不做百分号解码**，`CME_MINI:MNQ1!` 变成 `CME_MINI_MNQ1%21`
   → 404。要对每段 `decodeURIComponent`（带 try/catch，明文的 `!` 也吃不坏）。
5. **`Target.createTarget` 不接受 `width`/`height`**（Chrome 155 直接回
   `Target position can only be set for new windows`）。视口另用
   `Emulation.setDeviceMetricsOverride` 钉。
6. **月历画满整月 ≠ 整月都有明细**：`buildMonthGrid` 会给数据范围外的日子也造格子并标
   `out-of-range`，而 `calendarFor` 之前只在 `cal.days` 里找到才给 `focus` → 页面出现
   「标题说选中了 2026-10-01、正文还是"点左边日历里任意一天"」的自相矛盾。
   修法：范围外也返回 `focus`（`status='out-of-range'`），前端加一句解释文案。
7. **Tailwind 4 里未分层的普通 CSS 永远赢过分层 CSS** → `style.css` 只写结构性样式，
   绝不写 margin/width。且 preflight **不设 `font-size`**，必须显式写 `body { font-size: 14px }`。
8. 深色模式用 `html.dark`（0,1,1）压过 `:root`（0,1,0）覆盖变量，不靠顺序赌。
9. **Tailwind 4 会 tree-shake 主题变量（最阴的一个）。** `@theme` 里定义的变量，
   如果没有任何工具类实际引用它，就**不会输出到 `:root`**。`--color-accent` 正是这种：
   全站只有 canvas 和我自己写的 CSS 在用它，没有 `bg-accent` 之类类名 → 被删了。
   而 canvas 用 `getComputedStyle` 读变量，读不到拿到空串；`ctx.fillStyle = ''` 又**静默忽略**；
   更致命的是绘制代码里 `if (runColor && i > runStart)` 把空串当假值 → **整段"有数据"的格子被跳过**。
   症状：浅色模式下时间轴 2274 个「有数据」格子一个都没画、图例色块和直方图柱也消失，
   而深色模式看着完全正常（`html.dark { … }` 是手写 CSS，变量一直在 → 只坏了一半）。
   修法：`@theme static`（强制全量输出）+ `canvasPalette()` 逐项兜底 + 缺变量时 `console.error`。
   **发现方式值得记：写了一条"逐格采样 canvas 像素、与接口位图状态对账"的 e2e 断言。**
   光看截图只能看出"像是有点少"，看不出到底少在哪 —— 这条断言直接给出
   `counts:{0:1182, 1:0, blank:2274}` vs `expect:{0:1182, 1:2274, 2:0}`，一眼定位。
10. **canvas 里别用 CSS 的 `color-mix()`。** 它是 CSS 颜色 5 的能力，`fillStyle` 解析吃不吃
    取决于浏览器版本；而且当时那份数据里一根「应有但缺」的格子都没有，等于这段配色从未被验证。
    改用 `globalAlpha`（所有实现都有）。顺带把 run-length 从"比颜色对象"改成"比状态字符" ——
    同字符必然同色同透明度，就不会再卷进对象引用/空串假值这类坑。

### 测试分层（都离线可跑）

```
npm test                    # selftest + ui-selftest
node test/selftest.mjs      # 49 项：协议 / 存储 / 入库路由 / 覆盖度与日历 / 视图层 / 迁移
node test/ui-selftest.mjs   # 17 项：切出 app.js 里 createApp 之前那段 eval
node test/e2e.mjs           # 44 项：真后端 + 独立无头 Chrome，含几何/交互/深浅色/像素对账
```

**为什么必须有 e2e**：jsdom 没有布局引擎也没有 CSSOM，Tailwind 运行时注入的样式它一概读不到。
「两栏有没有并排」「开关是不是 46×26」「canvas 有没有被压成 0 宽」只有真浏览器答得了。
更进一步：**逐格采样 canvas 像素、和接口的位图状态对账** —— 光看截图只能看出"像是有点少"，
看不出到底少在哪。这条断言后来直接抓出了 Tailwind 主题变量被 tree-shake 的 bug。

e2e 里还有两条"守根因"的断言，别删：
- 「主题变量全都真的进了样式表」（防 `@theme static` 被去掉后静默复发）
- 「问题不在范围内要说清」+「点某天后占位文案必须消失」（防焦点面板自相矛盾复发）

同时 canvas 的布局常量通过 `window.__tv.layout()` 暴露给 e2e ——
DOM 里拿不到 gutter/rowH，重抄一份进测试就多一处会漂的副本。
