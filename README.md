# tradingview-j

一个仓库两块，**互不引用**：

- **Go 侧**（`main.go`/`internal/`/`web/`）：旁路抓你**本人已登录的 Chrome** 里 TradingView 图表页的 WS 帧，
  解 5 分钟 K 线落 CSV 并做本地复盘。零第三方依赖，产物 `tv-capture-v<版本>.exe`（`0.31.0`）。只**被动**监听。
- **Spring 侧**（`src/`/`webapp/`）：Go 版复盘系统的迁移目标，SQLite，端口 8791；下单撮合已接通
  （市价 / 限价 / 止损、跳空修正、手续费净盈亏），PF 考核判定已接进【下一根】：逐根判爆仓、日终结算、
  余额与亏损线随之更新，**达标当场平仓冻结、升级仍手动**。

# 一、Go 侧：抓取 + 复盘

## 跑起来

Chrome 里开 `chrome://inspect/#remote-debugging` → 勾 Allow → 打开带 `/chart/` 的图表页、周期切 5 分钟（Chrome
136+ 加 `--remote-debugging-port` 会被静默忽略，只能走这个开关）。需 Go 1.26+ 与 `go-winres`。

```text
build.cmd            :: 前端 + exe 一次做完（任一阶段失败即中断）· --no-web 只编 exe
./build-wsl.sh       :: 同上，但在 WSL2 里跑：前端在 ext4 镜像里编、Go 交叉编译到 windows/amd64
```

版本号只有 `VERSION` 一个来源（文件名 / exe 属性 / 横幅页脚三处），**升版本 = 改它再重跑 `build.cmd`**；
`.syso` 是编译期快照，别手改别提交。`web/dist` **不进 exe**，发布要连 `dist` 一起带走。

`build-wsl.sh` 里前端**不能就地编**：`web/node_modules` 是 Windows 的 pnpm 装的，只带 win32 原生二进制
（rolldown / `@tailwindcss/oxide` / lightningcss），Linux 上会报 `Cannot find native binding`，原地重装又会
弄坏 `build.cmd`。所以它把 `web/` 镜像到 `~/.cache/tv-capture-web` 去编，再把 `dist` 拷回来；Go 那步仍在
原地，exe 必须落在根目录（`outDir`/`rawDir` 相对 exe 所在目录展开）。

菜单三项：`1 启动抓取（录 CSV + 开分析页）` · `2 复盘（回放/标注/模拟交易/交易记录）` · `3 退出`。

**菜单 1**：等调试端口与图表页（没开就每 5s 重试），分析页在 `127.0.0.1:8765`；你只需往回拖图表，程序把帧
录成 CSV，`Ctrl+C` 先刷盘再关页面。分析页对数据目录**只读**（不建目录、不写索引、无写接口），每标的一张
月历显示当天根数、异常日**变淡不隐藏**。实时靠「写盘 → 比对磁盘指纹 → 重扫 → 页面每 2s 轮询」，**无推送**。

**菜单 2**：逐根回放 `data/` 的 K 线，画标注、做模拟交易。**有状态应用，但仍只读数据目录**（状态写 `state/`，
一个 CSV 都不改）：实例锚点与【下一根】、五种标注、挂单 + nATR 定手数、EMA20/ATR14/Doji/ZigZag、观众模式、
回放延伸、交易记录月历。改前端必须 `npm run build`。

## 配置 · 数据 · 结构

`config.json` 在 exe 同目录，**不接受命令行参数**，相对路径相对 exe 目录。常改 `matchUrl`、`symbol`
（留空自动识别）、`intervalSeconds`(300，**只收这个周期**)、`outDir`/`rawDir`、`webPort`/`replayPort`。

```
data/_symbols.json        标的名 → folder / tick / tickValue / commission
data/<folder>/<date>.csv  time,open,high,low,close,volume（时间列明文 yyyy-MM-dd HH:MM、本机时区、开盘时间）
state/ presets/ recordings/ raw/   复盘状态 · 绘图模板 · 录音 · 原始帧（都不入库）
main.go(只有 main+version) · cli(菜单,唯一 stdin reader) · capture(常驻) · cdp · wsclient · tvproto(分帧/抽K线)
ingest(周期反推/落盘) · store(CSV + 只读 scan) · webreport(分析页) · replay(实例/标注/撮合/记录) · strategy
```

分层按「**谁能 import 谁**」；`internal/` 保持扁平，入口不搬 `cmd/`（`.syso` 只链同目录包）；`web/` 用
Vue 3.5 + Pinia + Tailwind 4，K 线 Canvas 自绘、不用图表库。

## 不能让步的约定

- **标的名只认 `symbol_resolved`**，别在整帧里搜 `pro_name`（同一条 WS 上还有自选/报价的 `qsd`，带**别的
  品种**）。顺序：`config.symbol` → 序列绑定 → 会话内唯一 → 页面内唯一 → URL 猜；给不出结论就**先攒不落盘**。
  周期靠**相邻时间戳众数差**反推，按「会话 + 序列」分别投票；`lbs.bar_close_time` 是陷阱（可视边界）。
- **统计口径只有一份**（`store.Scan`）：根数/断档/应有根数/异常判定 —— 在 JS 里重算会出现两份口径，而**同一
  目录给出不同根数时用户没法裁决**。**「分析」不许写任何东西**，复盘也只用 `ReadDayRows`/`Catalog`。
- **前端预览、后端定稿**：除缩放/平移/十字光标没有操作在本地改状态，正式状态永远来自广播；唯一两边各算一遍
  的是 Ctrl 吸附（漂了会「松手后图形跳一下」）。EMA20/ATR14 后端算（**ATR 钉在 14**），Doji/ZigZag 留前端。
- **撮合规则只有一份**（`instance.go`），机器人走同一套；本根挂的单从**下一根**才撮合。**前端不算钱**，
  唯一例外是 nATR 定手数（每点价值必须 = `tickValue / tick`）；一键退仓**先平后撤**。
- **一条链路 + 一个写入口**：实时只有「写盘 → 指纹（名字+大小+修改时刻）→ 重扫 → 轮询」，别加推送；CSV 行
  格式只在 `store.readDayFile` 定义一次；网页版不许有算数字的代码（改格式同步 `format.test.cjs`）；存档是
  **快照不是日志**。
- 方向色只有一个语义（绿=涨/多/盈，红=跌/空/亏），只在 `--c-up`/`--c-down` 与 `CHART_THEME` 两处；**K 线蜡烛保持黑白**。

`go test ./...`（全离线）· `cd web && npm run type-check && npm run lint && npm run build`；前端改完要**用浏览器
真跑一遍**再看结论。抓取侧用假 CDP 服务端（`internal/wstest`）喂 `testdata/` 的真实抓包。**`build.cmd` 必须纯
ASCII + CRLF**、**菜单只能有一个 stdin reader**（都有测试拦）。

# 二、Spring 侧：服务端（当前实现）

`./mvnw spring-boot:run`，端口 **8791**、只绑本机；首次启动建 `./db/tradingview-j.db`，Swagger 在
`/swagger-ui.html`（springdoc 2.8.x）。版本号只一处：`pom.xml` 的 `<version>`。

**接口**

- **PF 模板**：`/api/pf-templates` 列表+增、`/{id}` 查改删；`PUT` 忽略 `stage`（阶段在链上）。
- **PF 账户**：列表（`?status=`）、增（`templateId`/`name`/**`symbolId` 三必填**）、查改删、`promote`、
  `fail`、`cursor`（推 `lastBarTime`，**只往前**）、`stages`。**没有改余额 / 重置 / 换标的**——余额只能由
  成交重算后追平；换标的等于换一条时间轴，那是重开账户。
- **行情（只读）**：`/api/bars/symbols`、`/api/bars?code=&time=`（上一交易日整天 + 截止 `time`，上一交易日
  按磁盘 CSV 算不是日历减一；**不落库不缓存**）· 实体抛的 `IllegalArgumentException` 转 400 · Swagger 的
  `UNWRAPPED_PACKAGES` 必须含 `org.springdoc`，否则文档页**白屏**。
- **历史记录**：`/api/history/audit-events`（分页，`page` 从 0 起、`size` 上限 200）、
  `/api/history/trade-records`（分页，摘要）。左菜单【操作记录】【交易记录】两个页面就是这两张表。
- **两个清空入口，各管各的**（都不可逆，前端两步确认）：
  - `DELETE /api/history/audit-events` —— 清 `audit_event`（我按过哪些按钮），返回删掉几行；
    **不动交易记录**（它锚在 `trade.seq` 上）。清完各账户 `seq` 从 0 重新开始。
  - `DELETE /api/history/trade-data` —— 清**交易信息那 4 张表**（我手上做过哪些单）：
    `trade_record_tag` → `trade` → `trade_record` → `trade_order`，返回
    `{orders,trades,records,tagLinks}` 四个数（分表返回是为了让用户核对删的范围）。
    **从叶子往根删**：标签关联和成交都指向 `trade_record`，先删记录虽然靠 `ON DELETE CASCADE`
    也不报错，但「删了几行标签关联」就成了不可知的级联副作用，账对不上。
    **不动 `trade_tag`**（标签字典）：清空删的是「哪条记录打了哪个标签」，不是标签本身。
    也不动 `audit_event`、账户本身（**余额是落库字面值，不会回退** —— 那是「重开账户」的事）、
    图形、语音、K 线 CSV。清完 `trade.seq` 从 1 重新开始；服务端不留持仓缓存
    （每次 `snapshot` 都重查这 4 张表），但**已经打开的交易页要刷新**才看得到空盘面。

**WebSocket `/ws`**（交易页唯一的写入通道，同端口、JSON 文本帧，`ws/` 包 6 个类：`WebSocketConfig` 挂端点、
`TradeSocketHandler` 只管连接与分发、`TradeDeskService` 是业务、`WsRequest`/`DeskSnapshot`/`EventMessage` 是线协议）

- 上行：`{"type":"hello","accountId":…}` / `step` / `ping` / `order_placed`（限价或止损） /
  `market_order`（市价即成交，可带 `stopDistance` 顺手挂保护性止损）/ `order_cancelled` /
  `order_moved` / `flat_all`。**连上不主动发东西**（身份只由 `hello` 给，连接本身不带身份，
  就没有「URL 写 A、消息写 B」的歧义）。下行：`snapshot`（只回发起方）/ `event{action,
  payload,by,seq}`（**广播给该账户全部连接，含发起方**）/ `error` / `pong`。
- **命令名 = 事实名**（`order_placed` 既能当「请挂单」发上来，也作为「挂上了」广播回来），
  唯二例外是 `step`→`bar_advanced` 和 `market_order`→`order_filled`（市价单一条命令产出一条事实，
  命令名不能和事实名同串）。**不认识的消息回 `error`，不静默丢** —— 静默丢弃会让「字段名写错」
  表现成「点了没反应」；`annotation_*` 目前就是这样明确拒绝的。
- 前端 `webapp/src/data/socket.ts` 自动重连（1s→15s）+ 重发 `hello`，收到 `snapshot` 就整块重建；
  **断线期间不缓存动作排队重发**（一条 `step` 重发会让账户一次多走一根，而用户只按了一下）。
- **【下一根】的链路**：`step` → `BarCursorService` 找当前那根之后的**第一根**（会跨日文件、
  会跳过缺失/空的日文件）→ `advanceCursor` 推账户 `lastBarTime` → **用这根 K 线撮合挂单**
  （`TradingService.match`）→ 写一条 `BAR_ADVANCED` → 广播。**顺序不能反**：先推账户再写流水，
  反过来的中途失败会留下「记了步进、盘面没动」的错位。没有下一根 → 回 `error`，按钮按
  `snapshot.hasNext` 变灰（**不是静默成功**）。
- **成交不另发一条 `order_filled`**：撮合结果直接并进那条 `bar_advanced`（`fills` = 这一根触发的）。
  拆成两条的话，前端会在「K 线到了、成交还没到」的那一帧画出错误的持仓线。
- 广播负载和 `audit_event.payload_json` 是**同一份**：`bar` 用画布口径 `BarView`（字段叫 `time`
  不是 `barTime`、没有 `ema20`）；挂单/成交/持仓用协议形状 `OrderView`/`TradeView`/`PositionView`
  （小写方向、`realizedPnl` 毛利 / `commission` / `netPnl` 三笔账），**发空数组不发 null**。

**数据模型**：**PF 账户是记账数据的唯一聚合根**，K 线不进库。三层 = **日志层 `audit_event`（唯一写入点、
append-only、每行带 `symbol_id` + `bar_time`）→ 快照层（当前值）→ 投影层 `TradeRecord`（`trade.seq`
区间 + 独立摘要）**。`Trade` 是账务唯一真相（持仓/盈亏由它重放），`trade.seq` 定同一根内先后；
`Drawing`/`AudioClip` 只挂 K 线、**不带 `account_id`**，不参与账户统计。

- **删账户删「账户本身」，不删盘面数据**：子表 `account_id` **NOT NULL 但不加外键**（SET NULL 抹归属、
  CASCADE 连带删、RESTRICT 让账户永远删不掉），闸门在实体工厂 + `requireActive`/`requireTradable`。
  **唯一的连带删除是 `prop_firm_stage_log`**（由 `PropFirmAccountService#delete` 显式按 `account_id` 删）：
  它描述的是账户自己的时间轴，账户没了既无归属也读不到；成交/挂单/交易记录是盘面事实，删了等于篡改复盘，
  必须留。代价：**删账户就没有「考出来的还是直接开的」这条痕迹了**，要留档先 `GET /{id}/stages` 导出。
- **交易记录的开 / 闭只有一条判据：成交后净头寸穿越 0**（`TradingService.keepRecord`）。一键退仓的平仓
  就是一笔反向市价成交，走的是同一条路，**没有「主动退仓」这个第二分支**；同向加仓 / 部分平仓只刷手数，
  不动起点和开仓价。区间锚在 `trade.seq` 而不是 `audit_event.seq` —— 撮合成交并进 `bar_advanced`、
  没有自己的事件行，两个序号序列本来就不对齐。**反手是「闭旧 + 开新」，两条记录共享那一个 seq**
  （一笔成交在事实上就是平掉旧仓 + 开新仓两条腿，`realizedFor` 只把平仓那半算盈亏）。
  一账户最多一条未闭合，由 `ux_record_open`（`WHERE closed = 0` 的 partial unique index）兜住；
  **闭合时必须 `saveAndFlush`** —— Hibernate 同一次 flush 里 insert 排在 update 之前，不先落库新记录会撞索引。
- **反手的那个 seq 上，手续费要按腿切**（2026-10-31）：`trade.commission` 是按整笔成交量收的，
  `trade_record.commission` 只累加**平仓腿**那部分（`手续费 × min(|成交前持仓|, |成交量|) / 成交量`），
  开仓腿那部分归新记录，两半相加恒等于成交上那个数（第二半用减法，不重复舍入）。
  **不要用 `seq BETWEEN start_seq AND end_seq` 去 SUM 毛利或手续费** —— 共享的那一个 seq 会被两条记录
  各算一遍，单条偏、全账户合计却对得上，是最难发现的一类偏差。摘要列才是账。
  `trade.trade_record_id` 同一轮开始回写：**反手那笔归旧记录**（与 `realizedPnl` 全额归旧记录同口径）。
- **标签是独立实体，不是记录上的一个字符串**（2026-11-01 拆表）：`trade_tag(id, name, color)` 是「我有
  哪些标签」这本册子，`trade_record_tag(record_id, tag_id, tag_index)` 只是关联。之前把名字/颜色直接写在
  关联行上、主键 `(record_id, tag_index)`，同一个「追单」在 20 条记录里就是 20 行互不相关的数据 ——
  改颜色要改 20 次，也答不出「我一共有哪些标签」。
  `name` 上有唯一索引 `ux_tag_name`（同名会让「按追单筛选」筛出两堆）；`record_id` **级联删**（记录没了
  记号没有附体），`tag_id` **RESTRICT**（被记录引用时不许删，得先摘干净 —— 删标签不能一次误点就抹掉几十条
  历史判断）；`tag_index` 只是显示顺序、不在主键里。`TradeRecord.tags` 是 `@ManyToMany` 且**不级联 REMOVE**。
  本次拆表**手删**了旧 `trade_record_tag`（当时 0 行），备份在 `db/tradingview-j.db.bak-20261101-tag-model`。
- **进度不单独存**：= 该(账户,品种)最后一条 `audit_event.bar_time`。**不做撤销**（append-only 只能补偿）。
- **全库没有「K 线下标」字段**：**下标是位置，时间是标识** —— 重抓/补一根/删坏行会让下标悄悄指向另一根
  且不报错。保留的只有序号 `*.seq` 和 `Anchor.offset`（「延伸 40 根」是意图）。**别加回来。**
- **账户绑定唯一标的**：`symbolId` 建户必填、无 setter；起点 `startBarTime` + `startDayFile`，建户时在**该标
  的目录**里随机抽一份日文件、取当天 **09:00 及之后第一根**（抽不到就不建账户）；`lastBarTime` = 盘面停在哪
  一根，**只增不减**（否则每次打开都全揭示 = 提前看到未来）。

**PF 考核**：三阶段 `EVAL → FUNDED → PAYOUT` 挤在同一行账户上，历史在 `prop_firm_stage_log`；升级时余额被
拨回账户规模，所以**余额不能由成交反推**，每阶段各存 `base_balance`。

- **交易日 `[D 06:00, 次日 04:45)`**，04:45–06:00 禁交易；23:55 日历日强平、04:50 结算收尾。不做夏冬令时，
  `PropFirmClock` 是唯一实现。**逐根判爆仓**：浮亏用本根极值（多单 low / 空单 high），**等于也算失败**，
  亏损线只在日终上移 —— 而「日终」是**这一天走完**那一刻（推进到本交易日最后一根就结算，
  不必等下一根，见 `PropFirmJudge#settleIfDayOver`），跟 Apex「market close 算、next session 生效」
  同一个口径。**一致性 50%**：`目标 = max(模板目标, 单日最大净盈利 / 0.5)`。
- **余额逐笔变、亏损线只在日终变**（两套时钟，见 `PropFirmSession`）。`service/PropFirmJudge` 把
  session 接到盘面上：每次用到就从**本阶段起点**重放一遍（十几毫秒，换来永远和成交对得上），
  结果写回 `balance` / `eod_peak_balance` 两个缓存列，并作为 `PfView` 挂在快照、`bar_advanced`、
  `order_filled`、`flat_all` 四条消息上 —— **前端一处钱都不算**，包括亏损线（EOD 追踪有一道
  `trailing_lock_level` 冻结水位，自己算会算虚高）。
- **达标即冻结**：日终判出达标 → 当根市价平仓 + 撤掉全部挂单 + 拒绝新单（`requireNotFrozen` 现算，
  **不存标志位**），用户到账户页手动点「升级」。
- **撞线即收摊**：判出失败那一刻**先**市价平掉持仓 + 撤光挂单（`TradingService#closeOut`，和「一键
  退仓」共用同一份实现），**再**置 `FAILED` —— 顺序不能反，失败之后就不能下单了，留个仓位就永远平不掉。
  平仓那笔成交并进撞线那一条 `bar_advanced`，不另发 `flat_all`。
- **失败≠冻结整页**：`FAILED` 只关「下单」这一件事（`requireTradable` 现算）。看盘、画线、录音、
  改盘面时间（【下一根】）、撤单、退仓一律照旧（`requireExisting`），因为考挂那一场本身就是复盘素材。
- **手数分档只属于 FUNDED**（利润 0→20 / 1000→30 / 2000→40），EVAL 固定上限 40。`PAYOUT` 只是「不能再
  下单」，账户仍 ACTIVE → `Status` 只有 ACTIVE / FAILED。

**约定**：金额一律 `BigDecimal`（列 TEXT）· 时间价格用明文/毫秒整数 · **能算的不存** · 快照优于引用 ·
主键 UUID · **余额只能由 `syncComputed` 追平**（旧的 `applyNetPnl` 已删，增量那条会漏开仓手续费）· 枚举存常量名。

**手续费**：`symbol.commission`（**每手每边**，**NOT NULL**：`0` 免费 / `>0` 收费，没有「没配」第三态），
成交那刻快照进 `trade`；「往返乘 2」只有 `roundTripCommission` 一处回答。`_symbols.json` 启动时由
`SymbolSyncService` upsert（内容没变不写，库里有清单里没有只 warn 不删）。⚠️ Go 侧会**整体重写**该文件，
**用户手写的每个键都必须有对应 struct 字段**，缺 `commission` 的标的进不了库。

**改表必须重建 `./db/`**（`ddl-auto: none`；`schema.sql` 全是 CREATE IF NOT EXISTS，删表只能手 `DROP`），
旧库改名 `db/*.bak-日期-原因` **别删**。「测试全绿」不等于「旧库能用」。
**例外：纯追加列可以用 `ALTER TABLE ... ADD COLUMN`**（SQLite 只支持加列/改名这几种形式），不用重建。
2026-10-31 新增 `trade_record.commission` 就是这么加的：

```sql
ALTER TABLE trade_record ADD COLUMN commission TEXT NOT NULL DEFAULT '0.00';
```

加了列还要**按腿回填历史值**（不是 `SUM(trade.commission)`，反手那笔会被算两遍），
做法见 `archive/20261031-record-commission/migrate.py`（先备份成 `db/*.bak-日期-原因`，可重复执行）。

## 构建与版本号

版本号**只有一个来源**：根目录的 `VERSION`（一行，例如 `0.21.0`）。它要出现在三处 ——
**产物文件名**、**exe 文件属性**、**程序内**（横幅 / 网页页脚 / `meta.version`）——
这三处分别由构建脚本、资源编译器、Go 编译器产生，任何一处人手填都会漂。所以：

| 落点 | 谁写进去的 |
|---|---|
| 根目录 `VERSION` | 人（唯一需要动手的地方） |
| `tv-capture-v<v>.exe` | `build.cmd` 的 `-o` |
| exe 属性里的文件 / 产品版本 | `go-winres --file-version` / `--product-version` |
| 横幅 / 网页页脚 / `meta.version` | `go build -ldflags -X main.version` |

**升版本 = 改 `VERSION` 那一行，再跑一次 `build.cmd`。** 光改 VERSION 不重新构建没有用：
`rsrc_windows_amd64.syso` 是**编译期快照**，每次由构建脚本重新生成，不要手工维护它、
也不要提交进仓库。`version_test.go` 把这几条钉成了断言（含三步齐全、`build.cmd` 必须是纯
ASCII + CRLF、`winres\winres.json` 里不许出现版本号键）。

产物**就在根目录**，和 `config.json` / `data\` / `raw\` 并排。注意 `outDir` / `rawDir` 全是
**相对 exe 所在目录**展开的：换个目录放 exe 就等于换一份数据目录。

状态行原地刷新，不刷屏。同时开多个图表标签页会**全部挂上**，各自独立录；某一个挂掉不影响其它。

抓取起来的同时，末尾还会打一段分析页的信息（地址、端口、同步间隔），浏览器随之打开：

```
  网页版分析 · D:\tradingview-j\data（和抓取一起起，Ctrl+C 时一起停）
  地址      http://127.0.0.1:8765/
  页面每 2 秒自动同步一次，抓到的 K 线会自己出现在日历上（不用刷新）。
```

### 分析页（抓取过程中自动打开）

对数据目录做一次**只读**扫描（不建目录、不写索引、不改任何文件），把结果摆成浏览器里的月历。
服务只绑 `127.0.0.1`，**没有任何能改数据的接口**。

- 每个标的一个月历，格子中间的大数字是**当天的 K 线根数**；标红 = 根数与该星期应有的根数不符
  （或文件有坏行 / 读不了），标黄 = 当天各标的根数不完全相同，灰格 = 没数据；
- **点某一天**出当天明细：根数、应有根数、首根 / 尾根，以及**每一段断档的起止时刻**；
- 工具条按月翻页，**所有日历一起翻**；「全部标的按日期合计」也是一张月历；
- 两个勾选框把「异常日」或「数量不一致的日」**高亮**出来（变淡、不隐藏）；
- 顶部的「统计口径」可以展开，里面写着每条判定的含义和「星期几应当有多少根」那张表。

统计量全部由 `store.Scan` 算好再送过去，网页端只做排版。**它和抓取同生共死**：
在程序窗口按 `Ctrl+C` 停止抓取时一起停（先刷盘、再关服务），页面从此读不到数据、
顶部会提示重开一次「启动抓取」。

**为什么是实时的 —— 三层各管一段，中间没有「推数据」的通道：**

| 层 | 做什么 | 频率 |
|---|---|---|
| 抓取（`store`） | 内存里按 `(标的, 日期)` 累积，把脏掉的日文件整体重写（tmp + rename） | 每 `flushSeconds`（默认 1 秒） |
| 服务（`webreport`） | 先比「磁盘指纹」（每个日文件的名字 + 大小 + 修改时刻）：一样发缓存，不一样重扫 | 每次请求 |
| 页面（`app.js`） | 每 `meta.pollMs`（2 秒，服务端给的）重新拉一次 `/api/analysis` | 2 秒，标签页在后台时暂停 |

所以链路是「磁盘变了 → 指纹变了 → 下一次请求重扫 → 格子上换个数字」，没有 WebSocket、
没有共享内存、也没有第二个统计口径 —— 页面看到的永远是磁盘那一刻的样子，只是看得勤。

**为什么每两秒重扫一次也不贵**：`store.Scanner` 记住每份日文件上次算出来的摘要和当时的
「大小 + 修改时刻」，重扫时只重新解析变过的那几份。44MB / 3300 份实测：全量 1.2 秒 →
没变化时 6 毫秒，抓取过程中通常只有当天那一两份文件需要重读。磁盘完全没动时服务端连扫都不扫，
直接发缓存（首屏几百毫秒）。

**页面这边**：换快照不会打断你 —— 正在看的那一天、翻到的那个月都会保住；「实时刷新」勾选框
可以关掉自动同步，顶部的「重新扫描」按钮走 `?refresh=1`，跳过指纹无条件重扫。

### 菜单 2：复盘

起一个本地网页，把 `data/` 里的 K 线**逐根回放**，在图上画标注、做模拟交易。
和菜单 1 那个分析页的区别：那个是**只读报表**，这里是**有状态的应用**（实例、标注、挂单、成交写进
`state/`），但它**仍然只读数据目录**，一个 CSV 都不会改。

- 右上角「标的与实例」→ 选标的（时间留空就随机挑一根）→ 新建实例：铺出这一刻及之前 400 根
  K 线，之后的行情逐根揭示；同一面板里能进入 / 删除实例；
- 【新增实例（最新）】是同一个面板里的第二个入口：不用填时间，直接把锚点定在 `data/` 里
  **最新的那一根 K 线**上（最后一个有数据的日文件的最后一根，跳过周日/停市留下的空文件）。
  因为锚点已经在数据末端，它之后没有可揭示的行情 —— 这一屏是用来看「当下这一屏」的，
  要往前推演还是选一个更早的时间点；
- 【新增实例（开盘）】是第三个入口：**随机挑一个交易日**，锚点定在那天的第 1 根 K 线（开盘根）上。
  为什么是随机的：锚在最后一天就等于【最新】（之后没有行情可揭示），而同一个开盘反复练没有意义。
  首尾两天不参选 —— 首日没有历史，尾日之后没有行情。判据是**停盘缺口**，不是「0 点」：
  日盘按美国时间开，北京时间在 6 点（夏令时）和 7 点（冬令时）之间跳，所以「哪一天从哪根开始」
  只能按「和前一根之间隔了 65 分钟」来认（`internal/replay/session.go`）。
  它后面还有一整天（以及之后几天）可以逐根推演；
- 【下一根】揭示下一根 K 线，同时用这根的最高 / 最低价撮合挂单；键盘 **→（右方向键）**
  是同一个动作（长按不连发：一次按键只走一根）；
- 工具条上还有【下一天开盘】：一步跳到下一个交易日的第 1 根（同一个缺口判据），
  中间那一夜是**逐根撮合**过去的 —— 夜里挂单照样成交、止损照样触发，跳过就等于把这些成交抹掉。
  它不占步进的手感：界面上只多出一步，但画布会把那一夜的 K 线一起补齐；
- 标注：趋势线 / 射线 / 矩形 / 箭头线 / 斐波那契回撤。**【射线】单击即完成**，其余两次单击；
  按住 **Shift** 画水平线、按住 **Ctrl** 吸附到 OHLC；坐标严格是「K 线时间 + 价格」；
  点一下图形就能改（拖端点、拖线身、`Del` 删除），不用切模式；选中之后会出现
  **同类模板条** —— 点一下就换样式（只换外观、不动端点，跨类型换不了）。
  它浮在画布左上角、不占工具条高度：选中一个图形不该让画布跟着变矮（画布一变尺寸，
  缩放就得重算一遍，用户调好的取景会被抹掉）；
- 画布左上角是【K 线数据栏】：指针压在哪根上，就显示那根的 **开 / 高 / 低 / 收 · EMA20 ·
  ATR · 涨跌**。ATR 用的是【指标 ▾】里那套 Length / Smoothing（副图关掉也照常显示，
  关的只是画不画折线）；**涨跌**是「收盘 − 前一根收盘」的**价差**（不是涨跌幅），正绿负红，
  第一根没有前收就写 `—`；
- 任意价格处**右键**就地挂单：单型按价格相对现价的方向自动定；挂单是**两对** ——
  上一对用手填的手数，下一对用 **nATR 倒推出来的手数**（算不出来时置灰，不拿 1 手冒充）；
  菜单里还能**复制价格**和**复制时间**（时间原样照抄数据里的 `time` 字段，不加星期、不换格式，
  贴进表格 / 日志就能逐字对上）；「移除 N 个绘图」连点两下确认；
- **有仓位时，对手单旁边会显示这块挂单成交后的盈亏**（例如多头 2 手、在 20050 挂卖 2 手 →
  `+100$`；在 19980 挂卖 3 手 → 按**仓位**只算 2 手，`-40$`）。同方向的挂单是加仓，
  加仓的盈亏取决于将来在哪儿平，所以不显示。口径和后端算平仓盈亏的一模一样
  （`(平 − 开) × 手数 × 每点价值`），只是把「将来」换成「这个挂单价」；
- 挂单线可以**上下拖改价**、右端「×」直接撤单；平仓虚线悬停看这笔交易，停 3 秒固定到画布；
- 模拟交易：限价 / 止损 / 市价，**不设止损止盈类型**（要止损就挂一张 `stop` 单），
  自由模式没有初始资金、不计点差 / 滑点；**手续费是全局的**（见下面「手续费」一节）；
  下单浮窗里还有**市价退仓并取消所有挂单** ——
  一条消息让服务端先撤光挂单、再按现价平掉整个仓位；
- **nATR 定手数（以损定仓）**在下单浮窗里：填两个数 —— **n**（止损距离 = n × ATR）和
  **最大亏损**（美元），面板当场给出「每手亏多少 → 下几手」，然后是两个
  【市价买入 x 手】/【市价卖出 x 手】按钮。例：ATR = 19.24、n = 10 → 192.4 点；MNQ 每点 $2
  → 每手亏 $384.80；上限 $2000 → 5.197 → **5 手**（实际亏 $1924）。
  手数是**四舍五入到最接近上限的那个整数**（不是向下取整）：需求的口径是「最多亏这么多」，
  所以 5 手亏 2100 优于 4 手亏 1800，允许略超；只有 1 手都亏不起时才必然超，那时实际亏损标红。
  ATR 用的是【指标 ▾】里那套 **Length / Smoothing**（副图没开也照样算），n 与最大亏损记在本机。
  按下这两个按钮时**止损是自动挂的**：服务端在成交的同一个动作里，按「成交价 ∓ n×ATR」
  （也就是最大亏损所在的那个价格）挂一张**同手数的 reverse `stop` 单**，面板上会预告两个
  方向各自的止损价。所以一条消息发出去，别人看到的就是「有仓、同时有保护」；
  止损价由后端按它自己的成交价算（不是前端拿现价去减），跳空 / 四舍五入时不会差一跳；
- 指标（EMA20 / ATR / Doji X + Blue ZigZag）收在工具条的【指标 ▾】下拉框里，按钮上的数字是
  「现在开着几个」；关掉下拉框它们就只剩这两三个字，不再占掉半行工具栏。
  **ATR 画在价格区下方一条独立副图里**（v0.22.0）：折线 + 左上角图例/数值 + 右轴上下界，
  纵轴自动贴合可见区间。v0.23.0 起参数可调，和 TradingView 内置的
  「Average true range」一一对应：**Length**（默认 14）+ **Smoothing**
  （RMA / SMA / EMA / WMA，默认 RMA），左上角图例写成 `ATR 14 RMA` 这样一眼能看出用的是哪一套；
  参数记在本机，下次打开还是这一套。口径对齐脚本的几处细节：TR 第一根用当根振幅
  （`ta.tr(true)`）、四种平滑都在第 Length 根才出第一个值、RMA 的系数是 1/n 而不是 EMA 的 2/(n+1)。
  副图里没有价格坐标，所以右键下单、单击画图在那儿都不生效；
- **Bar Count**（在【指标 ▾】里，默认开着）：在每根 K 线的**最低价下方**标出「这是当天的第几根」，
  用来两根一组读盘中节奏。口径三条：**每张 CSV（每个交易日）从 #1 重新数**（实例加载的每一天都是
  整日文件，所以 #1 就是那个 CSV 的第一行，00:00 或 06:00 那一根）、**只标单数**（1、3、5…）、
  数完一张表下一天回到 #1。数字**颜色可调**（取色器，默认蓝），和别的指标一样只影响你自己的屏幕：
  不发消息、不进存档；
- 多人：第二个标签页进来就是**观众**，能收广播但不能操作；「交还 / 接管」切换操作者，
  操作者关掉页面会自动释放。这是后端的硬约束，不是把按钮置灰；
- 底边是「模拟交易 / 操作记录」两个 Tab；正在回放时 Tab 条上会多出
  一枚红色的「回放中 x/y」，点它就回到播放器（平时不占位 —— 没在回放时它没有能点的事）。
- 回放到最后一步时，播放器上多一枚【＋ 加载下一根】（青色）：点一下就把记录末尾之后的一根真实
  K 线演出来（v0.27.0）。它是**写进记录的一步**（步进条上是「加载K线」），所以能跳回去、能重放、
  重开一条记录也还在；数据目录走到头时按钮变成「数据已到最后一根」。
  停在这种新加载的 K 线上时，播放器上多一条「延伸的 x 这根 · 🎙 在这根上录音」——
  录下来的语音存进这条交易记录（每根最多 9 条，可【清空本根】），回放到那一步就响。
  之所以只能在最后一步加载：中间插一根会让后面所有步的 K 线时间和游标错位，
  画在上面的图形、挂在上面的话会跑到别的柱子上。
- **交易记录是独立页**（底边和顶栏都有入口），v0.21.0 起首页是**月历**：**按「记录日」排**——
  你哪天做的就落在哪天（今天补做 2025 年 1 月、5 月、8 月和 2026 年 6 月、9 月的行情，
  五笔全算今天），**不是行情走到的那一天**；每笔各自的行情时间写在明细里。
  有记录的日子按盈亏染色（绿赚红亏，亏损日还带 ▼、盈利日带 ▲ —— 只靠颜色的话色觉障碍和
  灰度打印都读不出来），没记录的日子置灰，有记录的格子上写「N 笔 / ±X$」；右侧是本月概览和
  「本月是谁在做」（手动 / 各策略）。
  点有记录的格子进**当天详情**：KPI（开仓笔数、累计盈亏、胜率、盈亏比、最大回撤、平均持仓、
  单笔最佳最差、连胜连亏）+ 六张图（累计盈亏与回撤、胜率构成、每笔盈亏与累计、盈亏分布、
  多空对比、持仓时长与盈亏）+ 逐笔明细，**点任意一行就回到画布逐格演这一笔**。
  **来源筛选**在首页第二行（全部 / 手动 / 机器人，机器人再按策略细分），日历、当天详情、
  统计三处共用同一份选择；**标签**在明细里点「+ 标签」就能打：名字和颜色自己定、最多 8 个，
  存进记录目录的 `tags.json`，下次打标签时面板会列出用过的标签及次数。
  切到**统计** tab 是所有记录的汇总（累计曲线同样按记录时间排），并可按标签筛选（多选为「同时含」）。
  这一页**只做汇总与排版**，每一笔的钱仍然来自后端 stats。

### 手续费（v0.31.0 起全局生效）

按**品种、按成交边**收，自由模式和考核账户走同一条路：

| 标的 | 每手每边 |
|---|---|
| MES | \$0.50 |
| MNQ | \$0.50 |
| MGC | \$0.80 |

- 费率表在 `internal/store/timebar.go` 的 `commissionRules`（和 `tickRules` 同一个套路：
  标的名里含 `MES` 就命中）。**认不出来的标的不扣**——宁可显示「没有这笔费用」，也不猜一个数。
- 开仓、平仓**各收一次**，按实际成交手数；反手一笔（同时平 3 开 2）只按 5 手算一次。
- 扣在**唯一的记账点** `applyFill` 上，并且直接减进 `Trade.RealizedPnl`，所以那个字段是
  **净额**。下游（持仓面板的已实现盈亏、实例列表、交易记录统计、回放）拿到的天然是净额，
  不存在「毛额/净额」两本账。
- 因此**开仓那一笔成交的 `realizedPnl` 是负数**（= -手续费）。这不是 bug，成交本身就要花钱；
  成交流水里有单独的「手续费」列用来解释它。
- 费率在建实例时查一次就冻在实例上（写进 `meta.json` 的 `commissionPerContract`），
  改费率表不影响已经建出来的实例。
- 画布上的逐批平仓虚线（`closedLots`）仍然只按价格归因，所以它们的和会**比重仓累计盈亏多出
  手续费那一点**——两处口径不同，刻意如此。

### Prop Firm 考核账户（v0.31.0）

在【标的与实例】面板里选模板、点【新建考核账户】：后端**随机挑一个交易日的开盘首根**建户
（不是「现在」），账户规则在那一刻**快照冻结**。交易照常自动存成交易记录。

首批模板 **LucidFlex 50K**：

| 阶段 | 规则 |
|---|---|
| `EVAL` | 初始 \$50,000；盈利目标 \$3,000；回撤 \$2,000（日终追踪）；日终权益到 \$52,100 后亏损线锁在 \$50,100；当日净盈利达 \$1,200 后当日禁止再开仓；MES/MNQ/MGC 每品种最多 40 手 |
| `FUNDED` | EVAL 达标后**下一个交易日开盘**切换，余额重置为 \$50,000（EVAL 的盈利不转入）；需要 5 个盈利日（不必连续）、每个净赚 ≥ \$150 |
| `PAYOUT` | 攒够盈利日即转出金记录，金额 = 全部净盈利；**终态，只能平仓** |
| `breached` | 权益触及亏损线，**终态，只能平仓** |

口径（每一条都在 `account_test.go` 里钉住）：

- **余额是算出来的**：`初始 + (已实现盈亏 - 阶段基线)`。没有第二个余额字段，所以不会出现
  「余额和成交对不上」。手续费已经在已实现盈亏里扣过，不重复扣。
- **亏损线**：`floor = min(max(初始, 日终权益峰值) - 2000, 50100)`。日终权益到 52100 时
  `min(52100-2000, 50100)` 自然等于 50100，锁定不需要特判。
- **日终权益含浮动盈亏**（按该交易日最后一根的收盘价估）。盈利目标和回撤必须同一口径，
  否则「带浮盈过夜不算达标、带浮亏过夜算进回撤」就是套利空间。
- **判违规看最差点**：多头用当根最低价、空头用最高价、空仓用收盘价，`权益 <= 亏损线` 即终止。
  收盘安全但盘中打穿也算——和 OCO「止损优先」是同一套保守原则。
- **当日封顶看已实现**：`当日净额 = 累计已实现 - 当日开盘时的累计`，到 1200 就拦开仓，
  并且**当场撤掉同向挂单**（否则挂在上面的单不需要任何请求就会成交）。
- **「只能平仓」是字面意思**：闸门只拦「会增加暴露」的单，平仓、撤单、拖止损全部放行——
  否则账户一失败，手里那一仓就永远出不掉了。
- **EVAL 达标后必须等空仓才切 FUNDED**：基线重置会把过夜浮亏一起抹掉，那是这套规则里最好
  作弊的洞。不平仓就一直挂着「等待平仓后进入 FUNDED」，不代用户强平（强平要在成交流水里
  凭空多出一笔不存在的成交）。
- **交易日 = 停盘缺口**（`session.go` 的 `isSessionOpen`），不是「0 点」也不是写死的 06:00：
  日盘按美国时间开，北京 06:00（夏令时）/ 07:00（冬令时），写死小时会在冬令时错一小时。
- 40 手的「每品种」实现上是「每实例」：一个实例只有一个标的，两个 MES 账户各自能开 40 手。

账户状态存在实例的 `meta.json` 里（`account` 字段），和游标、持仓同一个提交点，所以
「已经爆仓的账户」重启后不会复活。回放里**没有**账户信息：`account_changed` 不进交易记录的
步骤白名单，记录也只覆盖持仓期间。

页面由 `web/` 构建，**改过前端代码要重新 `npm run build`**（托管的是构建产物）。
开发期可以 `cd web && npm run dev`，dev server 把 `/ws` 转给 8790。

```
  _symbols.json                      索引：标的名 → 文件夹 / tick / tickValue
  CME_MINI_MNQ1!/                    一个标的一个文件夹
    2026-10-15.csv                   文件名就是日期
state/                               ← replayStateDir（菜单 2 的实例存档）
  replay-instances.json              索引
  instances/ins-1/                   一个实例一个文件夹
    meta.json  bars.json  annotations.json  orders.json  trades.json  events.json
    voice.json  voice/voice-N.wav    语音
presets/replay-templates.json        ← replayPresetDir（绘图样式模板，全局，不跟实例）
recordings/                          ← replayRecordingDir（交易记录）
  recordings.json                    索引（删了会自动重建）
  rec-20261016-094512/               一笔交易一个文件夹
    recording.json                   开仓前盘面 + 每一步事件 + 统计 + 操作来源
    tags.json                        用户打的自定义标签（名字 + 颜色；没有就是没打过）
    audio-N.wav
raw/                                 ← rawDir（saveRawFrames 打开时才有）
  CME_MINI_MNQ1!/2026-10-16T09-30-00.ndjson
```

CSV 的内容：

```csv
time,open,high,low,close,volume
2026-10-16 09:40,30067.25,30067.25,30056,30061.5,847
```

- **时间列是明文** `yyyy-MM-dd HH:MM`，是这根 K 线的**开盘时间**，不是 Unix 秒；
- **时区用本机时区**（启动横幅会打印）。这也是文件名里「哪一天」的依据 —— 换机器 / 换时区跑，
  同一根 K 线的归属日会跟着变，所以尽量固定在同一台机器上采集；
- 写盘是**整体重写**（先写 `.tmp` 再 rename），启动时会先把磁盘上已有的当日文件读回内存再合并，
  所以重启不会覆盖已抓的数据；
- `state/`、`recordings/`、`raw/` 都是**用户产物，不入库**。

## 项目结构

```
VERSION               唯一的版本号来源
build.cmd             构建脚本：前端 → 读 VERSION → 生成资源对象 → 就地编译出 exe
winres/winres.json    Windows 资源模板（产品名与描述；不含版本号）
main.go               入口：只有 main() 与 version（-ldflags 的注入点）

internal/cli/         命令行外壳：横幅、菜单循环、各菜单项的编排（唯一的 stdin reader）
internal/capture/     常驻会话：等端口、等页面、挂监听、状态行
internal/cdp/         CDP 接入：端点发现、命令与事件、目标页挑选
internal/wsclient/    极简 WebSocket 客户端（零依赖，支持大帧与分片）
internal/tvproto/     协议层：分帧、按形状抽 K 线、标的解析
internal/ingest/      解码器：周期反推、暂存、交给落盘出口
internal/store/       CSV 存储：标的文件夹 + 每日文件整体重写；scan.go 是只读扫描（按文件并发 + 增量）
internal/config/      config.json 的加载 / 生成 / 校验
internal/rawlog/      原始帧留档（NDJSON）
internal/webreport/   分析页（跟着菜单 1 起）：JSON 接口 + 内嵌前端（static/ 是页面，vendor/ 是两个前端库）
internal/replay/      菜单 2：WS 服务 + 实例状态机 + 标注 + 撮合 + 机器人 + 交易记录
internal/strategy/    策略：纯函数，只看已收盘的 K 线，出「方向 + 止损价 + 目标价」
web/                  复盘前端（Vue 3 + Vite），构建产物 dist/ 由菜单 2 托管
internal/logx/        控制台日志：UTF-8 代码页、状态行原地刷新、显示宽度
internal/wstest/      测试专用的手写 WebSocket 服务端（不进最终产物）

testdata/             真实抓包裁剪出的回归样本
data/ state/ recordings/ raw/    运行期产物
```

上面那些空行就是**分层**，分组依据是「谁能 import 谁」，不是目录层级：

| 层 | 包 | 约束 |
|---|---|---|
| 入口 | `main` | 只 import `internal/cli`；除 `main()` 与 `version` 外不许长东西 |
| 编排 | `cli`、`capture` | 可以 import 下面所有层 |
| 协议与外部世界 | `cdp`、`wsclient`、`tvproto` | 不 import 领域层与表现层 |
| 领域与存储 | `ingest`、`store`、`config`、`rawlog` | 不 import 编排层与表现层 |
| 表现层 | `webreport`、`replay` | `webreport` 只读 `store.Scan` 的结果，不重算统计量 |
| 基础设施 | `logx` | 谁都可以用 |

几条结构上的约定：

- **入口留在根目录，不搬进 `cmd/`**：只有一个可执行文件，而且使用方式是双击 ——
  `go build .` / `go run .` 得能直接用。搬走 main 包还会连带改掉 `.syso` 的输出目录
  （它只会被链接进同目录的那个包，搬走就静默变成空的属性页）。
- **`internal/` 保持扁平**：Go 的导入路径就是包路径，往中间插一层只让 import 变长，
  不产生任何编译器能看见的边界。包的数量就是职责的数量。
- **`internal/replay` 是个自成一体的应用包**：实例、操作权、广播、标注、撮合、机器人都在一起，
  只被 `cli` 调用，不许反向依赖 `webreport`；读 CSV 用 `store` 的只读函数，一个字节都不写。

前端（`web/`）是 Vue 3.5 + Pinia + TypeScript + Vite，样式用 **Tailwind 4**（CSS-first，
没有 `tailwind.config.js`）。**K 线不用图表库**：Canvas 画 K 线，SVG 画标注并承接命中测试，
两层共用同一套坐标变换（`chart/scale.ts`）。唯一的图表库依赖是 **ECharts**（`records/` 那六张
统计图按需注册，只打进 `/records` 这个懒加载 chunk，画布页不受影响：K 线的缩放、十字光标
要和标注严格同坐标系，交给图表库反而做不干净）。开发用 `npm run dev`；`npm run type-check` /
`lint` / `build` 三道就是前端的「测试」（没有自动化测试）。

## 设计说明

这一节只讲**边界与不可让步的约定**。为什么这么做、踩过哪些坑、哪些结论是被数据推翻过又重建的，
都写在对应文件的注释里；改代码前请先读那个文件的开头。

**为什么只做被动监听**：主动拖动图表会让交互序列变得不像人操作的，高频使用有被风控的可能。
所以没有自动回拉、不接受命令行参数、不做批量调度。这条约束的副产品是**抓取链路上没有一行
JavaScript** —— 不注入脚本就不需要浏览器扩展。

**为什么零依赖**：唯一需要的外部能力是「一个 WebSocket 客户端」，而它可以完全用标准库实现。
自写的客户端要处理两件被真实数据逼出来的事：单帧可达 247KB（要支持 64 位长度与分片重组），
以及写帧必须掩码。`go.mod` 里至今没有 `require`，这是刻意的。

**标的名怎么认**：只认 `symbol_resolved`，别在整帧里搜 `pro_name` —— 同一个 WebSocket 上跑的
不只是图表数据，自选 / 报价面板的 `qsd` 消息里带着**别的品种**。判定顺序是
`config.symbol` → 序列绑定 → 会话内唯一 → 页面内唯一 → URL 猜。给不出结论时 K 线**先攒着
不落盘**，等品种明确后补写 —— 猜错会污染别的标的。

**周期怎么反推**：帧里没有任何字段直接写着周期，`lbs.bar_close_time` 是个陷阱（它是图表右侧
可视边界）。周期靠相邻时间戳的**众数差**反推，而且按「会话 + 序列」分开投票（多个图表会话的
序列都叫 `sds_1`，混着投会互相污染）。反推出来之前 K 线暂存不落盘，宁可晚几百毫秒，
也不要把 1 小时图的 K 线混进 5 分钟目录。

**写入语义**：内存里按 `(标的, 日期)` 维护 `时间戳 → K 线`，同一时间戳直接覆盖，每
`flushSeconds` 整体重写脏掉的日文件（tmp + rename）。所以**重复数据在结构上不可能出现**，
不需要查「这根是不是已经有」。

**统计口径只有一份**：根数、断档、应有根数、异常判定全部在 `store.Scan` 里算，网页端只排队版。
反过来在 JS 里重算一遍就会出现两份口径，而**同一个数据目录给出不同根数时用户没法裁决**。
「星期几应当有多少根」只写在 `store.ExpectedBars` 一处，页面通过 `meta.expectRule` 印出来。

**报告只有一个出口**：只有菜单 1 顺带起的那个分析页。终端的表格报表曾经存在，已整个删掉 ——
两套界面看同一份数据，数字一旦有出入用户没法裁决。

**实时靠「重扫 + 增量」，不靠推数据**：抓取只负责把内存里的当天数据按 `flushSeconds` 写进
CSV，页面每 2 秒问一次磁盘。中间刻意没有 WebSocket / 共享内存 / 事件总线 —— 那会让
「页面上的数字从哪来」多出一条不经过文件的路，而这条路上的数字没法用编辑器核对。
代价是多等一到两秒，换来的是「屏幕上任何数字都能在 CSV 里找到」。

**标注只有「时间 + 价格」，没有像素**：换窗口大小、缩放级别、显示器，像素就全错了，而时间价格
不会；后端要做校验（锚点不能是未来），它只认识时间和价格。端点可以带 `offset` 往右越过最后一根
K 线（那不是时间也不是像素，是「锚点下标 + 根数」），所以延伸段和 K 线严格对齐、缩放平移都不漂。

**前端预览、后端定稿**：除了缩放 / 平移 / 十字光标，没有任何一个操作是本地直接改状态的。
预览可以本地算（手感），但定稿必须由后端校验、编号、广播回来，界面上的正式状态**永远来自广播**。
唯一需要两边各算一遍的是 Ctrl 吸附 —— 两份实现必须同口径，不一致的症状是「松手后图形跳一下」。

**指标的算法只有一份，放哪儿按「是不是盘面事实」分**：EMA20 与 ATR14 在 Go 里算好下发
（`Bar.ema20` / `Bar.atr14`），同一份历史在任何界面、任何客户端上都必须是同一个数；
Doji X + ZigZag 的 Lag / Doji Size 是工具栏上随手拧的**显示参数**，留在前端
（`chart/indicators.ts`），拧一下不该变成一次网络往返。ATR 的周期**也钉在 14**
（Wilder 平滑，种子是前 14 根 TR 的简单平均）：改周期就是另一个指标，要开放给用户调，
得先在协议里把「谁算、算哪个」定死，而不是让两边各算一套。ATR 副图是**布局的一部分**——
开关一变就要重算 layout（`scale.setAtrPane`），只翻布尔值不重算的症状是「K 线还是原来那么高、
副图压在最下面一截上」；它没有价格坐标，所以右键下单 / 画标注在副图里一律不接。

**撮合规则只有一份**：在 `internal/replay/instance.go`，机器人走的也是同一套方法（策略拿不到
`Instance`，就不可能自己造一个成交价）。成交价通常是挂单价、跳空时取开盘价；本根挂的单从下一根
才参与撮合（否则就是拿已收完的 K 线倒推成交）。**前端不算钱**：成交、持仓、盈亏全部来自后端。

**「一键退仓」是一条消息、一次广播**：前端不发「先撤 N 张单、再反向市价」那一串，因为中间态
会被所有人看见（挂单一张张消失、仓位还有一瞬间的反手风险）。服务端在 `Instance.flatAll` 里
先 `marketOrder` 平掉整个仓位、再撤掉全部挂单（失败时挂单还没动过，盘面原样），然后广播一条
`flat_all` —— 平仓走的就是手动市价那条路，
所以钱的口径和「自己点市价卖出」完全一样。

**为什么 nATR 定手数可以在前端算**（它是唯一一处前端会碰钱的地方）：它**不产生**盈亏，只产生
一个**整数手数**；算式就三行（`n × ATR`、乘每点价值、除最大亏损），而「每点价值」是从
`tickValue / tick` 推出来的，和后端 `pointValueOf` 同一口径 —— 所以算出来的手数拿去下单，
成交后后端算的钱和面板上预告的钱对得上。真正的成交价、持仓、盈亏仍然只有后端说了算，
前端不因为算了这一下就获得了「自己记账」的资格。算式只有一份，在 `web/src/lib/natr.ts`。

**但它带的那张止损单不在前端算**：前端只把**距离**（`n × ATR`）塞进 `order_market`
的 `stopDistance`，价格由后端按自己的成交价算（`Instance.marketOrderWithStop`，
`stopPrice = roundPrice(成交价) ∓ 距离`）。理由是分工 —— ATR 只活在界面上，成交价只活在
后端；谁的数字谁算，两边都不会拿对方的近似值去减。而且成交和挂止损**在同一个锁里**、
只广播一条 `order_filled`（`stopOrder` 字段单独带一份给操作记录）：拆成两条消息，
中间必然有一帧「有仓、没止损」，那正是这个方法要消灭的东西。
止损价算不出合法价格（距离大到把价格减成负数）时**先报错、一个仓位都不开**；
万一挂单真的失败，会立刻反向市价平掉这一笔 —— 「没挂上止损」等于「这单没做」。

**交易记录挂在唯一的广播出口上**：不散在各个 `do*Locked` 里，因为那样每加一个动作就要记得补
一行，迟早会漏，而漏掉的动作在回放里表现成「画面少了一步」。挂在出口上，新增动作天然被录，
机器人操作也天然被录。录下来的是**广播出去的原文**，回放时喂给同一个 reducer，画面必然一致。

**回放和实时共用一个 reducer**：`applyInstanceEvent` 是唯一把广播变成盘面的地方，所以回放不是
「另写一套播放逻辑」，而是「深拷起点快照，再把事件依次喂进去」。

**回放延伸也是一步，而不是一次性的临时视图**（v0.27.0，`internal/replay/extend.go`）。
走到最后一步之后可以往后加载真实行情，这件事落在数据上只有一句话：**记录里多一步**
（`kind = bar_extended`，payload 只有 `bar / cursor / hasMore`）。三条后果都是白拿的 ——
「跳到第 N 步」照样重现、重开记录那几根还在、步进条上能一眼看出哪里是延伸出来的。
刻意**不**复用 `bar_advanced`：那条的 payload 带着订单 / 成交 / 持仓的全量快照（实时撮合算出来的），
延伸那段时间根本没有成交，照它更新会把回放里的仓位改写成「还开着」—— 那是编造。
**只能在末尾加载**：中间插一根会让后面所有步的 `time` 与 `cursor` 错位，画在上面的图形、
挂在上面的话会集体跑到别的柱子上。所以服务端只认记录最后一根，前端也只在那一步给按钮。

**在延伸出来的 K 线上录音，走的是记录自己那条路**：回放里前端没有 join 任何实例
（`rec:<id>` 是演出来的），`voice_add` 那一套（以及它背后的 `instance.voice`）用不了。
于是三条以 `recordingId` 为中心的请求（`recording_extend` / `recording_voice_add` /
`recording_voice_clear`）直接读改写记录目录：语音同样变成记录里的一个 `recording_audio` 步
（`audio-N.wav` 另存一份，每根 9 条、WAV 格式、2MB 上限与复盘录音共用
`checkAudioClip` 同一份校验），所以「走到那一步就响」这条规则一行都不用改。
落盘用的是 `RecordingStore.UpdateRecording`（只重写 `recording.json` 与索引），
**不是** `Save` —— `Save` 会按这次传进来的音频字节清理目录里的 `audio-*.wav`，
而延伸手里根本没有那些字节，用它保存等于把已有语音全删掉。

**机器人 = 纯函数策略 + 执行器 + 撮合**：策略只出「方向 + 止损价 + 目标价」（绝对价格，不是距离
—— 换算散在两边迟早有一边把方向写反），执行器负责下单与保护单，成交口径复用撮合。
加一个策略只要实现 `OnBar`，协议和前端都不用动。

**考核账户挂在实例上，不是独立实体**（v0.31.0，`internal/replay/account.go`）。一个账户
就是「一张盘面 + 一套规则快照」，而实例已经是那张盘面了；做成两个实体就要维护「账户 ↔ 实例」
的对应、各自一套落盘与广播，收益为零。所以账户是 `Instance.account`，nil 就是自由模式。
结算只有两个钩子，都在 `advance` 里：**跨交易日那一根之前**做日终结算（峰值 / 亏损线 /
盈利日 / 阶段切换），**每笔成交累加之后**判线（不是整根判一次 —— 同一根里可能先止损打穿、
后止盈补回来）。顺序反过来就会「少算本笔，爆仓慢一拍」。手续费也只有一个扣点（`applyFill`），
于是余额永远是算出来的，不存在第二本账。

**两条行为契约**（细节看代码）：同组保护单（OCO）一根 K 线里只成交一张，**两张都被扎到时
判止损**；**日历日最后一根（23:55）无条件平仓 + 撤光挂单**，任何仓位不留过夜。

## 改代码时的注意

- **不要引入第三方依赖**：`go.mod` 目前没有 `require`，这是刻意的。
- **不要让「分析」写任何东西**：统计走只读的 `store.Scan`（`store.Store` 一 Open 就会建目录、
  分配标的目录名）；复盘读 CSV 只用 `ReadDayRows` / `Catalog`，唯一写入口是 `persist.go`。
- **不要让两处各写一份解析**：CSV 行格式只在 `store.readDayFile` 里定义一次。
- **版本号只改 `VERSION` 一个文件**，改完必须**重新构建**（`.syso` 是编译期快照）。
- **`build.cmd` 必须纯 ASCII + CRLF**，改它时不要写入中文或裸 LF（有测试拦）。
- **菜单只能有一个 stdin reader**：否则缓冲层里攒着的字符会被绕过去，表现成「按一次回车跳过两项」。
- **网页版不许有「算数字」的代码**：改了显示格式或日历日期算术，要同步改
  `internal/webreport/testdata/format.test.cjs` 的期望值 —— 那是唯一事实来源。
- **改了 `internal/webreport/static/` 下任何文件都要重新 `go build`**：`//go:embed` 是编译期快照。
- **「实时」只有一条链路**：`store` 写盘 → 指纹变 → `webreport` 重扫 → 页面轮询。
  不要为了「更快」加事件推送或让页面直接读抓取进程的内存 —— 那会造出第二条口径，
  而页面上的数字一旦无法用编辑器在 CSV 里核对，用户就没法判断该信谁。
- **`store.Scanner` 的记忆键是「路径 + 大小 + 修改时刻」**，别只留大小（同一时间戳被覆盖时
  字节数可能一样）；也别把目录 mtime 算进去（Windows 上延迟落定）。
- **缓存失效靠「磁盘指纹」，不是靠时间**：`webreport.fingerprint` 只比每个日文件的名字 + 大小 +
  修改时刻，**不许**把目录自己的 mtime 算进去 —— Windows 上目录 mtime 是延迟落定的，
  连读两次都可能不一样，算进去的后果是缓存永远不命中（表面上「没坏」，只是白扫）。
- **`web/dist` 不是 embed 的**：复盘服务运行期从磁盘读，所以改前端必须 `npm run build`，
  发布时要连 `dist` 一起带走（否则页面是那张「还没构建」的说明页）。
- **URL 路径用 `path`，磁盘路径用 `filepath`**：`filepath.Clean` 在 Windows 上会把 `/assets/x.js`
  变成 `\assets\x.js`，任何 `HasPrefix(..., "/assets/")` 都会静默失效。
- **存档是快照不是日志**：加「属于实例」的字段可以（`omitempty` 让老档照读）；
  「属于进程」的字段（谁在操作、日文件索引、机器人协程）**别加**，那些恰恰不该被恢复。
- **改完会改实例状态的代码，想一下它会不会被标脏**：落盘靠 `markDirtyLocked()`，它挂在
  `broadcastInstanceLocked` 上，所以走广播的改动一定会被存下。
- **记录页的时间轴只有一个口径**：日历归日、按天求和、累计曲线排序、明细里的「记于」全部用
  `createdAt`（记录生成时间）；行情时间（K 线）只作为每笔的附加信息显示。别把 `groupByDay`
  改回按 K 线日期分组 —— 复盘可以今天补做去年的行情，两个时间本来就该分开。
- **前端不写钱**：成交、持仓、盈亏全部来自后端广播；改撮合规则只改 `instance.go`。
  唯一的例外是 nATR 定手数（它只算「下几手」，不算盈亏），算式只在 `web/src/lib/natr.ts`，
  「每点价值」必须继续按 `tickValue / tick` 算 —— 和后端 `pointValueOf` 漂了，用户就会看到
  「说好亏 $1924，结果亏了别的」。**止损价不在这个例外里**：前端只传距离，
  价格由后端按自己的成交价算（`marketOrderWithStop`），别把它挪回前端去减。
- 前端相关的几条：`types/protocol.ts` 与 `replay/protocol.go` 逐字对应（字段名对不上不报错，
  只表现成「某个面板一直是空的」）；`@` 别名在 `vite.config.ts` 与 `tsconfig.app.json` 两处
  同步；**方向色只有一个语义**（绿 = 涨/做多/盈利，红 = 跌/做空/亏损），取值只在两处：
  页面是 `style.css` 的 `--c-up` / `--c-down`（组件用 `text-up` / `bg-down` 这类语义类），
  画布是 `chart/render.ts` 的 `CHART_THEME` —— 改颜色两处一起改，别再引入第二套红绿。
  **K 线例外**：画布上的蜡烛保持黑白（`CHART_THEME.up/down` 都是 `#111827`，只有空心/实心
  不同），别顺手把它改成红绿 —— 蜡烛是画布的主体，染色会盖过挂单线、持仓线和成交标记。

## 注意事项

抓取属于对 TradingView 服务条款的灰色操作。低频、小批量自用风险可控；
**不要高频批量拉，不要全品种刷。**

程序只做被动监听是刻意的：不产生任何主动交互，也就不给风控提供触发依据。但也不要长时间挂着
连续录几十个小时 —— 需要哪段历史，开一次拖一遍就够了。

本项目未声明开源许可（仓库内没有 `LICENSE`）。
=======
| LIMIT BUY / SELL | `low ≤ p` / `high ≥ p` | `min(p, open)` / `max(p, open)` |
| STOP BUY / SELL | `high ≥ p` / `low ≤ p` | `max(p, open)` / `min(p, open)` |

- **跳空修正不能省**（不加则每次跳空都白送钱、回测数字全废）。
- **本根挂的单本根不撮合**：实现是「挂单的 `placedAtBar` **严格早于**本根时间」
  （`TradingEngine.eligible`），不是另加一列 `effective_from_bar` —— 两者在当前语义下等价，
  因为下单只能发生在账户 `lastBarTime` 那一根上，而那根的 O/H/L/C 已经收完。
  哪天允许「往过去某根挂单」，就得把这一列加回来。
- **没有 OCO**（2026-10-31 删 `TradeOrder.ocoGroup` / `TradingEngine.ocoWinners`）：`webapp`
  只发独立挂单，同根双触发就成交两张 —— 那是用户各挂各单的真实结果，不该被一条前端发不出来的
  规则偷偷改掉。Go 侧的机器人仍用组（`instance.go` 的 `seqGroup`），两边语义从这里分叉。
- 不做部分成交 / 滑点：一根 5 分钟 K 线只有 O/H/L/C，这两件事没有数据支撑。

**记账口径**（`TradeLedger` 是唯一算法，前端一处钱都不算）：

- 持仓 / 已实现盈亏 / 逐批平仓全部由 `trade` 表重放得出，**不单独存**；
- 每笔成交的 `realizedPnl` 是**毛利**（平均成本法），`commission` 是成交那一刻的费率快照
  （每手每边 × 手数，**开仓也收**），`netPnl = 毛利 − 手续费`；广播里的 `realizedPnl` 是**净额**；
- 逐批归因（`ClosedLot`）用**这一批自己的开仓价**算毛利，手续费不摊到批次上（一笔成交可能
  同时平掉几批，没有可靠的摊法）；账户口径一律以净额为准。
- **金额只到分**（`entity.trade.Money`）：均价可能除不尽（六个价位均价 = 174586/6），
  所以均价除法用 `DECIMAL128`，而 `realizedPnl` / 浮盈 / `netPnl` / 落库手续费一律
  `Money.round` 收敛到两位小数。**别把均价精度改回 10 位** —— 那会让 835 变成 `834.99996`
  （误差 ×手数×每点价值放大），回归测试见 `TradeLedgerTest`。
  **闸门在实体工厂上**（`Trade.fill` / `TradeRecord.closeAt` / `PropFirmStageLog.close` /
  `PropFirmAccount.syncComputed`），以后新增记账路径绕不过去；`PositionView` 把**均价**
  也收敛到两位，但那只是展示 —— 算账仍用全精度 `Position`，否则乘回去又会偏。
- 手数必须是 1~10000 的整数；价格吸到 `tick` 上（没配 tick 按两位小数）。

**状态与并发**：订单只有 `OPEN → FILLED | CANCELLED`（实体方法 `markFilled` / `cancel` 把关，
重复成交当场抛）。**不用乐观锁**：`spring.datasource.hikari.maximum-pool-size = 1` 让
「读一批 → 算 → 写回」整段串行（改连接池之前先回来看 `TradingService` 类注释）。
撤单 / 改价 / 一键退仓都写 `audit_event`（`ORDER_CANCELLED` / `ORDER_MOVED` / `FLAT_ALL`）；
撮合不单独写 —— 它在 `bar_advanced` 那条流水里。**强平先平后撤**（失败不留半截状态）。

**待做（仍是设计，未实现）**：撤单原因列 `cancel_reason` · 幂等（`expectedBarTime` 比对游标，
不符回 409）· 手数上限「净持仓 + 未成交挂单」· `TRAILING_INTRADAY` 口径（现在会明确抛错，不假装实现）·
23:55 先撮合后强平 · 04:45–06:00 的 12 根跳过 · 停在最后一根要调 `finish`（否则**当天永不结算**，
亏损线也就一天不结算）· CSV 被 Excel 占用整根回滚。
