# tradingview-j

> 旁路抓取你**本人已登录的 Chrome** 里 TradingView 图表页的 WebSocket 行情帧，
> 解出 **5 分钟 K 线**，按「一个标的一个文件夹、一天一个 CSV」落盘。

纯 Go 实现，**零第三方依赖**（WebSocket 客户端也是自写的），产物是**根目录下**的单个 exe：
`tv-capture-v<版本>.exe`（当前 `0.18.0`）—— 版本号既在文件名里，也写进了 exe 的文件属性。

程序只**被动**监听浏览器已经收到的数据：不注入脚本、不需要浏览器扩展、不主动操作图表、
也没有自动回拉。菜单 1 负责采集，菜单 2 是只读报表，菜单 3 是复盘与模拟交易。

## 特性

- **被动旁路**：只录页面自己请求到的行情，不产生任何主动交互（也因此没有注入脚本要维护）。
- **零依赖单文件**：`go.mod` 里没有 `require`，一个 exe 拷到哪都能跑，不需要装运行时。
- **明文 CSV**：时间列是 `yyyy-MM-dd HH:MM`，Excel / pandas / 文本编辑器直接可读。
- **整体重写落盘**：同一时间戳被反复推送时直接覆盖，重复数据在结构上不可能出现。
- **只收 5 分钟**：其他周期的序列整段跳过；周期是从数据反推出来的，不是配置里念出来的。
- **网页版分析（菜单 2）**：把**同一份**统计结果起在本机网页上（月历视图，点某一天看当天明细）。
- **复盘（菜单 3）**：本地网页里**逐根回放** K 线，画基于「K 线时间 + 价格」的标注，
  做限价 / 止损 / 市价模拟交易；多人时一人操作、其余观看，机器人也能接管演示。
  实例、标注、挂单、成交写进本地存档（`state/`），**关掉程序再进来还在**；数据目录始终只读。
- **交易记录（自动，没有开关）**：开仓那一刻自动开始记、平仓那一刻自动收尾。记的是**事件流**
  而不是视频，所以能单步回放、能跳步，机器人操作同样被记。记录与实例存档互不引用。
- **策略机器人**：工具栏【启动机器人 ▾】里选一个策略让它自己跑 —— 逐根推进、自动开仓、
  自动挂止损止盈两张保护单（同一个 OCO 组），**日终强平不留过夜**，数据跑完自己停。
- **语音讲解**：按 K 线时间挂在盘面上（空仓也能录），横轴下方有一条录音条按时间排布，
  可单条试听也可连播。
- **浅色 / 深色两套配色**、**价格轴按标的 tick 走**、**盈亏按合约价值换算成美元**。

## 前置条件

- **Chrome，并打开远程调试开关**（每个浏览器会话要做一次）：

  1. 打开你平时登录着 TradingView 的那个 Chrome
  2. 地址栏访问 `chrome://inspect/#remote-debugging`
  3. 勾选 **Allow remote debugging for this browser instance**
  4. 打开 TradingView 的**图表页**（URL 里带 `/chart/`），周期切到 **5 分钟**

  > Chrome 136 起，给默认用户数据目录加 `--remote-debugging-port` 会被**静默忽略**，
  > 「关掉 Chrome 再加参数重启」这条路走不通，只能用上面这个开关。它立即生效、不用重新登录，
  > 代价是每次外部发起连接 Chrome 会弹一次授权框要求点 **Allow**。

- **Go 1.26+**：只在从源码构建时需要。`go.mod` 里的 `go 1.26` 是**对齐两台构建机的工具链下限**
  （代码本身只用到 1.22 的语法；Go 1.26 是最后一个支持 macOS Monterey 的版本）。
- **`go-winres`**：构建时把版本信息写进 exe 属性，一次性装好即可：
  `go install github.com/tc-hib/go-winres@latest`，确认 `%USERPROFILE%\go\bin` 在 `PATH` 里。
  它是**构建期工具**，不进入程序。
- 当前只在 **Windows** 上实际跑过。macOS 用 `build.sh`；`.syso` 只在 windows/amd64 参与链接，
  其它平台的产物只是没有属性页。

## 快速开始

```bat
build.cmd                        :: 前端 + exe 一次做完
build.cmd --no-web               :: 只编 exe，跳过前端（沿用上次的产物）
tv-capture-v0.18.0.exe           :: 产物就落在根目录（版本号来自 VERSION）
```

三个阶段顺序固定，**任一阶段失败就地中断**，所以不会留下「前端是新的、exe 还是旧的」：

| 阶段 | 跑什么 | 产物 |
|---|---|---|
| 1 前端 | `cd web && npm run build`（缺 `node_modules` 时先 `npm install`） | `web\dist\`，菜单 3 运行期托管它 |
| 2 资源 | `go-winres make --file-version=<v> --product-version=<v>` | `rsrc_windows_amd64.syso` |
| 3 Go | `go build -ldflags "-X main.version=<v>" -o tv-capture-v<v>.exe .` | 根目录的 exe，**就地**生成 |

启动后是一个四选一的菜单：

```
  1  启动抓取            等 Chrome + 图表页，把 5 分钟 K 线录成 CSV
  2  网页版分析          只读统计：每个标的每天多少根、缺口在哪
  3  复盘                随机/指定时间点，逐根回放、画标注、模拟下单、自动交易记录
  4  退出
```

选 **1** 之后程序会自己等调试端口和图表页出现（没开就一直等，每 5 秒重试，不需要重启程序）。
**你要做的只有一件事**：在 Chrome 里往回拖动图表，或用回放模式跳日期 —— 图表走到没缓存的
范围时页面自己就会去要数据，程序把这段录下来。`Ctrl+C` 停下来会先刷盘，然后**回到菜单**。

## 构建与版本号

版本号**只有一个来源**：根目录的 `VERSION`（一行，例如 `0.18.0`）。它要出现在三处 ——
**产物文件名**、**exe 文件属性**、**程序内**（横幅 / 网页页脚 / `meta.version`）——
这三处分别由构建脚本、资源编译器、Go 编译器产生，任何一处人手填都会漂。所以：

| 落点 | 谁写进去的 |
|---|---|
| 根目录 `VERSION` | 人（唯一需要动手的地方） |
| `tv-capture-v<v>.exe` | `build.cmd` 的 `-o` |
| exe 属性里的文件 / 产品版本 | `go-winres --file-version` / `--product-version` |
| 横幅 / 网页页脚 / `meta.version` | `go build -ldflags -X main.version` |

**升版本 = 改 `VERSION` 那一行，再跑一次 `build.cmd`。** 光改 VERSION 不重新构建没有用：
`rsrc_windows_amd64.syso` 是**编译期快照**，每次由构建脚本重新生成，不要手工维护它、
也不要提交进仓库。`version_test.go` 把这几条钉成了断言（含三步齐全、`build.cmd` 必须是纯
ASCII + CRLF、`winres\winres.json` 里不许出现版本号键）。

产物**就在根目录**，和 `config.json` / `data\` / `raw\` 并排。注意 `outDir` / `rawDir` 全是
**相对 exe 所在目录**展开的：换个目录放 exe 就等于换一份数据目录。

## 使用

### 菜单 1：启动抓取

```
[信息] 发现浏览器调试端点：port 9222 · 来源 DevToolsActivePort
[信息] CDP 通道已建立，开始等待 TradingView 图表页…
[信息] 已接入图表页：CME_MINI:MNQ1! · 5 分钟 - TradingView
[状态] 页[...] 帧 1204(收1180/发24) 心跳 12 · 周期 300s · 品种 CME_MINI:MNQ1! · 落盘 288 根
```

状态行原地刷新，不刷屏。同时开多个图表标签页会**全部挂上**，各自独立录；某一个挂掉不影响其它。

### 菜单 2：网页版分析

对数据目录做一次**只读**扫描（不建目录、不写索引、不改任何文件），把结果摆成浏览器里的月历。
服务只绑 `127.0.0.1`，**没有任何能改数据的接口**。

- 每个标的一个月历，格子中间的大数字是**当天的 K 线根数**；标红 = 根数与该星期应有的根数不符
  （或文件有坏行 / 读不了），标黄 = 当天各标的根数不完全相同，灰格 = 没数据；
- **点某一天**出当天明细：根数、应有根数、首根 / 尾根，以及**每一段断档的起止时刻**；
- 工具条按月翻页，**所有日历一起翻**；「全部标的按日期合计」也是一张月历；
- 两个勾选框把「异常日」或「数量不一致的日」**高亮**出来（变淡、不隐藏）；
- 顶部的「统计口径」可以展开，里面写着每条判定的含义和「星期几应当有多少根」那张表。

统计量全部由 `store.Scan` 算好再送过去，网页端只做排版；**停止用 `Ctrl+C`**（和抓取一致）。

### 菜单 3：复盘

起一个本地网页，把 `data/` 里的 K 线**逐根回放**，在图上画标注、做模拟交易。
和菜单 2 的区别：菜单 2 是**只读报表**，菜单 3 是**有状态的应用**（实例、标注、挂单、成交写进
`state/`），但它**仍然只读数据目录**，一个 CSV 都不会改。

- 右上角「标的与实例」→ 选标的（时间留空就随机挑一根）→ 新建实例：铺出这一刻及之前 400 根
  K 线，之后的行情逐根揭示；同一面板里能进入 / 删除实例；
- 【下一根】揭示下一根 K 线，同时用这根的最高 / 最低价撮合挂单；
- 标注：趋势线 / 射线 / 矩形 / 箭头线 / 斐波那契回撤。**【射线】单击即完成**，其余两次单击；
  按住 **Shift** 画水平线、按住 **Ctrl** 吸附到 OHLC；坐标严格是「K 线时间 + 价格」；
  点一下图形就能改（拖端点、拖线身、`Del` 删除），不用切模式；
- 任意价格处**右键**就地挂单：单型按价格相对现价的方向自动定；「移除 N 个绘图」连点两下确认；
- 挂单线可以**上下拖改价**、右端「×」直接撤单；平仓虚线悬停看这笔交易，停 3 秒固定到画布；
- 模拟交易：限价 / 止损 / 市价，**不设止损止盈类型**（要止损就挂一张 `stop` 单），
  无初始资金、不计手续费 / 点差 / 滑点；
- 多人：第二个标签页进来就是**观众**，能收广播但不能操作；「交还 / 接管」切换操作者，
  操作者关掉页面会自动释放。这是后端的硬约束，不是把按钮置灰；
- 底边是「模拟交易 / 操作记录 / 交易记录」三个 Tab，右上角可切浅色 / 深色。

页面由 `web/` 构建，**改过前端代码要重新 `npm run build`**（托管的是构建产物）。
开发期可以 `cd web && npm run dev`，dev server 把 `/ws` 转给 8790。

## 配置

程序**不接受任何命令行参数**，所有参数都在 exe 同目录的 `config.json` 里；文件不存在会自动
生成一份默认的。相对路径都相对 **exe 所在目录**展开，不是当前工作目录。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `matchUrl` | `"tradingview.com/chart"` | 挂到哪个标签页：按 URL / 标题子串匹配 |
| `symbol` | `""` | 强制指定标的；留空则自动识别（推荐留空） |
| `cdpPort` | `0` | `0` = 自动发现（读 `DevToolsActivePort`，再探测 9222/9229/9333） |
| `intervalSeconds` | `300` | **只收这个周期**的 K 线 |
| `outDir` / `rawDir` | `"data"` / `"raw"` | CSV 目录 / 原始帧留档目录 |
| `saveRawFrames` | `true` | 是否留档原始 WebSocket 帧 |
| `csvHeader` | `true` | CSV 是否写表头行 |
| `webPort` | `8765` | 菜单 2 的端口；`0` = 让系统随便给一个 |
| `replayPort` | `8790` | 菜单 3 的端口（页面与 WebSocket 同一个）；`0` = 随便给一个 |
| `replayDistDir` | `"web/dist"` | 菜单 3 托管的前端构建产物 |
| `replayStateDir` | `"state"` | 实例存档目录 |
| `replayRecordingDir` | `"recordings"` | 交易记录目录 |
| `replayPresetDir` | `"presets"` | 全局样式模板目录（和实例存档分开） |
| `flushSeconds` | `1` | CSV 落盘间隔 |
| `attachPollSeconds` | `3` | 多久检查一次新出现的图表页 |
| `retrySeconds` | `5` | 接入失败后的重试间隔 |
| `statusSeconds` | `15` | 状态行刷新间隔 |
| `networkBufferMB` | `200` | CDP 网络事件缓冲上限 |
| `maxFrameMB` | `16` | 单帧上限，超了断开重连 |
| `pauseOnExit` | `true` | 出错退出时是否等回车（双击运行时能看清报错） |

## 数据输出

```
data/                                ← outDir
  _symbols.json                      索引：标的名 → 文件夹 / tick / tickValue
  CME_MINI_MNQ1!/                    一个标的一个文件夹
    2026-10-15.csv                   文件名就是日期
state/                               ← replayStateDir（菜单 3 的实例存档）
  replay-instances.json              索引
  instances/ins-1/                   一个实例一个文件夹
    meta.json  bars.json  annotations.json  orders.json  trades.json  events.json
    voice.json  voice/voice-N.wav    语音
presets/replay-templates.json        ← replayPresetDir（绘图样式模板，全局，不跟实例）
recordings/                          ← replayRecordingDir（交易记录）
  recordings.json                    索引（删了会自动重建）
  rec-20261016-094512/               一笔交易一个文件夹
    recording.json                   开仓前盘面 + 每一步事件 + 统计
    audio-N.wav
raw/                                 ← rawDir（saveRawFrames 打开时才有）
  CME_MINI_MNQ1!/2026-10-16T09-30-00.ndjson
```

CSV 的内容：

```csv
time,open,high,low,close,volume
2026-10-16 09:40,30067.25,30067.25,30056,30061.5,847
```

- **时间列是明文** `yyyy-MM-dd HH:MM`，是这根 K 线的**开盘时间**，不是 Unix 秒；
- **时区用本机时区**（启动横幅会打印）。这也是文件名里「哪一天」的依据 —— 换机器 / 换时区跑，
  同一根 K 线的归属日会跟着变，所以尽量固定在同一台机器上采集；
- 写盘是**整体重写**（先写 `.tmp` 再 rename），启动时会先把磁盘上已有的当日文件读回内存再合并，
  所以重启不会覆盖已抓的数据；
- `state/`、`recordings/`、`raw/` 都是**用户产物，不入库**。

## 项目结构

```
VERSION               唯一的版本号来源
build.cmd             构建脚本：前端 → 读 VERSION → 生成资源对象 → 就地编译出 exe
winres/winres.json    Windows 资源模板（产品名与描述；不含版本号）
main.go               入口：只有 main() 与 version（-ldflags 的注入点）

internal/cli/         命令行外壳：横幅、菜单循环、三个菜单项的编排（唯一的 stdin reader）
internal/capture/     常驻会话：等端口、等页面、挂监听、状态行
internal/cdp/         CDP 接入：端点发现、命令与事件、目标页挑选
internal/wsclient/    极简 WebSocket 客户端（零依赖，支持大帧与分片）
internal/tvproto/     协议层：分帧、按形状抽 K 线、标的解析
internal/ingest/      解码器：周期反推、暂存、交给落盘出口
internal/store/       CSV 存储：标的文件夹 + 每日文件整体重写；scan.go 是只读扫描
internal/config/      config.json 的加载 / 生成 / 校验
internal/rawlog/      原始帧留档（NDJSON）
internal/webreport/   菜单 2：JSON 接口 + 内嵌前端（static/ 是页面，vendor/ 是两个前端库）
internal/replay/      菜单 3：WS 服务 + 实例状态机 + 标注 + 撮合 + 机器人 + 交易记录
internal/strategy/    策略：纯函数，只看已收盘的 K 线，出「方向 + 止损价 + 目标价」
web/                  复盘前端（Vue 3 + Vite），构建产物 dist/ 由菜单 3 托管
internal/logx/        控制台日志：UTF-8 代码页、状态行原地刷新、显示宽度
internal/wstest/      测试专用的手写 WebSocket 服务端（不进最终产物）

testdata/             真实抓包裁剪出的回归样本
data/ state/ recordings/ raw/    运行期产物
```

上面那些空行就是**分层**，分组依据是「谁能 import 谁」，不是目录层级：

| 层 | 包 | 约束 |
|---|---|---|
| 入口 | `main` | 只 import `internal/cli`；除 `main()` 与 `version` 外不许长东西 |
| 编排 | `cli`、`capture` | 可以 import 下面所有层 |
| 协议与外部世界 | `cdp`、`wsclient`、`tvproto` | 不 import 领域层与表现层 |
| 领域与存储 | `ingest`、`store`、`config`、`rawlog` | 不 import 编排层与表现层 |
| 表现层 | `webreport`、`replay` | `webreport` 只读 `store.Scan` 的结果，不重算统计量 |
| 基础设施 | `logx` | 谁都可以用 |

几条结构上的约定：

- **入口留在根目录，不搬进 `cmd/`**：只有一个可执行文件，而且使用方式是双击 ——
  `go build .` / `go run .` 得能直接用。搬走 main 包还会连带改掉 `.syso` 的输出目录
  （它只会被链接进同目录的那个包，搬走就静默变成空的属性页）。
- **`internal/` 保持扁平**：Go 的导入路径就是包路径，往中间插一层只让 import 变长，
  不产生任何编译器能看见的边界。包的数量就是职责的数量。
- **`internal/replay` 是个自成一体的应用包**：实例、操作权、广播、标注、撮合、机器人都在一起，
  只被 `cli` 调用，不许反向依赖 `webreport`；读 CSV 用 `store` 的只读函数，一个字节都不写。

前端（`web/`）是 Vue 3.5 + Pinia + TypeScript + Vite，样式用 **Tailwind 4**（CSS-first，
没有 `tailwind.config.js`）。**画图不用图表库**：Canvas 画 K 线，SVG 画标注并承接命中测试，
两层共用同一套坐标变换（`chart/scale.ts`）。开发用 `npm run dev`；`npm run type-check` /
`lint` / `build` 三道就是前端的「测试」（没有自动化测试）。

## 设计说明

这一节只讲**边界与不可让步的约定**。为什么这么做、踩过哪些坑、哪些结论是被数据推翻过又重建的，
都写在对应文件的注释里；改代码前请先读那个文件的开头。

**为什么只做被动监听**：主动拖动图表会让交互序列变得不像人操作的，高频使用有被风控的可能。
所以没有自动回拉、不接受命令行参数、不做批量调度。这条约束的副产品是**抓取链路上没有一行
JavaScript** —— 不注入脚本就不需要浏览器扩展。

**为什么零依赖**：唯一需要的外部能力是「一个 WebSocket 客户端」，而它可以完全用标准库实现。
自写的客户端要处理两件被真实数据逼出来的事：单帧可达 247KB（要支持 64 位长度与分片重组），
以及写帧必须掩码。`go.mod` 里至今没有 `require`，这是刻意的。

**标的名怎么认**：只认 `symbol_resolved`，别在整帧里搜 `pro_name` —— 同一个 WebSocket 上跑的
不只是图表数据，自选 / 报价面板的 `qsd` 消息里带着**别的品种**。判定顺序是
`config.symbol` → 序列绑定 → 会话内唯一 → 页面内唯一 → URL 猜。给不出结论时 K 线**先攒着
不落盘**，等品种明确后补写 —— 猜错会污染别的标的。

**周期怎么反推**：帧里没有任何字段直接写着周期，`lbs.bar_close_time` 是个陷阱（它是图表右侧
可视边界）。周期靠相邻时间戳的**众数差**反推，而且按「会话 + 序列」分开投票（多个图表会话的
序列都叫 `sds_1`，混着投会互相污染）。反推出来之前 K 线暂存不落盘，宁可晚几百毫秒，
也不要把 1 小时图的 K 线混进 5 分钟目录。

**写入语义**：内存里按 `(标的, 日期)` 维护 `时间戳 → K 线`，同一时间戳直接覆盖，每
`flushSeconds` 整体重写脏掉的日文件（tmp + rename）。所以**重复数据在结构上不可能出现**，
不需要查「这根是不是已经有」。

**统计口径只有一份**：根数、断档、应有根数、异常判定全部在 `store.Scan` 里算，网页端只排队版。
反过来在 JS 里重算一遍就会出现两份口径，而**同一个数据目录给出不同根数时用户没法裁决**。
「星期几应当有多少根」只写在 `store.ExpectedBars` 一处，页面通过 `meta.expectRule` 印出来。

**报告只有一个出口**：只有菜单 2 的网页版。终端的表格报表曾经存在，已整个删掉 ——
两套界面看同一份数据，数字一旦有出入用户没法裁决。

**标注只有「时间 + 价格」，没有像素**：换窗口大小、缩放级别、显示器，像素就全错了，而时间价格
不会；后端要做校验（锚点不能是未来），它只认识时间和价格。端点可以带 `offset` 往右越过最后一根
K 线（那不是时间也不是像素，是「锚点下标 + 根数」），所以延伸段和 K 线严格对齐、缩放平移都不漂。

**前端预览、后端定稿**：除了缩放 / 平移 / 十字光标，没有任何一个操作是本地直接改状态的。
预览可以本地算（手感），但定稿必须由后端校验、编号、广播回来，界面上的正式状态**永远来自广播**。
唯一需要两边各算一遍的是 Ctrl 吸附 —— 两份实现必须同口径，不一致的症状是「松手后图形跳一下」。

**撮合规则只有一份**：在 `internal/replay/instance.go`，机器人走的也是同一套方法（策略拿不到
`Instance`，就不可能自己造一个成交价）。成交价通常是挂单价、跳空时取开盘价；本根挂的单从下一根
才参与撮合（否则就是拿已收完的 K 线倒推成交）。**前端不算钱**：成交、持仓、盈亏全部来自后端。

**交易记录挂在唯一的广播出口上**：不散在各个 `do*Locked` 里，因为那样每加一个动作就要记得补
一行，迟早会漏，而漏掉的动作在回放里表现成「画面少了一步」。挂在出口上，新增动作天然被录，
机器人操作也天然被录。录下来的是**广播出去的原文**，回放时喂给同一个 reducer，画面必然一致。

**回放和实时共用一个 reducer**：`applyInstanceEvent` 是唯一把广播变成盘面的地方，所以回放不是
「另写一套播放逻辑」，而是「深拷起点快照，再把事件依次喂进去」。

**机器人 = 纯函数策略 + 执行器 + 撮合**：策略只出「方向 + 止损价 + 目标价」（绝对价格，不是距离
—— 换算散在两边迟早有一边把方向写反），执行器负责下单与保护单，成交口径复用撮合。
加一个策略只要实现 `OnBar`，协议和前端都不用动。

**两条行为契约**（细节看代码）：同组保护单（OCO）一根 K 线里只成交一张，**两张都被扎到时
判止损**；**日历日最后一根（23:55）无条件平仓 + 撤光挂单**，任何仓位不留过夜。

## 测试

```bash
go test ./...                                     # 全部离线，不启动任何浏览器
cd web && npm run type-check && npm run lint      # 前端类型与 lint
cd web && npm run build                           # 构建产物（菜单 3 用它）
```

**禁止用无头浏览器测试**：慢，而且浏览器进程中断这类问题在测试里看不见。替代方案是用一个
**假 CDP 服务端扮演 Chrome**（`internal/wstest`），把**真实抓包**当成 WebSocket 帧事件推下去 ——
从握手、分帧、抽 K 线、周期判定、品种识别到落盘、留档，除「Chrome 自己的行为」以外全跑了一遍。
`testdata/` 下的回归样本都是真实抓包裁出来的，期望值用独立脚本统计，不是照抄被测代码的输出。

| 包 | 钉住的事 |
|---|---|
| `tvproto` | 分帧 / 抽 K 线 / 品种与序列绑定（含两份真实抓包回归） |
| `store` | CSV 落盘 / 覆盖语义 / 重启后合并 / 坏行容错 / 只读扫描 |
| `ingest` | 周期反推 / 暂存补写 / 品种归属与串味防护 |
| `cdp`、`wsclient` | 端点发现 / 超时断线；握手 / 大帧 / 分片 / ping-pong |
| `webreport` | JSON 形状 / 静态资源 / 端口回退 / 只读 / 前端格式化交叉校验 |
| `replay` | 实例与操作权 / 存档与迁移 / 标注 / 撮合 / 交易记录 / 语音 / 协议 / dist |
| `strategy` | 形态识别 / 参数 / 交易日与日终口径 |
| `.`（根包） | 版本号机制的四个落点 |

**自动测试覆盖不到「Chrome 的真实行为」**，这一段只能人工做，步骤很短：勾上远程调试开关 →
打开图表页 → 菜单选 1 → 在 Chrome 里点 Allow → 往回拖几次图表 → 看 CSV 是否在长大 →
`Ctrl+C` 停下 → 菜单 2 核一下根数。另外 `internal/replay` 里有两条对着真服务跑的用例
（默认跳过）：一条只验协议，一条让测试自己起服务、关掉、再重开，验「重启恢复」。

## 改代码时的注意

- **不要引入第三方依赖**：`go.mod` 目前没有 `require`，这是刻意的。
- **不要让「分析」写任何东西**：统计走只读的 `store.Scan`（`store.Store` 一 Open 就会建目录、
  分配标的目录名）；复盘读 CSV 只用 `ReadDayRows` / `Catalog`，唯一写入口是 `persist.go`。
- **不要让两处各写一份解析**：CSV 行格式只在 `store.readDayFile` 里定义一次。
- **版本号只改 `VERSION` 一个文件**，改完必须**重新构建**（`.syso` 是编译期快照）。
- **`build.cmd` 必须纯 ASCII + CRLF**，改它时不要写入中文或裸 LF（有测试拦）。
- **菜单只能有一个 stdin reader**：否则缓冲层里攒着的字符会被绕过去，表现成「按一次回车跳过两项」。
- **网页版不许有「算数字」的代码**：改了显示格式或日历日期算术，要同步改
  `internal/webreport/testdata/format.test.cjs` 的期望值 —— 那是唯一事实来源。
- **改了 `internal/webreport/static/` 下任何文件都要重新 `go build`**：`//go:embed` 是编译期快照。
- **`web/dist` 不是 embed 的**：复盘服务运行期从磁盘读，所以改前端必须 `npm run build`，
  发布时要连 `dist` 一起带走（否则页面是那张「还没构建」的说明页）。
- **URL 路径用 `path`，磁盘路径用 `filepath`**：`filepath.Clean` 在 Windows 上会把 `/assets/x.js`
  变成 `\assets\x.js`，任何 `HasPrefix(..., "/assets/")` 都会静默失效。
- **存档是快照不是日志**：加「属于实例」的字段可以（`omitempty` 让老档照读）；
  「属于进程」的字段（谁在操作、日文件索引、机器人协程）**别加**，那些恰恰不该被恢复。
- **改完会改实例状态的代码，想一下它会不会被标脏**：落盘靠 `markDirtyLocked()`，它挂在
  `broadcastInstanceLocked` 上，所以走广播的改动一定会被存下。
- **前端不写钱**：成交、持仓、盈亏全部来自后端广播；改撮合规则只改 `instance.go`。
- 前端相关的几条：`types/protocol.ts` 与 `replay/protocol.go` 逐字对应（字段名对不上不报错，
  只表现成「某个面板一直是空的」）；`@` 别名在 `vite.config.ts` 与 `tsconfig.app.json` 两处
  同步；涨跌色只在 `chart/render.ts` 的两套主题里改，且两套一起改。

## 注意事项

抓取属于对 TradingView 服务条款的灰色操作。低频、小批量自用风险可控；
**不要高频批量拉，不要全品种刷。**

程序只做被动监听是刻意的：不产生任何主动交互，也就不给风控提供触发依据。但也不要长时间挂着
连续录几十个小时 —— 需要哪段历史，开一次拖一遍就够了。
