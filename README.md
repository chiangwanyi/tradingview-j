# tradingview-j

> 旁路抓取你**本人已登录的 Chrome** 里 TradingView 图表页的 WebSocket 行情帧，
> 解出 **5 分钟 K 线**，按「一个标的一个文件夹、一天一个 CSV」落盘。

纯 Go 实现，**零第三方依赖**（WebSocket 客户端也是自写的），产物是**根目录下**的单个 exe：
`tv-capture-v<版本>.exe`（当前 `0.4.0`）—— 版本号既在文件名里，也写进了 exe 的文件属性。

程序只**被动**监听浏览器已经收到的数据：不往页面里注入脚本、不需要浏览器扩展、
不主动操作图表、也没有自动回拉 —— **抓取链路上没有一行 JavaScript**。
（菜单 2/3 的网页是零构建的只读界面，随 exe 内嵌；菜单 4 的复盘前端是 `web/` 里的
Vue + TypeScript 工程，**需要先 `npm run build`**，产物由本地服务托管，不联网。）

## 特性

- **被动旁路**：只录页面自己请求到的行情，不产生任何主动交互。
- **零依赖单文件**：`go.mod` 里没有 `require`，一个 exe 拷到哪都能跑，不需要装运行时。
- **明文 CSV**：时间列是 `yyyy-MM-dd HH:MM`，Excel / pandas / 文本编辑器直接可读，不用换算。
- **整体重写落盘**：同一时间戳被反复推送时直接覆盖，重复数据在结构上不可能出现。
- **只收 5 分钟**：其他周期的序列整段跳过。周期是从数据反推出来的，不是配置里念出来的。
- **两套只读视图**：菜单 2 在终端出表，菜单 3 把**同一份**统计结果起在本机网页上
  （日历视图，点某一天看当天明细；可筛选、可折叠）。
- **复盘（菜单 4）**：本地网页里**逐根回放** K 线，在图上画基于「K 线时间 + 价格」的标注，
  做限价 / 止损的模拟交易；多人时一人操作、其余观看，也能让后端机器人接管演示。
  实例、标注、挂单、成交写进本地存档（`state/`），**关掉程序再进来还在**；
  数据目录始终只读，**不回写 CSV**。
- **浅色 / 深色两套配色**：深色是绿涨红跌实心；浅色是「阳线白填充黑框、阴线全黑」，
  白底上更清楚（也顺手照顾色弱）。切换即时生效，选择会被记住。
- **价格轴按标的的 tick 走**：MNQ/MES `0.25`、MGC/BTCUSDT `0.1`、CL `0.01`（写在
  `data/_symbols.json` 里，可以手改），轴上不会出现这个标的根本不存在的报价。
  **十字光标也一样**：鼠标停在两根刻度之间，价格会吸到最近的那个合法跳价（`6484.12` → `6484.00`）。
- **右键就地挂单**：在画布任意价格右键，弹出「买入 N 手 / 卖出 N 手 / 复制价格」，
  **单型按价格相对现价的方向自动定** —— 现价下方买入是限价、卖出是止损，现价上方则相反
  （限价单等价格过来，止损单等价格跑了才追）；价格是右键那一点吸附后的价格，复制走系统剪贴板。
- **图上直接看仓位**：未平仓时画一条贯穿全宽的**成本线**（多头绿、空头红），标签写着成本价与已实现盈亏；
  每次成交留一个三角（买上 / 卖下），已经平掉的仓再连一条「开仓均价 → 平仓价」的线 ——
  这些是画上去的痕迹，不能选中、拖动、删除。
- **看得清的字**：字号整体上调一档、正文用 13px，时间轴给完整日期时间（`周五 2026-10-16 09:35`）。

## 前置条件

- **Chrome，并打开远程调试开关**（每个浏览器会话要做一次）：
  1. 打开你平时登录着 TradingView 的那个 Chrome
  2. 地址栏访问 `chrome://inspect/#remote-debugging`
  3. 勾选 **Allow remote debugging for this browser instance**
  4. 打开 TradingView 的**图表页**（URL 里带 `/chart/`），周期切到 **5 分钟**
- **Go 1.26+**（`go.mod` 里声明的是 `go 1.26`）：只在从源码构建时需要；跑 exe 不需要任何运行时。
  > 代码本身只用到 Go 1.22 的语法，这行是**对齐两台构建机的工具链下限**（Windows 上用 1.27.2、
  > 老 macOS 12 上最高只能用 1.26 —— Go 1.26 是最后一个支持 Monterey 的版本，1.27 起要求 Ventura+）。
  > 把它改大不会让新工具链跑上老系统，只会让老机器编不了。
- **`go-winres`**：构建时用它把版本信息写进 exe 的文件属性，一次性装好即可：
  `go install github.com/tc-hib/go-winres@latest`，然后确认 `%USERPROFILE%\go\bin` 在 `PATH` 里。
  它是**构建期工具**，不进入程序：`go.mod` 里依然没有 `require`。
- 当前只在 **Windows** 上实际跑过；代码本身不依赖平台特性（`internal/logx` 有 `//go:build !windows`
  分支，`syscall.SIGTERM` 在 darwin 上也有）。已交叉编译验证 `darwin/amd64` / `darwin/arm64` 能编过，
  但 `build.cmd` 是 cmd 脚本、`.syso` 只在 windows/amd64 下参与链接，所以在 macOS 上要自己跑
  `go build -ldflags "-X main.version=$(cat VERSION)" -o tv-capture-v$(cat VERSION)`。

> Chrome 136 起，给默认用户数据目录加 `--remote-debugging-port` 启动参数会被**静默忽略**，
> 端口根本不会开 ——「关掉 Chrome 再加参数重启」这条路走不通，只能用上面那个官方开关。
> 勾选后在**当前运行中的实例**上立即生效，不需要重启 Chrome、不需要重新登录；
> 代价是每次外部发起连接，Chrome 会弹一次授权框要求点 **Allow**。

## 快速开始

```bat
build.cmd                        :: 双击它，或者在命令行里跑
tv-capture-v0.4.0.exe            :: 产物就落在根目录（版本号来自 VERSION）
```

构建只做三件事，都在 `build.cmd` 里：读根目录的 `VERSION` → 生成 exe 属性要用的资源对象
→ `go build`。产物**就地**落在根目录，文件名带版本号。详细约定见下面「构建与版本号」。

启动后是一个五选一的菜单：

```
  1  启动抓取            等 Chrome + 图表页，把 5 分钟 K 线录成 CSV
  2  分析已抓取的数据    只读统计：每个标的每天多少根、缺口在哪
  3  网页版分析          同一份统计结果放进浏览器，日历视图
  4  复盘                随机/指定时间点，逐根回放、画标注、模拟下单
  5  退出
```

选 **1** 之后，程序会自己等 Chrome 的调试端口出现、再等图表页出现（没开就一直等，
每 5 秒重试一次，**不需要重启程序**），然后开始录。

**你要做的只有一件**：在 Chrome 里随意往回拖动图表，或者用回放模式跳日期。
图表每走到一段没缓存的范围，页面自己就会向服务器要历史数据，程序把这段录下来。

按 `Ctrl+C` 停下来：抓取会先把内存里的当天数据刷进 CSV、打印本次写入统计；
网页服务则直接停掉监听。**两者都是回到菜单**，不是退出程序 ——
想接着抓就再选 1，选 4 才退出。

## 构建与版本号

版本号**只有一个来源**：仓库根目录的 `VERSION` 文件（一行，例如 `0.1.0`）。
`build.cmd` 按顺序做三件事，全程不需要你手写第二个版本号：

| 步骤 | 做什么 | 版本号用在哪儿 |
|---|---|---|
| 1 | 读 `VERSION` | 下面两步都用它 |
| 2 | `go-winres make … --file-version=<v> --product-version=<v>` | 生成 `rsrc_windows_amd64.syso` 并编进 exe —— 右键「属性 → 详细信息」里的**文件版本 / 产品版本**就是它 |
| 3 | `go build -ldflags "-X main.version=<v>" -o tv-capture-v<v>.exe .` | **产物文件名**（就落在根目录），以及程序内的启动横幅、网页版页脚与 `/api/analysis` 里的 `meta.version` |

**升版本 = 改 `VERSION` 那一行，再跑一次 `build.cmd`。** 光改 VERSION 不重新构建是没有用的：
`rsrc_windows_amd64.syso` 是**编译期快照**，由构建脚本每次重新生成，
不要手工维护它、也不要提交进仓库（已在 `.gitignore` 里）。

`version_test.go` 盯着这四个落点：`VERSION` 必须是一行三段数字、`main.go` 里的兜底值与它一致、
`build.cmd` 确实做了「读 VERSION / 注入 / 带版本命名」、而 `winres\winres.json` 里
**不许再出现版本号**。谁漂了 `go test .` 会当场报出来。为什么这么定见
[docs/design.md](docs/design.md) 的「版本号为什么只有一个来源」。

产物**就在根目录**，跟 `config.json`、`data\`、`raw\` 并排，所以双击它读写的还是你原来那份数据
—— 没有 `dist\`，构建也不搬运任何文件。注意 `outDir` / `rawDir` 是**相对 exe 所在目录**展开的：
换个目录放 exe（或者把它拷给别人）就等于换一份数据目录，那边会新建自己的
`config.json` 和 `data\`。想长期用就让它留在根目录。

> `build.cmd` 里的日志是**英文**：这个文件必须保持**纯 ASCII**，
> 因为 cmd.exe 按字节偏移回读批处理脚本，中文这类多字节字符会让它把行尾当成新命令执行
> （实测：脚本里中文从 237 字节涨到 1071 字节后，跑到一半就开始报
> `'。' is not recognized as an internal or external command`）。
> 程序本身当然还是中文的 —— 只有这个构建脚本如此。细节见
> [docs/testing.md](docs/testing.md) 的「改代码时的注意」。

## 使用

### 菜单选项 1：启动抓取

接入成功后的日志长这样（状态行会原地刷新，不刷屏）：

```
[信息] 发现浏览器调试端点：port 9222 · 来源 DevToolsActivePort
[信息] CDP 通道已建立，开始等待 TradingView 图表页…
[信息] 已接入图表页：CME_MINI:MNQ1! · 5 分钟 - TradingView
[状态] 页[...] 帧 1204(收1180/发24) 心跳 12 · 周期 300s · 品种 CME_MINI:MNQ1! · 落盘 288 根
```

同时开多个图表标签页会**全部挂上**，各自独立录。中间某一个挂掉不影响其它。

### 菜单选项 2：分析已抓取的数据

对数据目录做一次**只读**扫描（不建目录、不写索引、不改任何文件），打印一张按天的表：

```
  标的 1 个 · 日文件 47 个 · 合计 10,822 根 · 磁盘 573.7 KB
  时间跨度  2026-08-24 06:00 ~ 2026-10-16 14:45

  ▸ CME_MINI:MNQ1!    （文件夹 CME_MINI_MNQ1!/）
      日期          根数   首根   尾根  缺口 最大断档      文件
      2026-08-25     276  00:00  23:55    12   1时5分   14.7 KB
      2026-09-08     228  00:00  23:55    60   5时5分   12.1 KB
      2026-10-16     166  00:00  14:45    12   1时5分    8.8 KB
```

| 列 | 含义 |
|---|---|
| `根数` | 这个日文件里的 K 线根数（同一时间戳只算一根） |
| `首根` / `尾根` | 当天第一根和最后一根的开盘时间，就是 CSV 时间列里的明文 |
| `缺口` | 首根与尾根之间按 `intervalSeconds` 推算「应当有多少根」，减去实有根数 |
| `最大断档` | 相邻两根之间最大的间隔 —— 拖图时跳过了范围，或交易所休市 |
| `文件` | 日文件的字节数 |

读表时注意两点：

- 工作日常见的「缺口 12 / 最大断档 1时5分」**就是 CME 每天的结算休市**（含边界那一根），
  不是丢数据。周六那几天只有 60 根左右（凌晨收市），同样正常。
- 备注列只在出问题时才出现。`坏N行` = 有 N 行解析不了（已跳过，不影响其它行）；
  `重复N行` = 同一个时间戳出现了 N 次 —— 写入是「整体重写 + 原子改名」，
  重复在结构上不可能出现，所以这一列一旦亮，说明文件被手工改过或被别的工具合并过。
  它是报警，不是统计。
- `缺口 / 最大断档` 这两列**只有终端这张表有**：它们把「缺在哪一刻到哪一刻」压成了一个数字，
  而那个数字（12 根）在每日结算休市这种正常形态下天天出现，看不出任何东西。网页版
  （菜单 3）已经把这两个概念换成了「缺失区间的起止时刻」和「这一天该有多少根」——
  见下面「菜单选项 3」。

超过一个标的时，末尾会多一节「全部标的按日期合计」。表里的数字可以独立复核，比如总根数：

```bash
cd data/CME_MINI_MNQ1! && awk 'FNR>1{n++} END{print n}' *.csv
```

### 菜单选项 3：网页版分析

**同一个统计结果**，换成浏览器里的日历。程序在本机起一个只读的网页服务、
自动用默认浏览器打开，终端里也会打印地址：

```
  网页版分析 · E:\Data\projects\tradingview-j\data
  一根 K 线 300 秒 · 时区 Local · 与菜单 2 同一份统计代码
  只读：页面上的任何操作都不会改动数据目录里的文件
  地址      http://127.0.0.1:8765/
```

页面上比终端多出来的东西：

- 顶部总览（标的数 / 日文件数 / 总根数 / 占用磁盘 / 周期 / 时区）与时间跨度；
- **每个标的一个月历**，格子中间的大数字就是**当天的 K 线根数**；标红 = 这一天根数与该星期应有的根数不符（或文件有坏行 / 重复行 / 读不了），标黄 = 当天各标的的根数不完全相同，格子角上那行小字写着原因，没数据的日是灰格；
- **点日历上的某一天**，右边出现当天的明细：根数、应有根数、首根 / 尾根、文件大小 / 行数、检查结果，以及**这一天每一段时间断档的缺失开始时刻与结束时刻**（正常的一天就一行：`05:00 → 05:55  缺 12 根`，那是 CME 每天的结算休市）；
- 工具条上的 `‹ 2026-10 ›` 按月翻页（也可以直接选月份），**所有日历一起翻**；在搜索框里敲 `2026-10` 也会把日历翻到那个月；
- 「全部标的按日期合计」也是一张月历，格子是当天所有标的的合计根数与标的数，标黄表示当天各标的的根数不一致。**点某一天会列出当天每个标的各自的数字**（不是多数派的那几行标黄）；
- 搜索框按标的或日期筛选；两个勾选框把「异常日」或「数量不一致的日」**高亮**出来（其余变淡、不隐藏 —— 格子凭空消失会让人以为那天没数据），工具条上同时报出命中多少天、多少根；
- 顶部的「统计口径」可以展开，里面写着每条判定的含义和**「星期几应当有多少根」那张表**：

  | 周一 | 周二 | 周三 | 周四 | 周五 | 周六 | 周日 |
  |---|---|---|---|---|---|---|
  | 216 / 204 | 276 | 276 | 276 | 276 | 72 / 60 | 休市 |

  周一和周六各有两个值，是因为美国夏令时/冬令时会让本地时刻整体挪 1 小时 ——
  这半年一次的切换意味着**只写一个值会让切换后的那半年天天误报**（实测：本机 2024-03 起
  817 天里，周一的 204 根全部落在冬令时、216 根全部落在夏令时）。表里的数字只写在
  `store.ExpectedBars` 一处，页面直接把它印出来，不在 HTML 里另抄一份。
- 每个标的可以单独折叠，右上角一键全部展开 / 折叠；
- 「重新扫描」按钮 = 重新读一遍磁盘（页面刷新同理）；右上角显示这份快照的时间与耗时。

有几件事是刻意这么做的：

- **数字一定和终端一样**。根数、断档区间、应有根数、异常判定全部由 Go 侧的 `store.Scan`
  算好再送过去，网页端只负责排版 —— 统计口径不可能有两份实现（唯一在 JS 里重写的是千分位、
  `KB / MB` 这类**显示格式**，它有一份对着 Go 测的交叉校验，见 [docs/testing.md](docs/testing.md)）。
- **只监听 `127.0.0.1`**，不对外网开放：页面上会显示你本地数据目录的绝对路径。
- **只读**：网页版没有、也不会有任何能改数据的接口。连扫描都是 `store.Scan`
  （菜单 2 用的同一个函数），不建目录、不写索引。
- **停止用 `Ctrl+C`**（和抓取一致），停止后回到菜单。用回车停会让「读 stdin 的协程」
  和菜单抢输入，表现成「回到菜单后选 1 没反应」。

端口在 `config.json` 的 `webPort` 里改，默认 `8765`。**被别的程序占用时会自动换一个空闲端口，
并在终端里把这件事说出来**（换了却不说，用户就会对着旧端口反复刷新）。

### 菜单选项 4：复盘

起一个本地网页，把 `data/` 里的 K 线**逐根回放**，在图上画标注、做模拟交易。
和菜单 2/3 的关键区别：菜单 2/3 是**只读报表**，菜单 4 是**有状态的应用**
（实例、标注、挂单、成交都写进 `state/` 下的存档）；但它**仍然只读数据目录**，一个 CSV 都不会改。

```
  复盘 · 数据目录 E:\Data\projects\tradingview-j\data
  前端产物 E:\Data\projects\tradingview-j\web\dist
  实例存档 E:\Data\projects\tradingview-j\state
  一根 K 线 300 秒 · 时区 Local（和 CSV 里的时间列一致）
  只读数据目录：标注、挂单、成交只存在服务端（外加一份实例存档），不写回 CSV
  多人连接时只有一人能操作，其余人观看；操作可随时交还或接管
  ────────────────────────────────────────────────────────────────────────
  提示：改过前端代码要重新 npm run build（静态文件是构建产物，不是源码）
  页面      http://127.0.0.1:8790/
  WebSocket ws://127.0.0.1:8790/ws
  已尝试用默认浏览器打开；没打开就手动把上面的地址粘进去。
```

- 右上角「标的与实例」点开 → 选标的（时间点留空就是**随机**挑一根）→「新建实例」：
  把这一刻及之前的 400 根 K 线铺到画布上，之后的行情逐根揭示；同一面板里能看到所有实例、
  进入/删除，以及这个标的的最小 tick；
- 「下一根」揭示下一根 K 线，同时用这根的最高/最低价撮合你的挂单；
- 画标注：线段 / 矩形 / 文字。坐标严格是「K 线时间 + 价格」，按住 **Ctrl** 吸附到 OHLC；
  拖动能移动、选中后按 Delete 删除；拖动过程中画布上是虚线预览，松手后由后端定稿再广播回来；
- 在**任意价格处右键**弹出小菜单：买入 N 手、卖出 N 手、复制价格；
  N 就是底部下单框里的「数量」，价格是右键位置吸附到 tick 后的价格（复制走剪贴板）；
  单型不用选：价格在现价下方时「买 = 限价、卖 = 止损」，在现价上方时反过来；
- 图上的**成本线**（未平仓时）与**成交三角 / 开平连线**是自动画的：三角买上卖下，
  连线从开仓均价连到平仓价；它们属于「交易痕迹」，不能选中、不能拖动、不能删除；
- 模拟交易：限价单 / 止损单，**不设止损止盈**（要止损就自己挂 stop 单），无初始资金、
  不计手续费 / 点差 / 滑点，只记盈亏和成交流水；
- 多人：第二个标签页进来就是**观众**，能收到全部广播但不能操作；「交还 / 接管」切换操作者，
  操作者关掉页面会自动释放；
- 「启动机器人」让服务端机器人接管操作权，自动步进 / 画标注 / 下单 —— 一个人也能看演示；
- 底边是「模拟交易 / 操作记录」两个 Tab，可以整条收起（想看全屏的图时）；
- 右上角可以切**浅色 / 深色**，选择记在本机（`localStorage`）；
- 关掉程序（Ctrl+C 回菜单，或直接退出）**实例还在**：下次选 4 进来，列表里就是上次那些，
  游标、标注、挂单、成交、盈亏都在。只有「操作权」不保存 —— 谁进来谁重新拿。

页面由 `web/` 构建，**改过前端代码要重新 `npm run build`**（托管的是构建产物，不是源码）。
开发期可以 `cd web && npm run dev`，dev server 会把 `/ws` 转给 8790。
细节（协议、操作权、撮合与盈亏、坐标模型、已知限制）见 [docs/复盘设计.md](docs/复盘设计.md)。

## 配置

程序**不接受任何命令行参数**（使用方式是双击，双击时传不进参数），
所有参数都在 exe 同目录的 `config.json` 里。文件不存在会**自动生成一份默认的**。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `matchUrl` | `"tradingview.com/chart"` | 挂到哪个标签页上：按 URL/标题子串匹配。同时开多个图表页会全部挂上 |
| `symbol` | `""` | 强制指定标的。留空则自动识别（推荐留空） |
| `cdpPort` | `0` | `0` = 自动发现（读 `DevToolsActivePort`，再探测 9222/9229/9333） |
| `intervalSeconds` | `300` | **只收这个周期**的 K 线。目前按需求只考虑 5 分钟 |
| `outDir` | `"data"` | K 线 CSV 的根目录，结构见下 |
| `rawDir` | `"raw"` | 原始帧留档的根目录 |
| `saveRawFrames` | `true` | 是否留档原始 WebSocket 帧（复盘协议用，占磁盘） |
| `csvHeader` | `true` | CSV 是否写表头行 |
| `webPort` | `8765` | 菜单 3 的网页服务监听哪个本地端口。`0` = 让系统随便给一个 |
| `replayPort` | `8790` | 菜单 4 的复盘服务端口（页面与 WebSocket 同一个端口）。`0` = 让系统随便给一个 |
| `replayDistDir` | `"web/dist"` | 菜单 4 托管的前端构建产物，相对 **exe 所在目录** |
| `replayStateDir` | `"state"` | 菜单 4 的实例存档目录（里面就一个 `replay-instances.json`），相对 **exe 所在目录** |
| `flushSeconds` | `1` | CSV 落盘间隔。内存里攒着，按这个间隔整体重写 |
| `attachPollSeconds` | `3` | 多久检查一次新出现的图表页 |
| `retrySeconds` | `5` | 接入失败后的重试间隔 |
| `statusSeconds` | `15` | 状态行刷新间隔 |
| `networkBufferMB` | `200` | CDP 网络事件缓冲上限 |
| `maxFrameMB` | `16` | 单帧上限，超了断开重连（防止畸形长度头把内存吃光） |
| `pauseOnExit` | `true` | 出错退出时是否等回车（双击运行时能看清报错） |

相对路径（`outDir` / `rawDir` / `replayDistDir` / `replayStateDir`）都相对 **exe 所在目录**展开，
而不是当前工作目录 —— 双击运行时工作目录不可靠。

## 数据输出

```
data/                                ← outDir
  _symbols.json                      程序自己维护的「标的名 → 文件夹」索引
  CME_MINI_MNQ1!/                    ← 一个标的一个文件夹
    2026-10-15.csv                   ← 文件名就是日期
    2026-10-16.csv
  BINANCE_BTCUSDT/
    2026-10-16.csv
state/                               ← replayStateDir（菜单 4 的实例存档）
  replay-instances.json              实例 + 游标 + 标注 + 挂单 + 成交（整体快照）
raw/                                 ← rawDir（saveRawFrames 打开时才有）
  CME_MINI_MNQ1!/
    2026-10-16T09-30-00.ndjson       一行一条原始帧，事后可复盘协议
```

`2026-10-16.csv` 的内容：

```csv
time,open,high,low,close,volume
2026-10-16 09:40,30067.25,30067.25,30056,30061.5,847
2026-10-16 09:45,30061.5,30080,30055.25,30072.5,1024
```

- **时间列是明文** `yyyy-MM-dd HH:MM`，单元格里是这根 K 线的**开盘时间**，不是 Unix 秒。
- **时区用本机时区**（启动横幅里会打印当前用的是哪个）。这也是文件名里「哪一天」的依据：
  换机器/换时区跑，同一根 K 线的归属日会跟着变，所以尽量固定在同一台机器上采集。
- 成交量缺失时该列留空，不会因此丢整行。
- 写盘是**整体重写**（先写 `.tmp` 再 rename），所以同一时间戳无论如何都只会有最后一行；
  程序启动时也会先把磁盘上已有的当日文件读回内存再合并，于是重启不会覆盖已抓的数据。
  细节见 [docs/design.md](docs/design.md) 的「写入语义」一节。

## 项目结构

```
VERSION               唯一的版本号来源（一行，例如 0.1.0）
build.cmd             构建脚本：读 VERSION → 生成资源对象 → 就地编译出 tv-capture-v<版本>.exe
winres/winres.json    Windows 资源模板（exe 属性里的产品名与描述；不含版本号）
main.go               入口：只有 main() 与 version（-ldflags 的注入点）

internal/cli/         命令行外壳：横幅、菜单循环、四个菜单项的编排
                      （prompt.go 里是全程唯一的 stdin reader）

internal/capture/     常驻会话：等端口、等页面、挂监听、状态行

internal/cdp/         CDP 接入：端点发现、命令与事件、目标页挑选
internal/wsclient/    极简 WebSocket 客户端（零依赖，支持大帧与分片）
internal/tvproto/     协议层：~m~/~h~ 分帧、按形状抽 K 线、标的解析

internal/ingest/      解码器：周期反推、暂存、交给落盘出口
internal/store/       CSV 存储：标的文件夹 + 每日文件整体重写；scan.go 是只读扫描
internal/config/      config.json 的加载 / 生成 / 校验
internal/rawlog/      原始帧留档（NDJSON）

internal/termreport/  终端报表排版（菜单 2）
internal/webreport/   网页版分析（菜单 3）：JSON 接口 + 内嵌前端（static/ 是页面，vendor/ 是两个前端库）

internal/replay/      复盘（菜单 4）：WS 服务 + 实例状态机 + 标注 + 模拟交易 + 机器人
                      （server.go 运行期托管 web/dist —— 改前端要重新 npm run build；
                        persist.go 是实例存档，写 <replayStateDir>/replay-instances.json）
web/                  复盘前端（Vue 3 + Vite 工程），构建产物 dist/ 由菜单 4 托管

internal/logx/        控制台日志：UTF-8 代码页、状态行原地刷新、显示宽度
internal/wstest/      测试专用的手写 WebSocket 服务端（不进最终产物）

testdata/             真实抓包裁剪出的回归样本（tvproto / ingest / capture 共用）
data/                 抓到的 K 线 CSV（一个标的一个文件夹，一天一个文件）
state/                菜单 4 的实例存档（不入库）
raw/                  原始帧留档的默认目录（不入库）
```

上面那些空行就是**分层**：外壳 → 编排 → 协议与存储 → 表现层 → 基础设施。
分组依据是「谁能 import 谁」，不是目录层级 —— 入口为什么不放进 `cmd/`、
`internal/` 为什么不按层再套子目录，见 [docs/design.md](docs/design.md) 的「代码怎么分工」。

`internal/replay` 是个**自成一体的应用包**：实例、操作权、广播、标注、撮合、机器人都在里面，
只被 `internal/cli` 调用，不许反向依赖 `termreport` / `webreport`；它读 CSV 用的是
`store` 里那套**只读**函数（`ReadDayRows` / `Catalog`），一个字节都不写。

## 常见问题

| 现象 | 原因 |
|---|---|
| 菜单里按回车没反应 | 设计如此：回车 = 重画菜单。要开始抓就按 **1** |
| 一直打印「还没发现 Chrome 调试端点」 | 「前置条件」里那个开关没勾，或 Chrome 没开 |
| 连上了但没弹 Allow 框、随后报「连接已关闭」 | 上一次的授权被拒了，重新连一次并在浏览器里点 Allow |
| 找到页面但提示「接不进这个页面」 | **该标签页上开着开发者工具** —— 一个标签页同时只能有一个调试会话，关掉 DevTools 即可 |
| 帧在涨但 CSV 不涨 | 图表周期不是 5 分钟（日志里会写「序列 xxx 的周期是 1h」），或状态行里 `周期` 显示「未定」 |
| 状态行里 `暂存 N 根` 一直不降 | 那几根所在的序列周期反推不出来、或品种定不了。**它们不会落盘，也不影响主图采集** —— 这是刻意的 |
| `品种` 显示的标的跟你正在看的图表不一致 | 看日志里那句 `识别品种：…（会话 … · 品种键 …）`。实在不放心就把 `config.json` 的 `symbol` 填死 |
| CSV 文件被 Excel 占用导致写失败 | 日志会提示「下个周期重试」，关掉 Excel 即可 |
| 网页版打不开 / 浏览器里是旧内容 | 终端里会打印**实际**地址（`webPort` 被占用时会换端口）；页面本身也带「重新扫描」，刷新不会缓存旧数据 |
| 网页版显示的数字会不会和菜单 2 不一样 | 不会，是同一份 `store.Scan` 的结果，网页只做排版 |
| 菜单 4 打开是「前端还没构建」 | `web/dist` 不存在：在 `web` 目录执行 `npm install` 和 `npm run build`，或开发期 `npm run dev` |
| 复盘里点按钮提示「现在由 xxx 操作」 | 你是观众。等对方「交还操作权」，或在他退出后点「接管」 |
| 复盘会不会改动我的 CSV | 不会。标注、挂单、成交写在 `state/replay-instances.json` 里，`data/` 全程只读 |
| 复盘关掉再进来，实例还在吗 | 在（v1.1 起）。存档在 `state/`，Ctrl+C 回菜单时会同步刷一次盘 |
| 价格轴上写着 `tick 0.01`，但这是 0.25 一跳的品种 | 该标的在 `data/_symbols.json` 里没有 `tick`。加上 `"tick": 0.25` 就行，抓取重写索引时会保留这个字段 |
| 切到浅色后 K 线还是黑的 | 只有页面换了、画布没重画。Canvas 配色不跟 CSS 变量走，靠 `ChartPanel.vue` 里的 `watch(store.theme)` 触发重绘 |
| 多个标签页只有一个人能操作 | 设计如此：一人操作、其余观看，演示时观众看到的是同一个有序的广播流 |
| 菜单 4 端口不是 8790 了 | `replayPort` 被占用时自动换端口，终端会说明；开发模式还要同步改 `web/vite.config.ts` 里的 `/ws` 代理 |
| 从源码构建时 `go test` / `go run` 弹「此应用的一部分已被阻止」，报 `An Application Control policy has blocked this file` | 本机开着智能应用控制，它拦的是 `go.exe` 启动的那个二进制，与代码无关。定位与处理见 [docs/testing.md](docs/testing.md) 的「本机环境：智能应用控制会拦 go test / go run」一节 |

| 改了 `VERSION`，exe 属性里还是旧版本 | 光改文件不够：`rsrc_windows_amd64.syso` 是**编译期快照**，要重新跑 `build.cmd`（它会重新生成；别手工改那个文件） |
| 构建时提示「没找到 go-winres」 | 一次性装：`go install github.com/tc-hib/go-winres@latest`，再确认 `%USERPROFILE%\go\bin` 在 `PATH` 里 |
| 把 exe 挪到别的目录后，菜单 2 / 3 说没有数据 | 换目录就等于换数据目录：`outDir` 相对 **exe 所在目录**展开，新位置会新建自己的 `config.json` 和 `data\`。exe 就留在根目录别动 |
| exe 属性里的「公司」「版权」是空的 | 设计如此：`winres\winres.json` 里只填了产品名、内部名与描述，没编公司名和版权 |

每条现象的成因与代码位置见 [docs/testing.md](docs/testing.md) 的「排查要点」。

## 注意事项

抓取属于对 TradingView 服务条款的灰色操作。低频、小批量自用风险可控；
**不要高频批量拉，不要全品种刷。**

程序只做被动监听是刻意的：不产生任何主动交互，也就不给风控提供触发依据。
但也不要长时间挂着连续录几十个小时 —— 需要哪段历史，开一次拖一遍就够了。
